    Suffix Automaton Overview

    The suffix automaton (SAM) is a powerful data structure that can solve many string-related problems in linear time.

    For example, the following string problems can be solved in linear time using SAM:

    • Find all occurrences of a pattern string in another string.
    • Count the number of distinct substrings in a given string.

    Intuitively, the SAM of a string can be understood as a compressed form of all substrings of the given string. A notable fact is that SAM stores all this information in a highly compressed form. For a string of length 𝑛n, its space complexity is only 𝑂(𝑛)O(n). Moreover, the construction time of SAM is also 𝑂(𝑛)O(n). Specifically, a SAM has at most 2𝑛 −12n−1 states and 3𝑛 −43n−4 transitions.

    Definition

    The SAM of a string 𝑠s is the minimal DFA that accepts all suffixes of 𝑠s.

    In other words:

    • SAM is a directed acyclic graph. Vertices are called states, edges are called transitions.
    • The graph has a source 𝑡0t0, called the initial state, from which all other states can be reached.
    • Each transition is labeled with a character. All transitions from one state are different.
    • There are one or more terminal states. If we start from the initial state 𝑡0t0 and eventually reach a terminal state, the concatenation of all transition labels along the path must be a suffix of string 𝑠s. Conversely, every suffix of 𝑠s can be formed by a path from 𝑡0t0 to some terminal state.
    • Among all automata satisfying the above conditions, SAM has the fewest states.

    The key to SAM is precisely this minimality. In fact, building an AC automaton for all suffixes of string 𝑠s can also obtain a DFA accepting all suffixes of 𝑠s. However, in the worst case, such an automaton has Θ(𝑛2Θ(n2 states, which is unacceptable. As shown in the example below, many states are duplicated in the DFA obtained by building an AC automaton for all suffixes, and therefore can be merged. SAM takes state merging to the extreme, thus limiting the size of the resulting DFA to 𝑂(𝑛)O(n). In this sense, SAM is the "compressed" AC automaton of all suffixes of a string.

    Substrings and Paths

    The simplest and most important property of SAM is that it contains information about all substrings of string 𝑠s. Any path starting from the initial state 𝑡0t0, if we write down all transition labels along the path, forms a substring of 𝑠s. Conversely, every substring of 𝑠s corresponds to some path starting from 𝑡0t0.

    To simplify, we say that a substring corresponds to such a path (starting from 𝑡0t0 where all transition labels along it form this substring). Conversely, we say that any path corresponds to the string formed by its labels.

    There may be multiple paths reaching a state, so we say that a state corresponds to a set of strings, where each string corresponds to one of these paths.

    Linear-Time Construction Algorithm

    Before describing the linear-time algorithm for constructing SAM, we need to introduce two concepts that are crucial for understanding the construction process and prove their properties. Among them, the end position endposendpos defines the states in SAM (i.e., gives the necessary and sufficient conditions for merging states), while the suffix link linklink is simply the natural counterpart of the failure pointer in AC automaton in SAM.

    End Position endpos

    Consider any non-empty substring 𝑡t of string 𝑠s, and denote by endpos⁡(𝑡)endpos⁡(t) the set of all ending positions of 𝑡t in string 𝑠s (assuming character indices in the string start from zero). For example, for string 𝚊𝚋𝚌𝚋𝚌abcbc, we have endpos⁡(𝚋𝚌) ={2,4}endpos⁡(bc)={2,4}.

    The end positions of two substrings 𝑡1t1 and 𝑡2t2 may be exactly the same: endpos⁡(𝑡1) =endpos⁡(𝑡2)endpos⁡(t1)=endpos⁡(t2). This defines an equivalence relation among substrings of string 𝑠s. All non-empty substrings of 𝑠s can be divided into several equivalence classes based on their end position sets endposendpos.

    A fact is that each such equivalence class corresponds to a state of SAM1. That is, as long as two substrings have the same end positions, their paths in SAM correspond to the same state. In other words, each non-initial state in SAM corresponds to one or more non-empty substrings with the same endposendpos. In summary, states in SAM are all equivalence classes of non-empty substrings, plus the initial state.

    For now, we accept this fact and will introduce the algorithm for constructing SAM based on it. We will also show that SAM satisfies all properties except minimality; the minimality can be derived from the Myhill–Nerode theorem.

    From the values of endposendpos we can derive some important conclusions that explain the relationship between different substrings corresponding to the same state.

    Lemma 1

    For two non-empty substrings 𝑢u and 𝑤w of string 𝑠s (assuming |𝑢| ≤|𝑤||u|≤|w|), endpos⁡(𝑢) =endpos⁡(𝑤)endpos⁡(u)=endpos⁡(w) if and only if every occurrence of 𝑢u in 𝑠s exists as a suffix of 𝑤w.

    Proof

    The lemma is obvious. If 𝑢u and 𝑤w have the same endposendpos, then 𝑢u is a suffix of 𝑤w, and in 𝑠s it only appears as a suffix of 𝑤w. Conversely, by definition, if 𝑢u is a suffix of 𝑤w and appears only as a suffix of 𝑤w in 𝑠s, then the two substrings have the same endposendpos.

    Lemma 2

    Consider two non-empty substrings 𝑢u and 𝑤w (assuming |𝑢| ≤|𝑤||u|≤|w|). Then either endpos⁡(𝑢) ∩endpos⁡(𝑤) =∅endpos⁡(u)∩endpos⁡(w)=∅, or endpos⁡(𝑤) ⊆endpos⁡(𝑢)endpos⁡(w)⊆endpos⁡(u), depending on whether 𝑢u is a suffix of 𝑤w:

    {endpos⁡(𝑤)⊆endpos⁡(𝑢),if 𝑢 is a suffix of 𝑤,endpos⁡(𝑤)∩endpos⁡(𝑢)=∅,otherwise.{endpos⁡(w)⊆endpos⁡(u),if u is a suffix of w,endpos⁡(w)∩endpos⁡(u)=∅,otherwise.
    Proof

    If the sets endpos⁡(𝑢)endpos⁡(u) and endpos⁡(𝑤)endpos⁡(w) have at least one common element, then since strings 𝑢u and 𝑤w end at the same position, 𝑢u is a suffix of 𝑤w. Therefore, at every occurrence of 𝑤w, substring 𝑢u also occurs. Hence endpos⁡(𝑤) ⊆endpos⁡(𝑢)endpos⁡(w)⊆endpos⁡(u).

    Lemma 3

    Consider an equivalence class of substrings with the same endposendpos, and sort all substrings in the class in non-increasing order of length. Then no substring is longer than its predecessor, and at the same time each substring is a suffix of its predecessor. In other words, for any two substrings in the same equivalence class, the shorter one is a suffix of the longer one, and the lengths of substrings in this equivalence class form a continuous interval, taking all integer values in some range.

    Proof

    If the equivalence class contains only one substring, the lemma obviously holds. Now we discuss equivalence classes with more than one element.

    By Lemma 1, among two different strings with the same endposendpos, one must be longer, and the shorter one is always a proper suffix of the longer one. That is, there are no strings of equal length in the equivalence class.

    Let 𝑤w be the longest string in the equivalence class, and 𝑢u be the shortest. By Lemma 1, string 𝑢u is a proper suffix of string 𝑤w. Now consider any suffix of 𝑤w with length in the range [|𝑢|,|𝑤|][|u|,|w|]. It is easy to see that this suffix is also in the same equivalence class, because this suffix can only exist in string 𝑠s as a suffix of 𝑤w (this is because the shorter suffix 𝑢u appears in 𝑠s only as a suffix of 𝑤w). Therefore, by Lemma 1, this suffix has the same endposendpos as string 𝑤w.

    In short, substrings corresponding to the same state have different lengths that form a consecutive set of natural numbers, where the shorter ones are always suffixes of the longer ones.

    Suffix Link link

    Consider some state 𝑣 ≠𝑡0v≠t0 in SAM. We already know that state 𝑣v corresponds to an equivalence class of substrings with the same endposendpos. If we define 𝑤w as the longest among these strings, then all other strings are suffixes of 𝑤w.

    We also know that the first few suffixes of string 𝑤w (considered in decreasing order of length) are all contained in this equivalence class, and other suffixes (at least one — the empty suffix) are in other equivalence classes. Let 𝑡t be the longest among the other suffixes, and connect the suffix link of 𝑣v to 𝑡t.

    In other words, the suffix link link⁡(𝑣)link⁡(v) of 𝑣v connects to the state corresponding to the longest suffix of 𝑤w whose endposendpos set is different from 𝑤w, which is also the longest suffix of 𝑤w that appears more frequently in 𝑠s than 𝑤w.

    For convenience, we stipulate that the equivalence class corresponding to the initial state 𝑡0t0 contains only the empty string, and endpos⁡(𝑡0) ={ −1,0,…,|𝑆| −1}endpos⁡(t0)={−1,0,…,|S|−1}.

    Lemma 4

    All suffix links form a tree with root 𝑡0t0.

    Proof

    Consider any state 𝑣 ≠𝑡0v≠t0. The state connected to by its suffix link link⁡(𝑣)link⁡(v) corresponds to a strictly shorter string (by definition of suffix link and Lemma 3). Therefore, by following suffix links, we can always reach the initial state 𝑡0t0 corresponding to the empty string.

    Lemma 5

    The tree constructed with endposendpos sets as nodes and set inclusion as edges (i.e., each child's endposendpos set is contained in its parent's endposendpos set) is the same as the tree constructed from suffix links linklink.

    Proof

    By Lemma 2, any two endposendpos sets in SAM form a tree (because two sets either have no intersection or one is a subset of the other).

    Now consider any state 𝑣 ≠𝑡0v≠t0 and its suffix link link⁡(𝑣)link⁡(v). By the definition of suffix link and Lemma 2, we can obtain

    endpos⁡(𝑣)⊊endpos⁡(link⁡(𝑣)).endpos⁡(v)⊊endpos⁡(link⁡(v)).

    Note that it should be ⊊⊊ rather than ⊆⊆, because if endpos⁡(𝑣) =endpos⁡(link⁡(𝑣))endpos⁡(v)=endpos⁡(link⁡(v)), then 𝑣v and link⁡(𝑣)link⁡(v) should have been merged into one state.

    Combining with the previous lemmas: the tree formed by suffix links is essentially a tree formed by endposendpos sets.

    The suffix automaton stores information about all substrings of a string. This can be understood from two perspectives:

    • SAM itself can be seen as a compressed version of the AC automaton of all suffixes of a string. Therefore, it stores information about all prefixes of all suffixes of the string, which is equivalent to storing information about all substrings.
    • The suffix link tree of SAM can be seen as a compressed version of the suffix paths of all prefixes of a string. Therefore, it stores information about all suffixes of all prefixes, which is also equivalent to storing information about all substrings.

    Both perspectives are useful when dealing with different problems.

    Summary

    Before discussing the algorithm itself, let's summarize the previous content and introduce some auxiliary notation.

    • Substrings of 𝑠s can be divided into multiple equivalence classes based on their end position sets endposendpos.

    • SAM consists of the initial state 𝑡0t0 and one state for each endposendpos equivalence class (of non-empty substrings).

    • Each state 𝑣v matches one or more substrings. We denote longest⁡(𝑣)longest⁡(v) as the longest such string, and len⁡(𝑣)len⁡(v) as its length.     • For any state 𝑣 ≠𝑡0v≠t0, the suffix link is defined as an edge connecting to the suffix of longest⁡(𝑣)longest⁡(v) with length minlen⁡(𝑣) −1minlen⁡(v)−1. Suffix links starting from the root 𝑡0t0 form a tree. This tree also represents the inclusion relationships between endposendpos sets.

      minlen⁡(𝑣)=len⁡(link⁡(𝑣))+1.minlen⁡(v)=len⁡(link⁡(v))+1.

    Algorithm

    Now we can discuss the algorithm for constructing SAM. This algorithm is online: we can add characters to the string one by one, and maintain the SAM at each step.

    Process

    To ensure linear space complexity, we will only store the values of lenlen and linklink for each state, along with a transition list for each state. We will not mark terminal states (but we will show how to assign these marks after constructing the SAM).

    Initially, the SAM contains only one state 𝑡0t0 with index 00 (other states have indices 1,2,…1,2,…). For convenience, for state 𝑡0t0 we set len⁡(𝑡0) =0len⁡(t0)=0, link⁡(𝑡0) = −1link⁡(t0)=−1 (−1−1 denotes a virtual state).

    Now we only need to implement the process of adding a character 𝑐c to the current string. The algorithm flow is as follows:

    SAM Incremental Construction Process
    • Let 𝑙𝑎𝑠𝑡last be the state corresponding to the entire string before adding character 𝑐c (initially we set 𝑙𝑎𝑠𝑡 =0last=0, and update 𝑙𝑎𝑠𝑡last at the last step of the algorithm).
    • Create a new state 𝑐𝑢𝑟cur, and set len⁡(𝑐𝑢𝑟) =len⁡(𝑙𝑎𝑠𝑡) +1len⁡(cur)=len⁡(last)+1. At this point, the value of link⁡(𝑐𝑢𝑟)link⁡(cur) is still unknown.
    • Now we perform the following process: starting from state 𝑙𝑎𝑠𝑡last, if the current state does not have a transition labeled with character 𝑐c, we add a transition via character 𝑐c to state 𝑐𝑢𝑟cur, and move the current state along the suffix link. If we encounter a state that already has a transition for character 𝑐c, we stop and mark this state as 𝑝p.
    • Case 1: If we cannot find such a state 𝑝p, we reach the virtual state −1−1. We set link⁡(𝑐𝑢𝑟) =0link⁡(cur)=0 and exit.
    • Suppose we have found a state 𝑝p that can transition via character 𝑐c. We mark the state reached by this transition as 𝑞q. At this point, either len⁡(𝑝) +1 =len⁡(𝑞)len⁡(p)+1=len⁡(q), or len⁡(𝑝) +1 <len⁡(𝑞)len⁡(p)+1<len⁡(q).
    • Case 2: If len⁡(𝑝) +1 =len⁡(𝑞)len⁡(p)+1=len⁡(q), we simply set link⁡(𝑐𝑢𝑟) =𝑞link⁡(cur)=q and exit.

    • Case 3: Otherwise, it becomes complex and we need to copy state 𝑞q: we create a new state 𝑐𝑙𝑜𝑛𝑒clone, copying all information from 𝑞q except the value of lenlen (suffix links and transitions). We set len⁡(𝑐𝑙𝑜𝑛𝑒) =len⁡(𝑝) +1len⁡(clone)=len⁡(p)+1.

      After copying, we set the suffix link from 𝑐𝑢𝑟cur to point to 𝑐𝑙𝑜𝑛𝑒clone, and also set the suffix link from 𝑞q to point to 𝑐𝑙𝑜𝑛𝑒clone.

      Finally, we need to walk back along suffix links from state 𝑝p, and for each state that has a transition to state 𝑞q, we reconnect that transition to state 𝑐𝑙𝑜𝑛𝑒clone.

    • After processing any of the above three cases, we update the value of 𝑙𝑎𝑠𝑡last to state 𝑐𝑢𝑟cur.

    If we also want to know which states are terminal states and which are not, we can find all terminal states after constructing the complete SAM for string 𝑠s. To do this, we traverse suffix links starting from the state corresponding to the entire string (stored in variable 𝑙𝑎𝑠𝑡last) until we reach the initial state. We mark all states we traverse as terminal states. It is easy to understand that this will accurately mark all suffixes of string 𝑠s, and these states are all terminal states.

    Since we only create one or two new states for each character of 𝑠s, the SAM contains only a linear number of states. The linear number of transitions in the SAM, as well as the overall linear running time of the algorithm, have not been clearly explained yet; they will be covered later.

    Explanation

    We will explain in detail the details of each step of the algorithm and explain its correctness.

    Detailed Explanation of the Algorithm

    • If a transition (𝑝,𝑞)(p,q) satisfies len⁡(𝑝) +1 =len⁡(𝑞)len⁡(p)+1=len⁡(q), we call this transition continuous. Otherwise, when len⁡(𝑝) +1 <len⁡(𝑞)len⁡(p)+1<len⁡(q), this transition is called discontinuous.

      As can be seen from the algorithm description, continuous and discontinuous transitions are handled differently in the algorithm. Continuous transitions are fixed and we won't change them. In contrast, when inserting a new character into the string, discontinuous transitions may change (the endpoints of transition edges may change).

    • To avoid ambiguity, we denote the string before inserting current character 𝑐c into the SAM as 𝑠s.

    • The algorithm starts by creating a new state 𝑐𝑢𝑟cur, corresponding to the entire string 𝑠 +𝑐s+c. The reason for creating a new node is clear. At the same time, we also create a new character and a new equivalence class.

    • After creating a new state, we move from the state 𝑙𝑎𝑠𝑡last corresponding to the entire string 𝑠s along suffix links. For each state we pass through, we try to add a transition via character 𝑐c to the new state 𝑐𝑢𝑟cur.

      However, we can only add transitions that don't conflict with existing ones. Therefore, as soon as we find an existing transition for 𝑐c, we must stop.

    • The simplest case is that we reach the virtual state −1−1. This means we have added transitions via 𝑐c for all suffixes of 𝑠s. This also means character 𝑐c never appeared in string 𝑠s. Therefore, the suffix link of 𝑐𝑢𝑟cur is state 00.

    • In the second case, we find an existing transition (𝑝,𝑞)(p,q). This means we are trying to add a already existing string 𝑥 +𝑐x+c to the automaton (where 𝑥x is a suffix of 𝑠s, and string 𝑥 +𝑐x+c has already appeared as a substring of 𝑠s). Because we assume the construction of the automaton for string 𝑠s is correct, we should not add a new transition here.

      However, the difficulty is: to which state should the suffix link from state 𝑐𝑢𝑟cur connect? We want to connect the suffix link to a state whose longest string is exactly 𝑥 +𝑐x+c, i.e., the lenlen of this state should be len⁡(𝑝) +1len⁡(p)+1. However, such a state may not exist, i.e., len⁡(𝑞) >len⁡(𝑝) +1len⁡(q)>len⁡(p)+1. In this case, we must create such a state by splitting state 𝑞q.

    • Of course, if transition (𝑝, 𝑞)(p,q) is continuous, then len⁡(𝑞) =len⁡(𝑝) +1len⁡(q)=len⁡(p)+1. In this case, everything is simple. We only need to point the suffix link of 𝑐𝑢𝑟cur to state 𝑞q.

    • Otherwise, the transition is discontinuous, i.e., len⁡(𝑞) >len⁡(𝑝) +1len⁡(q)>len⁡(p)+1. This means state 𝑞q corresponds not only to the suffix 𝑠 +𝑐s+c of length len⁡(𝑝) +1len⁡(p)+1, but also to longer substrings of 𝑠s. We have no choice but to split state 𝑞q into two substates, where the length of the first substate is len⁡(𝑝) +1len⁡(p)+1.

      How do we split a state? We copy state 𝑞q, producing a state 𝑐𝑙𝑜𝑛𝑒clone, and set len⁡(𝑐𝑙𝑜𝑛𝑒) =len⁡(𝑝) +1len⁡(clone)=len⁡(p)+1. Since we don't want to change paths passing through 𝑞q, we copy all transitions from 𝑞q to 𝑐𝑙𝑜𝑛𝑒clone. We also set the suffix link from 𝑐𝑙𝑜𝑛𝑒clone to be the same as 𝑞q's suffix link, and set 𝑞q's suffix link to 𝑐𝑙𝑜𝑛𝑒clone.

      After splitting the state, we set the suffix link from 𝑐𝑢𝑟cur to 𝑐𝑙𝑜𝑛𝑒clone.

      The final step is to reconnect some transitions that originally pointed to 𝑞q to point to 𝑐𝑙𝑜𝑛𝑒clone. Which transitions need to be modified? It suffices to reconnect transitions corresponding to all strings 𝑤 +𝑐w+c (where 𝑤w is the longest string corresponding to state 𝑝p). That is, we need to continue moving along suffix links from node 𝑝p until we reach the virtual state −1−1, or the current state's transition via 𝑐c no longer points to state 𝑞q.

    Linear Time Complexity

    We assume the alphabet size is a constant, i.e., each operation of searching for a transition, adding a transition, and finding the next transition for a character takes 𝑂(1)O(1) time. If we store each node's transitions in a length |Σ||Σ| array (for fast lookup of transitions by label) and a dynamic list (for fast traversal of all available transitions), trading space for time, then the algorithm's time complexity2 is 𝑂(𝑛)O(n), and space complexity is 𝑂(𝑛|Σ|)O(n|Σ|).

    Proof

    If we consider the various parts of the algorithm, there are three places where the time complexity is not obviously linear:

    • The first is traversing all suffix links of state 𝑙𝑎𝑠𝑡last and adding transitions for character 𝑐c.
    • The second is the process of copying transitions when state 𝑞q is copied to a new state 𝑐𝑙𝑜𝑛𝑒clone.
    • The third is the process of modifying transitions pointing to 𝑞q and reconnecting them to 𝑐𝑙𝑜𝑛𝑒clone.

    We use the fact that the size of SAM (number of states and transitions) is linear (the proof of linearity for states is the algorithm itself, and the proof of linearity for transitions will be given after implementing the algorithm).

    Therefore, the total complexity of the first and second parts is obviously linear, because each single operation on average adds only one new transition to the automaton.

    We still need to estimate the total complexity of the third part. We reconnect transitions originally pointing to 𝑞q to 𝑐𝑙𝑜𝑛𝑒clone. Let 𝑣 =longest⁡(𝑝)v=longest⁡(p), which is a suffix of string 𝑠s. With each iteration, the length of 𝑣v decreases, so the starting position of 𝑣v as a suffix of 𝑠s must move backward. Therefore, the number of times 𝑝p moves along suffix links in the loop does not exceed the distance by which the starting position of 𝑣v as a suffix of 𝑠s moves backward. Because 𝑝p must move backward at least once to terminate the loop, and 𝑝p is at least the result of moving along suffix links from 𝑙𝑎𝑠𝑡last once, when the loop terminates, the starting position of 𝑣v as a suffix of 𝑠s is not earlier than the string longest⁡(link⁡(link⁡(𝑙𝑎𝑠𝑡)))longest⁡(link⁡(link⁡(last))). Moreover, when the loop terminates, the starting position of 𝑣v as a suffix of 𝑠s is exactly the starting position of 𝑣 +𝑐v+c as a suffix of 𝑠 +𝑐s+c. As a suffix of 𝑠 +𝑐s+c, the string 𝑣 +𝑐v+c is exactly longest⁡(link⁡(link⁡(𝑐𝑢𝑟)))longest⁡(link⁡(link⁡(cur))). Because 𝑐𝑢𝑟cur is the updated value of 𝑙𝑎𝑠𝑡last, the number of iterations in the loop does not exceed the distance by which longest⁡(link⁡(link⁡(𝑙𝑎𝑠𝑡)))longest⁡(link⁡(link⁡(last))) moves backward as a suffix of the current string, plus one (the number of moves required to terminate the loop).

    Since the position of longest⁡(link⁡(link⁡(𝑙𝑎𝑠𝑡)))longest⁡(link⁡(link⁡(last))) as a suffix of the current string monotonically increases3 during the entire SAM construction, its total movement distance does not exceed 𝑛n. This shows that the number of iterations in the loop that modifies transitions pointing to 𝑞q does not exceed 2𝑛2n. This is exactly what we needed to prove.

    Of course, if the alphabet size is not constant, the time complexity of SAM is not linear. Transitions from a node need to be stored in a balanced tree that supports fast query and insertion. Therefore, if we denote ΣΣ as the alphabet and |Σ||Σ| as the alphabet size, the asymptotic time complexity of the algorithm is 𝑂(𝑛log⁡|Σ|)O(nlog⁡|Σ|), and space complexity is 𝑂(𝑛)O(n).

    More Properties

    Number of States

    For a string 𝑠s of length 𝑛n, the number of states in its SAM does not exceed 2𝑛 −12n−1 (assuming 𝑛 ≥2n≥2).

    Proof

    The algorithm itself proves this conclusion. Initially, the automaton contains one state. Only one node is created in the first and second iterations. In the remaining 𝑛 −2n−2 steps, at most 2 states are created per step.

    However, we can also prove this estimate without using the algorithm. Recall that the number of states equals the number of distinct endposendpos sets. These endposendpos sets form a tree (the parent's endposendpos set contains the child's endposendpos set). Consider slightly modifying this tree: whenever it has an internal node with only one child (which means the child's set misses at least one position from its parent's set), we create a set containing these missed positions as its child. Eventually, we obtain a tree where every internal node has degree greater than one, and the number of leaves does not exceed 𝑛n. Such a tree has at most 2𝑛 −12n−1 nodes. Therefore, the original number of distinct endposendpos sets does not exceed 2𝑛 −12n−1.

    The string 𝚊𝚋𝚋𝚋⋯𝚋𝚋𝚋abbb⋯bbb reaches this upper bound for the number of states: starting from the third iteration, the algorithm splits a state in each iteration, eventually producing exactly 2𝑛 −12n−1 states.

    Number of Transitions

    For a string 𝑠s of length 𝑛n, the number of transitions in its SAM does not exceed 3𝑛 −43n−4 (assuming 𝑛 ≥3n≥3).

    Proof

    First, we estimate the number of continuous transitions. Consider the spanning tree formed by the longest paths from state 𝑡0t0 to all states in the automaton. The spanning tree contains only continuous edges, so its number is less than the number of states, i.e., the number of edges does not exceed 2𝑛 −22n−2.

    Now we estimate the number of discontinuous transitions. Let the current discontinuous transition be (𝑝, 𝑞)(p,q) with character 𝑐c. We take its corresponding string 𝑢 +𝑐 +𝑤u+c+w, where string 𝑢u corresponds to the longest path from the initial state to 𝑝p, and 𝑤w corresponds to the longest path from 𝑞q to any terminal state. On one hand, each incomplete string corresponds to a different string of the form 𝑢 +𝑐 +𝑤u+c+w (because strings 𝑢u and 𝑤w consist only of complete transitions). On the other hand, by the definition of terminal states, each string of the form 𝑢 +𝑐 +𝑤u+c+w is a suffix of the entire string 𝑠s. Since 𝑠s has only 𝑛n non-empty suffixes, and strings of the form 𝑢 +𝑐 +𝑤u+c+w do not contain 𝑠s (because the entire string contains only complete transitions), the total number of discontinuous transitions does not exceed 𝑛 −1n−1.

    Adding these two estimates, we get the upper bound 3𝑛 −33n−3. However, the maximum number of states can only occur in cases like 𝚊𝚋𝚋𝚋⋯𝚋𝚋𝚋abbb⋯bbb, and at that time the number of transitions is clearly less than 3𝑛 −33n−3.

    Therefore, we can obtain a tighter upper bound for the number of transitions in SAM: 3𝑛 −43n−4. The string 𝚊𝚋𝚋𝚋⋯𝚋𝚋𝚋𝚌abbb⋯bbbc reaches this upper bound.

    Suffix Link Tree

    Although constructing SAM is to obtain information about its states and transitions, the suffix links linklink recorded during construction and the length lenlen of the longest substring corresponding to each state are often more important in applications than SAM's transitions, and can even be used without the transitions.

    During the construction of SAM, we need to update the value of state 𝑙𝑎𝑠𝑡last. It corresponds to the string before (and after) each character is added, which is all prefixes of the entire string 𝑠s. Let the state corresponding to the 𝑖i-th prefix be 𝑣𝑖vi, giving us a total of 𝑛n states 𝑣0,𝑣1,⋯,𝑣𝑛−1v0,v1,⋯,vn−1. Additionally, we define the initial state 𝑡0t0 as 𝑣−1v−1, corresponding to the empty prefix. These states are temporarily called "prefix nodes".

    As mentioned in Lemma 4, all states and all suffix links form a rooted tree with root 𝑡0t0. This tree is also called the suffix link tree (domestic OI players often call it the parent tree). It records information about all suffixes of all prefixes of the string, i.e., information about all substrings.

    The suffix link tree has the following properties:

    • The string corresponding to an ancestor node is always a suffix of the string corresponding to a descendant node.
    • The endposendpos set at each node is the set of indices 𝑖i of all "prefix nodes" 𝑣𝑖vi in its subtree.
    • The endposendpos set of an ancestor node in the suffix link tree always strictly contains the endposendpos set of a descendant node.
    • The value of lenlen at each node is the length of the longest common suffix of all prefixes corresponding to "prefix nodes" 𝑣𝑖vi in its subtree.
    • Except for the root node 𝑡0t0, the number of distinct substrings corresponding to each node is its lenlen value minus its parent's lenlen value, i.e., len⁡(𝑣) −len⁡(link⁡(𝑣))len⁡(v)−len⁡(link⁡(v)).

    These properties have many applications. For example, the longest common suffix of the 𝑖i-th prefix and the 𝑗j-th prefix corresponds to the longest string corresponding to the LCA of 𝑣𝑖vi and 𝑣𝑗vj.

    Finally, the suffix link tree built for string 𝑠s has the same structure as the suffix tree built for its reverse 𝑠𝑅sR. This is often used for offline construction of suffix trees.

    Applications

    Now we look at some problems that can be solved using SAM. For simplicity, we assume the alphabet size 𝑘k is a constant. This allows us to consider adding a character and traversal as constant-time operations.

    Checking if a String Occurs

    Problem

    Given a text string 𝑇T and multiple pattern strings 𝑃P, check whether string 𝑃P occurs as a substring of 𝑇T.

    Solution

    We construct a suffix automaton for text string 𝑇T in 𝑂(|𝑇|)O(|T|) time. To check whether pattern 𝑃P occurs in 𝑇T, we start from 𝑡0t0 and follow transitions (edges) according to the characters of 𝑃P. If at some point we cannot follow a transition, then pattern 𝑃P is not a substring of 𝑇T. If we can process the entire string 𝑃P in this way, then the pattern occurs in 𝑇T.

    For each string 𝑃P, the algorithm's time complexity is 𝑂(|𝑃|)O(|P|). Moreover, this algorithm also finds the longest prefix of pattern 𝑃P that appears in the text string.

    Number of Distinct Substrings

    Problem

    Given a string 𝑆S, calculate the number of distinct substrings.

    Solution 1

    Construct a suffix automaton for string 𝑆S.

    Each substring of 𝑆S corresponds to some path in the automaton. Therefore, the number of distinct substrings equals the number of distinct paths starting from 𝑡0t0.

    Since SAM is a directed acyclic graph, the number of distinct paths can be calculated by dynamic programming. Let 𝑑𝑣dv be the number of paths starting from state 𝑣v (including the path of length zero). Then we have the following recurrence:

    𝑑𝑣=1+∑𝑤:(𝑣,𝑤,𝑐)∈𝐷𝐴𝑊𝐺𝑑𝑤dv=1+∑w:(v,w,c)∈DAWGdw

    That is, 𝑑𝑣dv can be expressed as the sum of 𝑑𝑤dw over all transitions (𝑣,𝑤,𝑐)(v,w,c) in the DAWG, where the triple (𝑣,𝑤,𝑐)(v,w,c) indicates there exists a transition from 𝑣v via 𝑐c to 𝑤w in the suffix automaton.

    Therefore, the number of distinct substrings is 𝑑𝑡0 −1dt0−1 (because we need to exclude the empty substring).

    Total time complexity: 𝑂(|𝑆|)O(|S|).

    Solution 2

    Another method is to use the information of the suffix link tree after constructing the suffix automaton. The number of substrings corresponding to each node is len⁡(𝑣) −len⁡(link⁡(𝑣))len⁡(v)−len⁡(link⁡(v)). Summing over all nodes in the automaton gives the answer.

    Total time complexity is still: 𝑂(|𝑆|)O(|S|).

    Number of Occurrences

    Problem

    For a given text string 𝑇T, there are multiple queries, each query gives a pattern string 𝑃P, and we need to answer how many times pattern 𝑃P occurs as a substring in string 𝑇T.

    Solution 1

    Using the information of the suffix link tree, we can perform a DFS to preprocess the size of each node's endposendpos set.

    All "prefix nodes" have initial set size 1, and non-"prefix nodes" have initial set size 0. Then, when backtracking from bottom to top along suffix links, we add each parent node's set size to all its children's set sizes (don't forget the parent node's own initial value). The value obtained at each node is the size of its endposendpos set. The reason we can directly sum the set sizes of different children is that the same 𝑣𝑖vi appears in only one subtree, so there is no double counting when summing.

    For a query, we find the node corresponding to pattern 𝑃P on the automaton. If it exists, the answer is the size of that node's endposendpos set; if it doesn't exist, the answer is 0.

    Preprocessing time complexity: 𝑂(|𝑇|)O(|T|). Single query time complexity: 𝑂(|𝑃|)O(|P|).

    Solution 2

    Construct a suffix automaton for text string 𝑇T.

    Next, perform preprocessing: for each state 𝑣v in the automaton, preprocess 𝑐𝑛𝑡𝑣cntv to equal the size of set endpos⁡(𝑣)endpos⁡(v). In fact, all substrings corresponding to the same state 𝑣v occur the same number of times in text string 𝑇T, which is equivalent to the number of positions in the set endposendpos.

    However, we cannot explicitly construct the set endposendpos, so we only consider their size 𝑐𝑛𝑡cnt.

    To calculate these values, we perform the following operations. For each state, if it was not created by cloning (and it is not the initial state 𝑡0t0), we initialize its 𝑐𝑛𝑡cnt to 1. Then we traverse all states in descending order of lenlen, and add the current value of 𝑐𝑛𝑡𝑣cntv to the state pointed to by its suffix link:

    𝑐𝑛𝑡link⁡(𝑣)+=𝑐𝑛𝑡𝑣cntlink⁡(v)+=cntv

    This way, the answer for each state is correct.

    Why is this correct? There are exactly |𝑇||T| states that are not obtained by cloning, and the first 𝑖i of them are created when inserting the first 𝑖i characters. Therefore, for each such state, we calculate the number of positions they correspond to when they are processed. Thus we initially set the 𝑐𝑛𝑡cnt value of these states to 1, and the 𝑐𝑛𝑡cnt values of other states to 0.

    Next, for each 𝑣v, we perform the following operation: 𝑐𝑛𝑡link⁡(𝑣) + =𝑐𝑛𝑡𝑣cntlink⁡(v)+=cntv. The meaning behind this is: if a string 𝑣v occurs 𝑐𝑛𝑡𝑣cntv times, then all its suffixes also end at exactly the same places, i.e., they also occur 𝑐𝑛𝑡𝑣cntv times.

    Why don't we double-count (i.e., count some positions twice) in this process? Because we only add a state's positions to one other state, so a state cannot have its positions repeatedly pointed to another state in two different ways.

    Therefore, we can calculate the 𝑐𝑛𝑡cnt values for all states in 𝑂(|𝑇|)O(|T|) time.

    To answer a query, we just need to look up the value 𝑐𝑛𝑡𝑡cntt, where 𝑡t is the state corresponding to the pattern string. If the pattern does not exist, the answer is 0. Single query time complexity: 𝑂(|𝑃|)O(|P|).

    Problem

    Given two strings 𝑆S and 𝑇T, find the longest common substring. A common substring is defined as a string 𝑋X that appears as a substring in both 𝑆S and 𝑇T.

    We construct a suffix automaton for string 𝑆S.

    Longest Common Substring Among Multiple Strings

    Problem

    Given 𝑘k strings 𝑆𝑖Si. We need to find their longest common substring, i.e., a string 𝑋X that appears as a substring in each string.

    Solution 1

    We concatenate all substrings into a longer string 𝑇T, separating each string with a special character 𝐷𝑖Di (one character per string):

    𝑇=𝑆1+𝐷1+𝑆2+𝐷2+⋯+𝑆𝑘+𝐷𝑘.T=S1+D1+S2+D2+⋯+Sk+Dk.

    Then we construct a suffix automaton for string 𝑇T.

    Now we need to find a string that exists in all strings 𝑆𝑖Si in the automaton. We can use the added special characters for this. If 𝑆𝑗Sj contains a substring 𝑋X, then from the node 𝑡t corresponding to substring 𝑋X, there must exist a path to 𝐷𝑗Dj that does not pass through any other special characters 𝐷1,⋯,𝐷𝑗−1,𝐷𝑗+1,⋯,𝐷𝑘D1,⋯,Dj−1,Dj+1,⋯,Dk. For a common substring 𝑋X, such a path should exist for each special character 𝐷𝑗Dj.

    Therefore, we need to compute reachability, i.e., for each state in the automaton and each character 𝐷𝑖Di, whether such a path exists. This can be easily computed by DFS or BFS along with dynamic programming. After that, the answer is the longest among the longest substrings longest⁡(𝑣)longest⁡(v) corresponding to all states that can reach all special characters.

    Solution 2

    Let 𝑆1S1 be the shortest string, and construct SAM for it. Using the algorithm for finding the longest common substring of two strings, calculate the longest common substring length between each remaining string and 𝑆1S1. During matching, each character from the string 𝑆𝑗Sj being matched causes a corresponding move on the SAM. Therefore, we can directly record, during the matching process, the length of the longest substring of 𝑆𝑗Sj that each state in the SAM can match.

    Because during the matching process, when we match to a state in SAM, we must also match to all its ancestor nodes on the suffix link tree, but the matching length information for ancestor nodes is not updated. Therefore, after completing the matching for string 𝑆𝑗Sj, we need to update from bottom to top along suffix links, propagating the longest substring information matched by child nodes to their parent nodes. At this time, we need to note that the longest matching length recorded by the parent node cannot exceed its own lenlen value. This way, we obtain the actual longest substring length of 𝑆𝑗Sj that each state on 𝑆1S1's SAM can match.

    Finally, after matching each 𝑆2,⋯,𝑆𝑘S2,⋯,Sk, we take the minimum of the actual matched lengths recorded for each state on the SAM, which gives the longest common substring length between each state and 𝑆2,⋯,𝑆𝑘S2,⋯,Sk.
