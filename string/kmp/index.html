    Prefix Function and KMP Algorithm

    String Prefix and Suffix Definitions

    For definitions of string prefix, proper prefix, suffix, and proper suffix, see String Basics.

    Prefix Function

    Definition

    Given a string 𝑠s of length 𝑛n, its prefix function is defined as an array 𝜋π of length 𝑛n. The definition of 𝜋[𝑖]π[i] is:

    1. If the substring 𝑠[0…𝑖]s[0…i] has a pair of equal proper prefix and proper suffix: 𝑠[0…𝑘 −1]s[0…k−1] and 𝑠[𝑖 −(𝑘 −1)…𝑖]s[i−(k−1)…i], then 𝜋[𝑖]π[i] is the length of this equal proper prefix (or proper suffix, since they are equal), i.e., 𝜋[𝑖] =𝑘π[i]=k;
    2. If there is more than one such pair, then 𝜋[𝑖]π[i] is the length of the longest one;
    3. If there are no equal pairs, then 𝜋[𝑖] =0π[i]=0.

    Simply put, 𝜋[𝑖]π[i] is the length of the longest equal proper prefix and proper suffix of the substring 𝑠[0…𝑖]s[0…i].

    In mathematical terms:

    𝜋[𝑖]=max𝑘=0…𝑖{𝑘:𝑠[0…𝑘−1]=𝑠[𝑖−(𝑘−1)…𝑖]}π[i]=maxk=0…i{k:s[0…k−1]=s[i−(k−1)…i]}

    By convention, 𝜋[0] =0π[0]=0.

    Process

    For example, for the string abcabcd:

    𝜋[0] =0π[0]=0, because a has no proper prefix and proper suffix, by convention it is 0

    𝜋[1] =0π[1]=0, because ab has no equal proper prefix and proper suffix

    𝜋[2] =0π[2]=0, because abc has no equal proper prefix and proper suffix

    𝜋[3] =1π[3]=1, because abca has only one pair of equal proper prefix and proper suffix: a, length 1

    𝜋[4] =2π[4]=2, because abcab has equal proper prefix and proper suffix only ab, length 2

    𝜋[5] =3π[5]=3, because abcabc has equal proper prefix and proper suffix only abc, length 3

    𝜋[6] =0π[6]=0, because abcabcd has no equal proper prefix and proper suffix

    Similarly, the prefix function for the string aabaaab is [0,1,0,1,2,2,3][0,1,0,1,2,2,3].

    Naive Algorithm for Computing Prefix Function

    Process

    A direct algorithm for computing the prefix function according to its definition:

    • Compute the prefix function values 𝜋[𝑖]π[i] in a loop with 𝑖 =1 →𝑛 −1i=1→n−1 ( 𝜋[0]π[0] is set to 00 ).
    • To compute the current prefix function value 𝜋[𝑖]π[i], we let variable 𝑗j start from the maximum proper prefix length 𝑖i.
    • If the proper prefix and proper suffix are equal at the current length, then this length is 𝜋[𝑖]π[i]; otherwise, decrement 𝑗j and continue matching until 𝑗 =0j=0.
    • If 𝑗 =0j=0 and there has been no match yet, set 𝜋[𝑖] =0π[i]=0 and move to the next index 𝑖 +1i+1.

vector<int> prefix_function(string s) {
  int n = (int)s.length();
  vector<int> pi(n);
  for (int i = 1; i < n; i++)
    for (int j = i; j >= 0; j--)

        pi[i] = j;
        break;

  return pi;
}

    Efficient Algorithm for Computing Prefix Function

    First Optimization

    The first important observation is that adjacent prefix function values can increase by at most 1.

    As shown in the figure below, when taking the largest possible 𝜋[𝑖 +1]π[i+1], it must require the new character 𝑠[𝑖 +1]s[i+1] to match the corresponding character, i.e., 𝑠[𝑖 +1] =𝑠[𝜋[𝑖]]s[i+1]=s[π[i]], in which case 𝜋[𝑖 +1] =𝜋[𝑖] +1π[i+1]=π[i]+1.

    𝜋[𝑖]=3⏞𝑠0 𝑠1 𝑠2 𝑠3⏟__⏟__⏟𝜋[𝑖+1]=4 … 𝜋[𝑖]=3⏞¯¯⏞¯¯⏞𝑠𝑖−2 𝑠𝑖−1 𝑠𝑖 𝑠𝑖+1⏟___⏟___⏟𝜋[𝑖+1]=4s0 s1 s2⏞π[i]=3 s3⏟π[i+1]=4 … si−2 si−1 si⏞π[i]=3 si+1⏟π[i+1]=4

    So when moving to the next position, the prefix function value either increases by one, stays the same, or decreases.

    static int[] prefix_function(String s) {
    int n = s.length();
    int[] pi = new int[n];
    for (int i = 1; i < n; i++) {
        for (int j = pi[i - 1] + 1; j >= 0; j--) {
            if (s.substring(0, j).equals(s.substring(i - j + 1, i + 1))) {
                pi[i] = j;
                break;
            }
        }
    }
    return pi;
}

    In this initially improved algorithm, when computing each 𝜋[𝑖]π[i], the best case is that the first string comparison completes the match, meaning the base number of string comparisons is n-1.

    And because of the constraint j = pi[i-1]+1 (pi[0]=0) on the maximum number of string comparisons, it can be seen that each time only in the best case will the upper limit of string comparisons accumulate by 1, and any additional string comparisons consume the room for later growth.

    From this, we can derive the worst case for the number of string comparisons: at least 1 string comparison consumption and at most n-2 comparison accumulations, making the total number of string comparisons n-1 + n-2 = 2n-3.

    Thus, after this optimization, computing the prefix function only requires 𝑂(𝑛)O(n) string comparisons, reducing the total complexity to 𝑂(𝑛2)O(n2).

    Second Optimization

    In the first optimization, we discussed the best case when computing 𝜋[𝑖 +1]π[i+1]: 𝑠[𝑖 +1] =𝑠[𝜋[𝑖]]s[i+1]=s[π[i]], in which case 𝜋[𝑖 +1] =𝜋[𝑖] +1π[i+1]=π[i]+1. Now let's go further along this line: discuss how to transition when 𝑠[𝑖 +1] ≠𝑠[𝜋[𝑖]]s[i+1]≠s[π[i]].

    As shown in the figure, when a mismatch occurs, we want to find for the substring 𝑠[0…𝑖]s[0…i] the second longest length 𝑗j (second to 𝜋[𝑖]π[i]) such that the prefix property still holds at position 𝑖i, i.e., 𝑠[0…𝑗 −1] =𝑠[𝑖 −𝑗 +1…𝑖]s[0…j−1]=s[i−j+1…i]:

    𝜋[𝑖]⏞¯¯⏞¯¯⏞𝑠0 𝑠1⏟𝑗 𝑠2 𝑠3 … 𝜋[𝑖]⏞¯¯¯⏞¯¯¯⏞𝑠𝑖−3 𝑠𝑖−2 𝑠𝑖−1 𝑠𝑖⏟𝑗 𝑠𝑖+1s0 s1⏟j s2 s3⏞π[i] … si−3 si−2 si−1 si⏟j⏞π[i] si+1

    If we find such length 𝑗j, then we only need to compare 𝑠[𝑖 +1]s[i+1] and 𝑠[𝑗]s[j] again. If they are equal, then 𝜋[𝑖 +1] =𝑗 +1π[i+1]=j+1. Otherwise, we need to find the second longest length 𝑗(2)j(2) for the substring 𝑠[0…𝑖]s[0…i] that maintains the prefix property, and so on, until 𝑗 =0j=0. If 𝑠[𝑖 +1] ≠𝑠[0]s[i+1]≠s[0], then 𝜋[𝑖 +1] =0π[i+1]=0. The second comparison is shown in the figure below.

    Observing the figure, because 𝑠[0…𝜋[𝑖] −1] =𝑠[𝑖 −𝜋[𝑖] +1…𝑖]s[0…π[i]−1]=s[i−π[i]+1…i], for the second longest length 𝑗j of 𝑠[0…𝑖]s[0…i], we have the property:

    𝑠[0…𝑗−1]=𝑠[𝑖−𝑗+1…𝑖]=𝑠[𝜋[𝑖]−𝑗…𝜋[𝑖]−1]s[0…j−1]=s[i−j+1…i]=s[π[i]−j…π[i]−1]

    static int[] prefix_function(String s) {
    int n = s.length();
    int[] pi = new int[n];
    for (int i = 1; i < n; i++) {
        int j = pi[i - 1];
        while (j > 0 && s.charAt(i) != s.charAt(j)) {
            j = pi[j - 1];

            j++;
        }
        pi[i] = j;
    }
    return pi;

    This is an online algorithm, i.e., it processes data as it arrives—for example, you can read the string character by character and immediately process them to compute the prefix function value for each character.     Applications

    Finding a Substring in a String: Knuth–Morris–Pratt Algorithm

    This algorithm was jointly published by Knuth, Pratt, and Morris in 19771. This task is a typical application of the prefix function.

    Process

    Given a text 𝑡t and a string 𝑠s, we try to find and display all occurrences of 𝑠s in 𝑡t.

    For convenience, we use 𝑛n to denote the length of string 𝑠s, and 𝑚m to denote the length of text 𝑡t.

    We construct a string 𝑠 +# +𝑡s+#+t, where ## is a delimiter that appears in neither 𝑠s nor 𝑡t. Then we compute the prefix function of this string. Now consider the meaning of the prefix function values after excluding the first 𝑛 +1n+1 values (i.e., those belonging to string 𝑠s and the delimiter). By definition, 𝜋[𝑖]π[i] is the length of the longest proper substring that ends at 𝑖i and is simultaneously a prefix. In our specific case, it is the length of the longest substring ending at 𝑖i that matches a prefix of 𝑠s. Due to the presence of the delimiter, this length cannot exceed 𝑛n. And if the equation 𝜋[𝑖] =𝑛π[i]=n holds, it means that 𝑠s appears completely at that position (i.e., its right end is at position 𝑖i). Note that the position index is in terms of the string 𝑠 +# +𝑡s+#+t.

    Therefore, if at some position 𝑖i we have 𝜋[𝑖] =𝑛π[i]=n, then string 𝑠s appears at position 𝑖 −(𝑛 −1) −(𝑛 +1) =𝑖 −2𝑛i−(n−1)−(n+1)=i−2n in string 𝑡t. The following figure shows the index diagram.

    As already mentioned in computing the prefix function, if we know that the prefix function values never exceed a certain value, then we don't need to store the entire string and the entire prefix function, but only the beginning of both. In our case, this means we only need to store the string 𝑠 +#s+# and the corresponding prefix function values. We can read the string 𝑡t one character at a time and compute the prefix function value for the current position.

    Thus, the Knuth–Morris–Pratt algorithm (KMP algorithm for short) solves this problem in 𝑂(𝑛 +𝑚)O(n+m) time and 𝑂(𝑛)O(n) memory.

    Period of a String

    For a string 𝑠s and 0 <𝑝 ≤|𝑠|0<p≤|s|, if 𝑠[𝑖] =𝑠[𝑖 +𝑝]s[i]=s[i+p] holds for all 𝑖 ∈[0,|𝑠| −𝑝 −1]i∈[0,|s|−p−1], then 𝑝p is called a period of 𝑠s.

    For a string 𝑠s and 0 ≤𝑟 <|𝑠|0≤r<|s|, if the prefix of 𝑠s of length 𝑟r equals the suffix of 𝑠s of length 𝑟r, then the prefix of 𝑠s of length 𝑟r is called a border of 𝑠s.

    From 𝑠s having a border of length 𝑟r, it follows that |𝑠| −𝑟|s|−r is a period of 𝑠s.

    According to the definition of the prefix function, we can obtain all border lengths of 𝑠s, i.e., 𝜋[𝑛 −1],𝜋[𝜋[𝑛 −1] −1],…π[n−1],π[π[n−1]−1],….2

    Therefore, using the prefix function, we can compute all periods of 𝑠s in 𝑂(𝑛)O(n) time. Since 𝜋[𝑛 −1]π[n−1] is the length of the longest border of 𝑠s, 𝑛 −𝜋[𝑛 −1]n−π[n−1] is the minimal period of 𝑠s.

    Counting Occurrences of Each Prefix

    Number of Distinct Substrings in a String

    Given a string 𝑠s of length 𝑛n, we want to compute the number of distinct substrings.

    We will solve this problem iteratively. In other words, given the current number of distinct substrings, we want to find a way to recalculate this number after adding a character at the end of 𝑠s.

    Let 𝑘k be the current number of distinct substrings of 𝑠s. We add a new character 𝑐c to 𝑠s. Obviously, some new substrings will end with character 𝑐c. We want to count these substrings ending with this character that we have not encountered before.

    Construct the string 𝑡 =𝑠 +𝑐t=s+c and reverse it to get 𝑡∼t∼. Now our task becomes: how many prefixes of 𝑡∼t∼ do not appear anywhere else in 𝑡∼t∼? If we compute the maximum prefix function value 𝜋maxπmax of 𝑡∼t∼, then the longest prefix that appears in 𝑠s has length 𝜋maxπmax. Naturally, all shorter prefixes also appear.

    Therefore, the number of new substrings appearing after adding a new character is |𝑠| +1 −𝜋max|s|+1−πmax.

    Thus, for each added character, we can compute the number of new substrings in 𝑂(𝑛)O(n) time, so the final complexity is 𝑂(𝑛2)O(n2).

    It is worth noting that we can also recalculate the number of distinct substrings when adding a character at the beginning, or removing a character from the end or beginning.

    String Compression

    Given a string 𝑠s of length 𝑛n, we want to find its shortest "compressed" representation, i.e., we want to find the shortest string 𝑡t such that 𝑠s can be represented by concatenating one or more copies of 𝑡t.

    Obviously, we only need to find the length of 𝑡t. Knowing this length, the answer to the problem is the prefix of 𝑠s of that length.

    Let's compute the prefix function of 𝑠s. Using the last value of this function 𝜋[𝑛 −1]π[n−1], we define 𝑘 =𝑛 −𝜋[𝑛 −1]k=n−π[n−1]. We will prove that if 𝑘k divides 𝑛n, then 𝑘k is the answer; otherwise, no valid compression exists, so the answer is 𝑛n.

    Assume 𝑛n is divisible by 𝑘k. Then the string can be divided into blocks of length 𝑘k. By the definition of the prefix function, the prefix of the string of length 𝑛 −𝑘n−k equals its suffix. However, this means the last block equals the second-to-last block, and the second-to-last block equals the third-to-last block, and so on. As a result, all blocks are equal, so we can compress string 𝑠s to length 𝑘k.

    Proof

    Indeed, we still need to prove that this value is optimal. Actually, if there is a compressed representation smaller than 𝑘k, then the last value of the prefix function 𝜋[𝑛 −1]π[n−1] must be greater than 𝑛 −𝑘n−k. Therefore, 𝑘k is the answer.

    Now assume 𝑛n is not divisible by 𝑘k. We will prove by contradiction that this means the answer is 𝑛n3. Suppose its minimal compressed representation 𝑟r has length 𝑝p ( 𝑝p divides 𝑛n ), and string 𝑠s is divided into 𝑛/𝑝 ≥2n/p≥2 blocks.     Building an Automaton from the Prefix Function

    Let's return to the new string formed by concatenating two strings with a delimiter. For strings 𝑠s and 𝑡t, we compute the prefix function of 𝑠 +# +𝑡s+#+t. Obviously, because ## is a delimiter, the prefix function values will never exceed |𝑠||s|. Therefore, we only need to store the string 𝑠 +#s+# and its corresponding prefix function values, after which we can dynamically compute the prefix function values for all subsequent characters:

    𝑠0 𝑠1 … 𝑠𝑛−1 #⏟___⏟___⏟need to store 𝑡0 𝑡1 … 𝑡𝑚−1⏟__⏟__⏟do not need to stores0 s1 … sn−1 #⏟need to store t0 t1 … tm−1⏟do not need to store

    In other words, we can construct an automaton (a finite state machine): its states are the current prefix function values, and transitions from one state to another are determined by the next character.

    When is this automaton useful? First, recall that most of the time we use the prefix function of 𝑠 +# +𝑡s+#+t for one purpose: finding all occurrences of string 𝑠s in string 𝑡t.

    By building the automaton of 𝑠 +#s+#, we no longer need to store string 𝑠s and its corresponding prefix function values. All transitions have already been computed in the table.

    𝐾[𝑖][𝑗]=𝐾[𝑖−1][𝑗]+[mid==|𝑠|]+𝐾[𝑖−1][mid]K[i][j]=K[i−1][j]+[mid==|s|]+K[i−1][mid]

    where [ ⋅][⋅] evaluates to 11 when the expression is true, and 00 otherwise. Thus, we have solved the problem about Gray strings, as well as a large class of similar problems. For example, using the same method, we can solve the following problem: given a string 𝑠s and some patterns 𝑡𝑖ti, where each pattern is given as follows: the pattern consists of ordinary characters, among which previous strings may be recursively inserted in the form 𝑡cnt𝑘tkcnt, i.e., at that position we must insert string 𝑡𝑘tk cntcnt times. Here is an example of such patterns:

    𝑡1=𝚊𝚋𝚍𝚎𝚌𝚊𝑡2=𝖺𝖻𝖼+𝑡301+𝖺𝖻𝖽𝑡3=𝑡502+𝑡1001𝑡4=𝑡102+𝑡1003t1=abdecat2=abc+t130+abdt3=t250+t1100t4=t210+t3100

    Recursive substitution causes the string length to explode exponentially, and their lengths can even reach the order of 100100100100. And we must find the number of occurrences of string 𝑠s in each of these strings.

    This problem can also be solved by constructing the automaton of the prefix function. As before, we compute the transitions for each pattern using the previously computed results and count the answers accordingly.
