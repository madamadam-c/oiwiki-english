    Boyer-Moore Algorithm

    KMP algorithm exploits the information from prefix matching to the fullest.

    The basic idea behind BM algorithm is to achieve faster character skipping by gaining more information from suffix matching than from prefix matching.

    Introduction

    Imagine our pattern string 𝑝𝑎𝑡pat is placed at the leftmost head of text string 𝑠𝑡𝑟𝑖𝑛𝑔string, aligning their first characters.

    𝑝𝑎𝑡:𝙴𝚇𝙰𝙼𝙿𝙻𝙴𝑠𝑡𝑟𝑖𝑛𝑔:𝙷𝙴𝚁𝙴 𝙸𝚂 𝙰 𝚂𝙸𝙼𝙿𝙻𝙴 𝙴𝚇𝙰𝙼𝙿𝙻𝙴…   ⇑pat:EXAMPLEstring:HERE IS A SIMPLE EXAMPLE…   ⇑

    Here we define: the length of 𝑝𝑎𝑡pat is 𝑝𝑎𝑡𝑙𝑒𝑛patlen, and especially for strings starting from 0, we define 𝑝𝑎𝑡𝑙𝑎𝑠𝑡𝑝𝑜𝑠 =𝑝𝑎𝑡𝑙𝑒𝑛 −1patlastpos=patlen−1 as the position of the last character of 𝑝𝑎𝑡pat;

    The length of 𝑠𝑡𝑟𝑖𝑛𝑔string is 𝑠𝑡𝑟𝑖𝑛𝑔𝑙𝑒𝑛stringlen, 𝑠𝑡𝑟𝑖𝑛𝑔𝑙𝑎𝑠𝑡𝑝𝑜𝑠 =𝑠𝑡𝑟𝑖𝑛𝑔𝑙𝑒𝑛 −1stringlastpos=stringlen−1.

    Suppose we know the 𝑝𝑎𝑡𝑙𝑒𝑛patlen-th character of 𝑠𝑡𝑟𝑖𝑛𝑔string (aligned with the last character of 𝑝𝑎𝑡pat), let's consider what information we can obtain:

    Observation 1

    If we know that this character 𝑐ℎ𝑎𝑟char does not appear in 𝑝𝑎𝑡pat, we don't need to consider the cases where 𝑝𝑎𝑡pat appears starting from the 1st, 2nd, ..., 𝑝𝑎𝑡𝑙𝑒𝑛patlen-th character of 𝑠𝑡𝑟𝑖𝑛𝑔string, and we can simply slide 𝑝𝑎𝑡pat down by 𝑝𝑎𝑡𝑙𝑒𝑛patlen characters.

    Observation 2

    More generally, if the position where 𝑐ℎ𝑎𝑟char appears at the end (i.e., rightmost) of 𝑝𝑎𝑡pat is 𝑑𝑒𝑙𝑡𝑎1delta1 characters away from the end,

    Then we can skip directly by 𝑑𝑒𝑙𝑡𝑎1delta1 characters: if the slide distance is less than 𝑑𝑒𝑙𝑡𝑎1delta1, then only the character 𝑐ℎ𝑎𝑟char cannot match, and of course the pattern string 𝑝𝑎𝑡pat won't match.

    Therefore, unless 𝑐ℎ𝑎𝑟char can match the last character of 𝑝𝑎𝑡pat, 𝑠𝑡𝑟𝑖𝑛𝑔string must skip 𝑑𝑒𝑙𝑡𝑎1delta1 characters (equivalent to sliding 𝑝𝑎𝑡pat backward by 𝑑𝑒𝑙𝑡𝑎1delta1 characters). And we can obtain a function 𝑑𝑒𝑙𝑡𝑎1(𝑐ℎ𝑎𝑟)delta1(char) to calculate 𝑑𝑒𝑙𝑡𝑎1delta1:

    𝐢𝐧𝐭 𝑑𝑒𝑙𝑡𝑎1(𝐜𝐡𝐚𝐫 𝑐ℎ𝑎𝑟)𝐢𝐟 char not in pat || char is the last character on pat𝐫𝐞𝐭𝐮𝐫𝐧 𝑝𝑎𝑡𝑙𝑒𝑛𝐞𝐥𝐬𝐞𝐫𝐞𝐭𝐮𝐫𝐧 𝑝𝑎𝑡𝑙𝑎𝑠𝑡𝑝𝑜𝑠−𝑖// i is the position where char appears at the rightmost end of pat, i.e., pat[i]=charint delta1(char char)if char not in pat || char is the last character on patreturn patlenelsereturn patlastpos−i// i is the position where char appears at the rightmost end of pat, i.e., pat[i]=char

    Note that this table clearly only needs to be calculated up to position 𝑝𝑎𝑡𝑙𝑎𝑠𝑡𝑝𝑜𝑠 −1patlastpos−1.

    Now suppose 𝑐ℎ𝑎𝑟char matches the last character of 𝑝𝑎𝑡pat, then let's see if the character before 𝑐ℎ𝑎𝑟char matches the second-to-last character of 𝑝𝑎𝑡pat:

    If it does, continue backing up until the entire pattern string 𝑝𝑎𝑡pat completes matching (at which point we've successfully found a match of 𝑝𝑎𝑡pat in 𝑠𝑡𝑟𝑖𝑛𝑔string);

    Or, we might mismatch after matching the 𝑚m-th-to-last character of 𝑝𝑎𝑡pat, at the (𝑚 +1)(m+1)-th-to-last character. At this point, we want to slide 𝑝𝑎𝑡pat forward to the next position where a match might be possible, and of course we want to slide as far as possible.

    Observation 3(a)

    In Observation 2, after matching the last 𝑚m characters of 𝑝𝑎𝑡pat, if we mismatch at the (𝑚 +1)(m+1)-th-to-last character, in order to align the mismatched character in 𝑠𝑡𝑟𝑖𝑛𝑔string with its corresponding character on 𝑝𝑎𝑡pat,

    We need to slide 𝑝𝑎𝑡pat backward by 𝑘k characters, meaning we should look at the subsequent 𝑘 +𝑚k+m characters (that is, look at the character aligned with 𝑠𝑡𝑟𝑖𝑛𝑔string after sliding 𝑝𝑎𝑡pat by 𝑘k).

    And 𝑘 =𝑑𝑒𝑙𝑡𝑎1 −𝑚k=delta1−m,

    So our attention should jump backward along 𝑠𝑡𝑟𝑖𝑛𝑔string by 𝑑𝑒𝑙𝑡𝑎1 −𝑚 +𝑚 =𝑑𝑒𝑙𝑡𝑎1delta1−m+m=delta1 characters.

    However, we have the opportunity to skip more characters—continue reading.

    Observation 3(b)

    If we know that the next 𝑚m characters of 𝑠𝑡𝑟𝑖𝑛𝑔string match the last 𝑚m characters of 𝑝𝑎𝑡pat, suppose this substring is 𝑠𝑢𝑏𝑝𝑎𝑡subpat,

    We also know that after the mismatched character 𝑐ℎ𝑎𝑟char in 𝑠𝑡𝑟𝑖𝑛𝑔string there is a substring matching 𝑠𝑢𝑏𝑝𝑎𝑡subpat. And if there exists 𝑠𝑢𝑏𝑝𝑎𝑡subpat before the corresponding mismatched character on 𝑝𝑎𝑡pat, we can slide 𝑝𝑎𝑡pat down by a distance,

    So that the 𝑠𝑢𝑏𝑝𝑎𝑡subpat (plausible reoccurrence, abbreviated as pr) that appears before the corresponding character of the mismatched character 𝑐ℎ𝑎𝑟char on 𝑝𝑎𝑡pat aligns with the 𝑠𝑢𝑏𝑝𝑎𝑡subpat in 𝑠𝑡𝑟𝑖𝑛𝑔string. If there are multiple 𝑠𝑢𝑏𝑝𝑎𝑡subpat on 𝑝𝑎𝑡pat, take the first one according to the right-to-left suffix matching order (rightmost plausible reoccurrence, abbreviated as rpr).

    Assume at this point 𝑝𝑎𝑡pat slides down by 𝑘k characters (i.e., the distance between the 𝑠𝑢𝑏𝑝𝑎𝑡subpat at the end of 𝑝𝑎𝑡pat and its rightmost plausible reoccurrence), then our attention should slide along 𝑠𝑡𝑟𝑖𝑛𝑔string by 𝑘 +𝑚k+m characters. This distance is called 𝑑𝑒𝑙𝑡𝑎2(𝑗)delta2(j):

    Assume 𝑟𝑝𝑟(𝑗)rpr(j) is the position of the rightmost plausible reoccurrence of 𝑠𝑢𝑏𝑝𝑎𝑡 =𝑝𝑎𝑡[𝑗 +1…𝑝𝑎𝑡𝑙𝑎𝑠𝑡𝑝𝑜𝑠]subpat=pat[j+1…patlastpos] when mismatching at 𝑝𝑎𝑡[𝑗]pat[j], 𝑟𝑝𝑟(𝑗) <𝑗rpr(j)<j (this is a simple definition; more precise discussion will be in the algorithm design section below), then obviously 𝑘 =𝑗 −𝑟𝑝𝑟(𝑗), 𝑚 =𝑝𝑎𝑡𝑙𝑎𝑠𝑡𝑝𝑜𝑠 −𝑗k=j−rpr(j), m=patlastpos−j.

    So we have:

    𝐢𝐧𝐭 𝑑𝑒𝑙𝑡𝑎2(𝐢𝐧𝐭 𝑗)// j is the position of the character on pat corresponding to the mismatched character𝐫𝐞𝐭𝐮𝐫𝐧 𝑝𝑎𝑡𝑙𝑎𝑠𝑡𝑝𝑜𝑠−𝑟𝑝𝑟(𝑗)int delta2(int j)// j is the position of the character on pat corresponding to the mismatched characterreturn patlastpos−rpr(j)

    Thus when mismatching, we can skip max(𝑑𝑒𝑙𝑡𝑎1,𝑑𝑒𝑙𝑡𝑎2)max(delta1,delta2) characters on 𝑠𝑡𝑟𝑖𝑛𝑔string.

    Efficient Algorithm

    Here we introduce an efficient algorithm with time complexity 𝑂(𝑛)O(n), but requiring additional 𝑂(𝑛)O(n) space complexity.

    Although Knuth proposed this construction method in 1977, his original version of the construction algorithm has a flaw—it actually doesn't produce 𝑑𝑒𝑙𝑡𝑎2delta2 that conforms to the definition for some 𝑝𝑎𝑡pat.

    2.     This gives us a good hint: we can use a process similar to calculating the prefix function to calculate case 3, but it's a reversed prefix function:

    • Two pointers point to the left endpoint of the substring and the "prefix" position of the longest common prefix-suffix of the substring, moving from right to left. When the two characters pointed to are equal, continue moving. This is equivalent to the "prefix" getting larger;
    • When the two characters are not equal, the previously equal part satisfies the requirement of 𝑑𝑒𝑙𝑡𝑎2delta2 for reappearance, and we backtrack the pointer pointing to the "prefix" position until new character equality is formed or we go out of bounds.

    Like the prefix function, we need an auxiliary array for backtracking. We can use the space of the prefix array generated in case 2.

pub fn build_delta_2_table_improved_minghu6(p: &[impl PartialEq]) -> Vec<usize> {
    let patlen = p.len();
    let lastpos = patlen - 1;
    let mut delta_2 = Vec::with_capacity(patlen);

    // Case 1
    // delta_2[j] = lastpos * 2 - j
    for i in 0..patlen {
        delta_2.push(lastpos * 2 - i);
    }

    // Case 2
    // lastpos <= delata2[j] = lastpos * 2 - j
    let pi = compute_pi(p);  // compute prefix function
    let mut i = lastpos;
    let mut last_i = lastpos; // just for initialization
    while pi[i] > 0 {
        let start;
        let end;

        if i == lastpos {
            start = 0;
        } else {
            start = patlen - pi[last_i];
        }

        end = patlen - pi[i];

        for j in start..end {
            delta_2[j] = lastpos * 2 - j - pi[i];
        }

        last_i = i;
        i = pi[i] - 1;
    }

    // Case 3
    // delata2[j] < lastpos
    let mut j = lastpos;
    let mut t = patlen;
    let mut f = pi;
    loop {
        f[j] = t;
        while t < patlen && p[j] != p[t] {
            // use min function to ensure later possible backtrack doesn't overwrite earlier data
            delta_2[t] = min(delta_2[t], lastpos - 1 - j);
            t = f[t];
        }

        t -= 1;
        if j == 0 {
            break;
        }
        j -= 1;
    }

    // no actual meaning, just for complete definition
    delta_2[lastpos] = 0;

    delta_2
}

    Galil Rule's Improvement to Worst-Case Scenario for Multiple Matches

    About the Multiple Match Problem of Suffix Matching Algorithms

    The previous search algorithm only involves finding the first 𝑝𝑎𝑡pat match in 𝑠𝑡𝑟𝑖𝑛𝑔string, but there are many different algorithmic approaches for finding all 𝑝𝑎𝑡pat matches in 𝑠𝑡𝑟𝑖𝑛𝑔string. The core concern of this problem is: how to use the information from previously successfully matched characters to reduce the worst-case time complexity to linear.

    After a successful match, simply sliding the 𝑠𝑡𝑟𝑖𝑛𝑔string pointer backward by 𝑝𝑎𝑡𝑙𝑒𝑛patlen distance and restarting suffix matching would lead to 𝑂(𝑚𝑛)O(mn) time complexity in the worst case (by convention, 𝑚m is 𝑝𝑎𝑡𝑙𝑒𝑛patlen, 𝑛n is 𝑠𝑡𝑟𝑖𝑛𝑔𝑙𝑒𝑛stringlen, same below).

    For example, an extreme case: 𝑝𝑎𝑡pat: 𝙰𝙰𝙰AAA, 𝑠𝑡𝑟𝑖𝑛𝑔string: 𝙰𝙰𝙰𝙰𝙰…AAAAA….

    Knuth proposed a method to use a "finite" set of states to record 𝑝𝑎𝑡𝑙𝑒𝑛patlen-length characters. This algorithm guarantees that each character on 𝑠𝑡𝑟𝑖𝑛𝑔string is compared at most once, but the cost is that this "finite" set of states may not be small—for a 𝑝𝑎𝑡pat where all characters are different, it needs 12𝑚2 +𝑚12m2+m states.

    The simple algorithm without additional preprocessing overhead introduced below is the Galil algorithm4.

    Galil Rule

    Assume a 𝑝𝑎𝑡pat, it is a prefix of a string 𝑈𝑈𝑈𝑈…UUUU… formed by repeating a substring 𝑈U n times. Then we call 𝑈U a period of 𝑝𝑎𝑡pat.

    For example, 𝑝𝑎𝑡 :𝙰𝙱𝙲𝙰𝙱𝙲𝙰𝙱pat:ABCABCAB is a prefix of 𝙰𝙱𝙲ABC repeated 𝙰𝙱𝙲𝙰𝙱𝙲𝙰𝙱𝙲ABCABCABC, so the length of 𝙰𝙱𝙲ABC, which is 3, is the period length of this 𝑝𝑎𝑡pat, that is, 𝑝𝑎𝑡[𝑖] =𝑝𝑎𝑡[𝑖 +3]pat[i]=pat[i+3].

    𝑝𝑎𝑡pat has at least one period with length equal to itself. We define the shortest period as 𝑘k, 𝑘 ≤𝑝𝑎𝑡𝑙𝑒𝑛k≤patlen.

    During the search process, if our 𝑝𝑎𝑡pat successfully completes a match, then according to the characteristics of the period, we only need to slide 𝑠𝑡𝑟𝑖𝑛𝑔string backward by 𝑘k characters and compare these 𝑘k characters to directly determine whether there is another match of 𝑝𝑎𝑡pat.

    To calculate the length of the shortest period, assume we know a pair of equal prefix-suffix of 𝑝𝑎𝑡pat, with length 𝑝𝑟𝑒𝑓𝑖𝑥𝑙𝑒𝑛prefixlen, then we have 𝑝𝑎𝑡[𝑖] =𝑝𝑎𝑡[𝑖 +(𝑝𝑎𝑡𝑙𝑒𝑛 −𝑝𝑟𝑒𝑓𝑖𝑥𝑙𝑒𝑛)]pat[i]=pat[i+(patlen−prefixlen)]. Thus we get a period of length 𝑝𝑎𝑡𝑙𝑒𝑛 −𝑝𝑟𝑒𝑓𝑖𝑥𝑙𝑒𝑛patlen−prefixlen,

    When we know the longest equal prefix-suffix of 𝑝𝑎𝑡pat, we get the shortest period of 𝑝𝑎𝑡pat.

    And the length of the longest equal prefix-suffix, 𝜋[𝑝𝑎𝑡𝑙𝑎𝑠𝑡𝑝𝑜𝑠]π[patlastpos], is already obtained during our calculation of 𝑑𝑒𝑙𝑡𝑎2delta2, so we don't need additional preprocessing time and space to improve the worst-case time complexity of the suffix matching algorithm to linear.

    pub fn find_all(&self, string: &str) -> Vec<usize> {
        let mut result = vec![];
        let string_bytes = string.as_bytes();
        let stringlen = string_bytes.len();
        let patlen = self.pat_bytes.len();
        let pat_last_pos = patlen - 1;
        let mut string_index = pat_last_pos;
        let mut pat_index;
        let l0 =  patlen - self.k;
        let mut l = 0;

        while string_index < stringlen {
            let old_string_index = string_index;

            while string_index < stringlen {
                string_index += self.delta0(string_bytes[string_index]);
            }
            if string_index < LARGE {
                break;
            }

            string_index -= LARGE;

            // If string_index has moved, it means there has been at least one failed match since the last successful match.
            // At this time, we need to reset the offset of the second match of Galil rule.
            if old_string_index < string_index {
                l = 0;
            }

            pat_index = pat_last_pos;

            while pat_index > l && string_bytes[string_index] == self.pat_bytes[pat_index] {
                string_index -= 1;
                pat_index -= 1;
            }

            if pat_index == l && string_bytes[string_index] == self.pat_bytes[pat_index] {
                result.push(string_index - l);

                string_index += pat_last_pos - l + self.k;
                l = l0;
            } else {
                l = 0;
                string_index += max(
                    self.delta_1[string_bytes[string_index] as usize],
                    self.delta_2[pat_index],
                );
            }
        }

        result
    }
}

    Impact of Worst Case on Practical Performance

    From a practical perspective, the theoretical worst case doesn't easily affect performance. Even with random text tests of very small alphabets of size 4, the impact of this worst case is too small to observe.

    Therefore, if not well designed, using the Galil rule will slightly drag down average performance. But for some extreme special 𝑝𝑎𝑡pat and 𝑠𝑡𝑟𝑖𝑛𝑔string like in the example: 𝑝𝑎𝑡pat: 𝙰𝙰𝙰AAA, 𝑠𝑡𝑟𝑖𝑛𝑔string: 𝙰𝙰𝙰𝙰𝙰…AAAAA…, the application of the Galil rule does improve performance several times over.

    Improved Algorithms

    Simplified Boyer-Moore Algorithm

    The most complex part of the BM algorithm is the construction of the 𝑑𝑒𝑙𝑡𝑎2delta2 table (i.e., the good suffix table). In practice, it was found that matching performance on general character sets relies mainly on the 𝑑𝑒𝑙𝑡𝑎1delta1 table (i.e., the bad character table). Therefore, a simplified version of the BM algorithm using only the 𝑑𝑒𝑙𝑡𝑎1delta1 table appeared, with usually little performance difference from the original.

    BMHBNFS Algorithm

    This algorithm combines Horspool and Sunday. It is the algorithm used for find in the stringlib module when CPython implements it5, hereinafter referred to as B5S.

    The basic idea of B5S is:

    1. Following the suffix matching approach, first compare whether the character at position 𝑝𝑎𝑡𝑙𝑎𝑠𝑡𝑝𝑜𝑠patlastpos is equal. If equal, compare whether the characters at positions 0…𝑝𝑎𝑡𝑙𝑎𝑠𝑡𝑝𝑜𝑠 −10…patlastpos−1 are equal. If still equal, we've found a match;

    2. If any stage has a mismatch, enter the jump phase;

    3. In the jump phase, first check whether the next character after position 𝑝𝑎𝑡𝑙𝑎𝑠𝑡𝑝𝑜𝑠patlastpos is in 𝑝𝑎𝑡pat. If not, slide directly to the right by 𝑝𝑎𝑡𝑙𝑒𝑛 +1patlen+1—this is the maximum use of the Sunday algorithm; If this character is in 𝑝𝑎𝑡pat, use 𝑑𝑒𝑙𝑡𝑎1delta1 at position 𝑝𝑎𝑡𝑙𝑎𝑠𝑡𝑝𝑜𝑠patlastpos for Horspool jump.

    Depending on whether time saving or space saving is the primary goal, the algorithm has vastly different implementations.

      The Bloom filter is designed as a Set type data structure that sacrifices accuracy (and also running time) to greatly save storage space. Its characteristic is that it will incorrectly judge items not in the set as existing (False Positives, abbreviated as FP), but will not judge items in the set as not existing (False Negatives, abbreviated as FN). Therefore, using it might not get the maximum character jump due to FP, but will not skip characters that should match due to FN.

      Theoretically analyzing, for the above "Bloom filter" implementation, when 𝑝𝑎𝑡pat length is 50 bytes, the FP probability is about 0.5, and when 𝑝𝑎𝑡pat length is 10 bytes, the FP probability is about 0.15.

      Although this is not a standard Bloom filter, first it actually doesn't use a real hash function—it is actually just a character mapping, mapping bytes 0-255 to the number formed by its first six bits.

      But considering we're doing character search in memory, this simplification is very important. Even using the fastest known non-cryptographic hash algorithm xxHash, the computation time is still an order of magnitude higher than this.

      Additionally, when 𝑝𝑎𝑡pat is below 30 bytes, to achieve the best FP probability, more than one hash function is needed. But this doesn't make much sense because an array with two u128 numbers can already build a full character set for the alphabet.

        while string_index < stringlen {
            if string_bytes[string_index] == self.pat_bytes[pat_last_pos] {
                if &string_bytes[string_index-pat_last_pos..string_index] == &self.pat_bytes[..patlen-1] {
                    result.push(string_index-pat_last_pos);
                }

                if string_index + 1 == stringlen {
                    break;
                }

                if !self.alphabet.contains(&string_bytes[string_index+1]) {
                    string_index += patlen + 1;  // sunday
                } else {
                    string_index += self.skip;  // horspool
                }
            } else {
                if string_index + 1 == stringlen {
                    break;
                }

                if !self.alphabet.contains(&string_bytes[string_index+1]) {
                    string_index += patlen + 1;  // sunday
                } else {
                    string_index += 1;
                }
            }

        }

        result
    }
}

      This version of the algorithm is not as fast as the previous suffix matching algorithms, but the gap is not large. The performance is still better than KMP, thanks to its excellent space complexity with at most two u64 integers.
