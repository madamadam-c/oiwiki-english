    String Hashing

    Definition

    We define a function 𝑓f that maps strings to integers, and this 𝑓f is called a Hash function.

    We want this function 𝑓f to help us conveniently determine whether two strings are equal.

    Idea of Hash

    The core idea of Hash is to map input to a small value range that can be easily compared.

    Warning

    The meaning of "small value range" varies in different contexts.

    In hash tables, the value range needs to be small enough to accept linear space and time complexity.

    In string hashing, the value range needs to be small enough for fast comparison (109109, 10181018 are both fast to compare).

    At the same time, to reduce the hash collision rate, the value range cannot be too small either.

    Properties

    Specifically, the most important properties of a hash function can be summarized as follows:

    1. When the hash function values are different, the two strings must be different;

    2. When the hash function values are the same, the two strings are not necessarily the same (but they are likely to be the same with high probability, and of course we would like them to always be the same).

      We call the phenomenon where the hash function values are the same but the original strings are different a hash collision.

    Explanation

    What do we need to focus on?

    Time complexity and the accuracy of Hash.

    Typically, we use the polynomial Hash method. For a string 𝑠s of length 𝑙l, we can define the polynomial Hash function as: 𝑓(𝑠) =∑𝑙𝑖=1𝑠[𝑖] ×𝑏𝑙−𝑖(mod𝑀)f(s)=∑i=1ls[i]×bl−i(modM). For example, for the string 𝑥𝑦𝑧xyz, its hash function value is 𝑥𝑏2 +𝑦𝑏 +𝑧xb2+yb+z.

    It should be noted that many people use an alternative definition of the Hash function, namely 𝑓(𝑠) =∑𝑙𝑖=1𝑠[𝑖] ×𝑏𝑖−1(mod𝑀)f(s)=∑i=1ls[i]×bi−1(modM). With this definition, the hash value of the same string 𝑥𝑦𝑧xyz becomes 𝑥 +𝑦𝑏 +𝑧𝑏2x+yb+zb2.

    Clearly, both definitions are viable, but the calculation formulas used for computing substring hash values (which will be discussed later) are different between the two. Therefore, be careful not to confuse these two different Hash methods.

    Since the first definition is simpler to calculate, used by more people, and can be understood by analogy with a base-𝑏b number, the discussion below will focus on the Hash function defined by 𝑓(𝑠) =∑𝑙𝑖=1𝑠[𝑖] ×𝑏𝑙−𝑖(mod𝑀)f(s)=∑i=1ls[i]×bl−i(modM).

    Additionally, sometimes for convenience and to expand the modulus, we use unsigned long long in C++ to define the result of the Hash function. Due to C++'s characteristics, this effectively sets the modulus 𝑀M to 264264, which is also a good choice.

    The accuracy will be discussed later.

    Analysis of Hash Error Rate

    Hash Collision

    Hash collision refers to two different strings mapping to the same Hash value.

    Let the value space of Hash (the number of all possible strings) be 𝑑d, and the number of calculations (the number of strings to be calculated) be 𝑛n.

    Then the probability of Hash collision is:

    𝑝(𝑛,𝑑)=1−𝑑!𝑑𝑛(𝑑−𝑛)!≈1−exp⁡(−𝑛(𝑛−1)2𝑑)p(n,d)=1−d!dn(d−n)!≈1−exp⁡(−n(n−1)2d)
    Proof

    When each value in Hash has equal probability of being generated, the probability of no collision is:

    ――𝑝(𝑛,𝑑)=1⋅(1−1𝑑)⋅(1−2𝑑)⋯(1−𝑛−1𝑑)p―(n,d)=1⋅(1−1d)⋅(1−2d)⋯(1−n−1d)

    Simplifying gives:

    ――𝑝(𝑛,𝑑)=𝑑𝑑⋅𝑑−1𝑑⋅𝑑−2𝑑⋯𝑑−𝑛+1𝑑=𝑑⋅(𝑑−1)⋅(𝑑−2)⋯(𝑑−𝑛+1)𝑑𝑛=𝑑!𝑑𝑛(𝑑−𝑛)!p―(n,d)=dd⋅d−1d⋅d−2d⋯d−n+1d=d⋅(d−1)⋅(d−2)⋯(d−n+1)dn=d!dn(d−n)!

    Therefore, the probability of Hash collision is:

    𝑝(𝑛,𝑑)=1−𝑑!𝑑𝑛(𝑑−𝑛)!p(n,d)=1−d!dn(d−n)!

    This formula is still too complex, so we simplify further.

    According to Taylor's formula:

    exp⁡(𝑥)=∞∑𝑘=0𝑥𝑘𝑘!=1+𝑥+𝑥22+𝑥36+𝑥424+⋯exp⁡(x)=∑k=0∞xkk!=1+x+x22+x36+x424+⋯

    When 𝑥x is an extremely small value, exp⁡(𝑥)exp⁡(x) approaches 1 +𝑥1+x.

    Substituting this into the original formula for no collision:

    ――𝑝(𝑛,𝑑)≈1⋅exp⁡(−1𝑑)⋅exp⁡(−2𝑑)⋯exp⁡(−𝑛−1𝑑)p―(n,d)≈1⋅exp⁡(−1d)⋅exp⁡(−2d)⋯exp⁡(−n−1d)

    Simplifying:

    ――𝑝(𝑛,𝑑)≈exp⁡(−1𝑑−2𝑑−⋯−𝑛−1𝑑)=exp⁡(−𝑛(𝑛−1)2𝑑)p―(n,d)≈exp⁡(−1d−2d−⋯−n−1d)=exp⁡(−n(n−1)2d)

    Therefore, the probability of Hash collision is:

    𝑝(𝑛,𝑑)≈1−exp⁡(−𝑛(𝑛−1)2𝑑)p(n,d)≈1−exp⁡(−n(n−1)2d)

    Cracking Hash with Large Modulus

    Notice this formula:

    𝑝(𝑛,𝑑)≈1−exp⁡(−𝑛(𝑛−1)2𝑑)p(n,d)≈1−exp⁡(−n(n−1)2d)

    To crack Hash, we need to satisfy the following conditions:

    1. 𝑑d must be greater than the modulus.
    2. 1 −𝑝(𝑑,𝑛)1−p(d,n) should be as small as possible.

    For example:

    If the character set is uppercase and lowercase letters and digits, and the modulus is 109 +7109+7:

    log62⁡109 +7 ≈6log62⁡109+7≈6

    𝑝(106,626) ≈0.9p(106,626)≈0.9

    Therefore, for this range, if we randomly generate 106106 strings of length 66, the probability that they have the same Hash value is as high as 90%90%.

    Cracking Natural Overflow Hash

    Since this Hash has too large a modulus, it cannot be cracked using the method above, so we need a different approach.

    First, this Hash has the form 𝑓(𝑠) =∑𝑙𝑖=1𝑠[𝑖] ×𝑏𝑙−𝑖f(s)=∑i=1ls[i]×bl−i. We classify and discuss based on 𝑏b.

    When b is even

    At this point, 𝑓(𝑠) =𝑠1 ⋅𝑏𝑙 +𝑠2 ⋅𝑏𝑙−1 +⋯ +𝑠𝑙 ⋅𝑏(mod𝑀)f(s)=s1⋅bl+s2⋅bl−1+⋯+sl⋅b(modM), where 𝑀M is 264264.

    It is easy to see that if 𝑙 ≥64l≥64, then 𝑠𝑖 ⋅𝑏𝑙 ≡0(mod𝑀)si⋅bl≡0(modM).

    So we just need to construct strings of length greater than 6464 in the form:

    aaa...a

    baa...a

    to cause collision.

    When b is odd

    Define !𝑠𝑖!si as reversing all characters in 𝑠𝑖si.

    Example:

    𝑠𝑖 =𝑎𝑏𝑎𝑎𝑏si=abaab

    !𝑠𝑖 =𝑏𝑎𝑏𝑏𝑎!si=babba

    That is, change a to b and b to a.

    Then define ℎ𝑎𝑠ℎ𝑖hashi as the Hash value of 𝑠𝑖si, and !ℎ𝑎𝑠ℎ𝑖!hashi as the Hash value of !𝑠𝑖!si.

    Continuously construct 𝑠𝑖 =𝑠𝑖−1 +!𝑠𝑖−1si=si−1+!si−1.

    𝑠12s12 and !𝑠12!s12 are the two strings we need.

    Derivation

    First, we have:

    ℎ𝑎𝑠ℎ𝑖=ℎ𝑎𝑠ℎ𝑖−1⋅𝑏𝑎𝑠𝑒2𝑖−2+!ℎ𝑎𝑠ℎ𝑖−1!ℎ𝑎𝑠ℎ𝑖=!ℎ𝑎𝑠ℎ𝑖−1⋅𝑏𝑎𝑠𝑒2𝑖−2+ℎ𝑎𝑠ℎ𝑖−1hashi=hashi−1⋅base2i−2+!hashi−1!hashi=!hashi−1⋅base2i−2+hashi−1

    Try subtracting:

    ℎ𝑎𝑠ℎ𝑖−!ℎ𝑎𝑠ℎ𝑖= ℎ𝑎𝑠ℎ𝑖−1⋅𝑏𝑎𝑠𝑒2𝑖−2+!ℎ𝑎𝑠ℎ𝑖−1−(!ℎ𝑎𝑠ℎ𝑖−1⋅𝑏𝑎𝑠𝑒2𝑖−2+ℎ𝑎𝑠ℎ𝑖−1)= (ℎ𝑎𝑠ℎ𝑖−1−!ℎ𝑎𝑠ℎ𝑖−1)⋅(𝑏𝑎𝑠𝑒2𝑖−2−1)hashi−!hashi= hashi−1⋅base2i−2+!hashi−1−(!hashi−1⋅base2i−2+hashi−1)= (hashi−1−!hashi−1)⋅(base2i−2−1)

    We find 2𝑖2i appears, but the original formula is too complex. Let's try substitution:

    Let:

    𝑓𝑖=ℎ𝑎𝑠ℎ𝑖−!ℎ𝑎𝑠ℎ𝑖𝑔𝑖=𝑏𝑎𝑠𝑒2𝑖−2−1fi=hashi−!hashigi=base2i−2−1

    From the original formula:

    𝑓𝑖=𝑓𝑖−1⋅𝑔𝑖=𝑓1⋅𝑔1⋅𝑔2⋯𝑔𝑖−1fi=fi−1⋅gi=f1⋅g1⋅g2⋯gi−1

    Since 𝑏𝑎𝑠𝑒2𝑖−2base2i−2 is always odd, 𝑔𝑖gi must be even.

    Therefore:

    2𝑖−1|𝑓𝑖2i−1|fi

    But this is too large, we need 𝑖 −1 ≥64i−1≥64 to crack it. Continue simplifying:

    Improvements to Hash

    Multi-value Hash

    After seeing so many ways to crack Hash above, there are of course solutions.

    Multi-value Hash means having multiple hash functions, each with a different modulus. This solves the problem of hash collisions.

    When judging, as long as one of the Hash values is different, the two strings are considered different. If all Hash values are the same, the two strings are considered the same.

    Generally, double-value Hash is sufficient.

    Multiple Substring Hash Queries

    The time complexity of computing the hash of a single string is 𝑂(𝑛)O(n), where 𝑛n is the string length, which is no different from brute force matching. If we need to query the hash of substrings of a string multiple times, recalculating each time is very inefficient.

    The common approach is to preprocess the hash value for each prefix of the entire string, treating the hash value as the result of a base-𝑏b number modulo 𝑀M. This allows us to quickly compute the hash of substrings:

    Let 𝑓𝑖(𝑠)fi(s) denote 𝑓(𝑠[1..𝑖])f(s[1..i]), i.e., the hash value of the prefix of length 𝑖i of the original string. Then according to the definition, 𝑓𝑖(𝑠) =𝑠[1] ⋅𝑏𝑖−1 +𝑠[2] ⋅𝑏𝑖−2 +⋯ +𝑠[𝑖 −1] ⋅𝑏 +𝑠[𝑖]fi(s)=s[1]⋅bi−1+s[2]⋅bi−2+⋯+s[i−1]⋅b+s[i]

    Now, we want to quickly compute 𝑓(𝑠[𝑙..𝑟])f(s[l..r]) using a prefix-sum-like method. According to the definition, the hash value of string 𝑠[𝑙..𝑟]s[l..r] is 𝑓(𝑠[𝑙..𝑟]) =𝑠[𝑙] ⋅𝑏𝑟−𝑙 +𝑠[𝑙 +1] ⋅𝑏𝑟−𝑙−1 +⋯ +𝑠[𝑟 −1] ⋅𝑏 +𝑠[𝑟]f(s[l..r])=s[l]⋅br−l+s[l+1]⋅br−l−1+⋯+s[r−1]⋅b+s[r]

    Comparing the two formulas above, we find that 𝑓(𝑠[𝑙..𝑟]) =𝑓𝑟(𝑠) −𝑓𝑙−1(𝑠) ×𝑏𝑟−𝑙+1f(s[l..r])=fr(s)−fl−1(s)×br−l+1 holds (you can manually substitute to verify). Therefore, we can use this formula to quickly get the hash of a substring. Here, 𝑏𝑟−𝑙+1br−l+1 can be preprocessed in 𝑂(𝑛)O(n) and then answered in 𝑂(1)O(1) for each query (or computed with fast exponentiation in 𝑂(log⁡𝑛)O(log⁡n) for each query).

    Applications of Hash

    String Matching

    After computing the hash of the pattern string, compute the hash of each substring of the text string with the same length as the pattern string, and compare each with the hash of the pattern string.

    String Matching Allowing k Mismatches

    Problem: Given a source string 𝑠s of length 𝑛n, and a pattern string 𝑝p of length 𝑚m, find how many substrings in the source string match the pattern string. 𝑠′s′ matches 𝑠s if and only if 𝑠′s′ has the same length as 𝑠s, and at most 𝑘k positions have different characters. Here 1 ≤𝑛,𝑚 ≤1061≤n,m≤106, 0 ≤𝑘 ≤50≤k≤5.

    This problem cannot be solved using KMP, but can be solved with hash + binary search.

    Enumerate all possible matching substrings. Suppose the currently enumerated substring is 𝑠′s′. Using hash + binary search, we can quickly find the first different position between 𝑠′s′ and 𝑝p. Then delete the part of 𝑠′s′ and 𝑝p from this mismatch position and before, and continue searching for the next mismatch position. This process occurs at most 𝑘k times.

    The total time complexity is 𝑂(𝑚 +𝑘𝑛log2⁡𝑚)O(m+knlog2⁡m).

    Longest Palindromic Substring

    Binary search the answer, and when checking feasibility, enumerate the palindrome center (axis of symmetry) and use hash to check if the two sides are equal. Need to preprocess both forward and reverse hash values. Time complexity is 𝑂(𝑛log⁡𝑛)O(nlog⁡n).

    This problem can be solved using the Manacher algorithm in 𝑂(𝑛)O(n) time.

    It can also be solved in 𝑂(𝑛)O(n) using hash. The specific method is to let 𝑅𝑖Ri denote the length of the longest palindrome ending at 𝑖i. Then the answer is max𝑛𝑖=1𝑅𝑖maxi=1nRi. Considering that 𝑅𝑖 ≤𝑅𝑖−1 +2Ri≤Ri−1+2, we only need to brute force starting from 𝑅𝑖−1 +2Ri−1+2 and decrease until finding the first palindrome. Let variable 𝑧z denote the current enumerated 𝑅𝑖Ri, initially 00. Then 𝑧z increases by 22 each time 𝑖i increases, and decreases by 11 during each brute force iteration. Therefore, the brute force loop executes at most 2𝑛2n times, giving a total time complexity of 𝑂(𝑛)O(n).

    Longest Common Substring

    Problem: Given 𝑚m non-empty strings with total length not exceeding 𝑛n, find the longest common substring among all strings. If there are multiple, output any one of them. Here 1 ≤𝑚,𝑛 ≤1061≤m,n≤106.

    Clearly, if there exists a longest common substring of length 𝑘k, then a common substring of length 𝑘 −1k−1 must also exist. Therefore, we can binary search the length of the longest common substring. Suppose the current length is 𝑘k. The logic of check(k) is to hash all substrings of length 𝑘k from each string and store the hash values in 𝑛n hash tables. Then compute the intersection.

    Time complexity is 𝑂(𝑚 +𝑛log⁡𝑛)O(m+nlog⁡n).

    Counting Distinct Substrings in a String

    Problem: Given a string of length 𝑛n, consisting only of lowercase English letters, find the number of distinct substrings in this string.

    To solve this problem, we iterate over all substrings of length 𝑙 =1,⋯,𝑛l=1,⋯,n. For each length 𝑙l, we multiply its Hash value by the same power of 𝑏b and store it in an array. The number of distinct elements in the array equals the number of distinct substrings of that length in the string, and this number is added to the final answer.

    For convenience, we will use ℎ[𝑖]h[i] as the prefix hash, and define ℎ[0] =0h[0]=0.

    int count_unique_substrings(string const& s) {
  int n = s.size();

  constexpr static int b = 31;
  constexpr static int m = 1e9 + 9;
  vector<long long> b_pow(n);
  b_pow[0] = 1;
  for (int i = 1; i < n; i++) b_pow[i] = (b_pow[i - 1] * b) % m;

  vector<long long> h(n + 1, 0);
  for (int i = 0; i < n; i++)
    h[i + 1] = (h[i] + (s[i] - 'a' + 1) * b_pow[i]) % m;

  int cnt = 0;
  for (int l = 1; l <= n; l++) {
    set<long long> hs;
    for (int i = 0; i <= n - l; i++) {
      long long cur_h = (h[i + l] + m - h[i]) % m;
      cur_h = (cur_h * b_pow[n - i - 1]) % m;
      hs.insert(cur_h);
    }
    cnt += hs.size();
  }
  return cnt;
}

    #include <cassert>
#include <cstring>
#include <iostream>
#include <vector>
using namespace std;

constexpr int L = 1e6 + 5;
constexpr int HASH_CNT = 2;

int hashBase[HASH_CNT] = {29, 31};
int hashMod[HASH_CNT] = {int(1e9 + 9), 998244353};

struct StringWithHash {
  char s[L];
  int ls;
  int hsh[HASH_CNT][L];
  int pwMod[HASH_CNT][L];

  void init() {  // 初始化
    ls = 0;
    for (int i = 0; i < HASH_CNT; ++i) {
      hsh[i][0] = 0;
      pwMod[i][0] = 1;
    }
  }

  StringWithHash() { init(); }

  void extend(char c) {
    s[++ls] = c;                          // 记录字符数和每一个字符
    for (int i = 0; i < HASH_CNT; ++i) {  // 双哈希的预处理
      pwMod[i][ls] =
          1ll * pwMod[i][ls - 1] * hashBase[i] % hashMod[i];  // 得到b^ls
      hsh[i][ls] = (1ll * hsh[i][ls - 1] * hashBase[i] + c) % hashMod[i];
    }
  }

  vector<int> getHash(int l, int r) {  // 得到哈希值
    vector<int> res(HASH_CNT, 0);
    for (int i = 0; i < HASH_CNT; ++i) {
      int t =
          (hsh[i][r] - 1ll * hsh[i][l - 1] * pwMod[i][r - l + 1]) % hashMod[i];
      t = (t + hashMod[i]) % hashMod[i];
      res[i] = t;
    }
    return res;
  }
};

bool equal(const vector<int> &h1, const vector<int> &h2) {
  assert(h1.size() == h2.size());
  for (unsigned i = 0; i < h1.size(); i++)
    if (h1[i] != h2[i]) return false;
  return true;
}

int n;
StringWithHash s, t;
char str[L];

void work() {
  int len = strlen(str);  // 取字符串长度
  t.init();
  for (int j = 0; j < len; ++j) t.extend(str[j]);
  int d = 0;
  for (int j = min(len, s.ls); j >= 1; --j) {
    if (equal(t.getHash(1, j), s.getHash(s.ls - j + 1, s.ls))) {  // 比较哈希值
      d = j;
      break;
    }
  }
  for (int j = d; j < len; ++j) s.extend(str[j]);  // 更新答案数组
}

int main() {
  cin.tie(nullptr)->sync_with_stdio(false);
  cin >> n;
  for (int i = 1; i <= n; ++i) {
    cin >> str;
    work();
  }
  cout << s.s + 1 << '\n';
  return 0;
}
