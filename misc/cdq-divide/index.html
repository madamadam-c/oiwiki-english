    CDQ Divide-and-Conquer

    This page introduces CDQ divide and conquer.

    Introduction

    CDQ divide and conquer is an idea rather than a specific algorithm, similar to dynamic programming. This idea has been extended widely. Depending on the principle and implementation, it is roughly divided into three categories:

    • Solving problems related to pairs of points.
    • Optimizing and transferring 1D dynamic programming.
    • Transforming some dynamic problems into static problems through CDQ divide and conquer.

    The idea of CDQ divide and conquer was first organized and summarized by IOI 2008 gold medalist Danqi Chen in high school, and it is named after her initials.1

    Solving Problems Related to Pairs of Points

    Most problems of this type are similar to: "given a sequence of length 𝑛n, count the number of pairs (𝑖,𝑗)(i,j) with certain properties", or "given a sequence of length 𝑛n, find a pair (𝑖,𝑗)(i,j) that maximizes the value of some function".

    The algorithmic process for using CDQ divide and conquer to solve this type of problem is as follows:

    1. Find the midpoint 𝑚𝑖𝑑mid of the sequence;

    2. Divide all pairs (𝑖,𝑗)(i,j) into 3 categories:

      1. Pairs satisfying 1 ≤𝑖 ≤𝑚𝑖𝑑,1 ≤𝑗 ≤𝑚𝑖𝑑1≤i≤mid,1≤j≤mid;
      2. Pairs satisfying 1 ≤𝑖 ≤𝑚𝑖𝑑,𝑚𝑖𝑑 +1 ≤𝑗 ≤𝑛1≤i≤mid,mid+1≤j≤n;
      3. Pairs satisfying 𝑚𝑖𝑑 +1 ≤𝑖 ≤𝑛,𝑚𝑖𝑑 +1 ≤𝑗 ≤𝑛mid+1≤i≤n,mid+1≤j≤n.

    3. Split the sequence (1,𝑛)(1,n) into two sequences (1,𝑚𝑖𝑑)(1,mid) and (𝑚𝑖𝑑 +1,𝑛)(mid+1,n). At this point, the first and third categories of pairs lie within these two sequences;

    4. Recursively process these two categories of pairs;

    5. Find a way to process the second category of pairs.

    As we can see, the idea of CDQ divide and conquer is to continuously assign pairs of points to the left and right intervals recursively.

    In practice, we usually use a function solve(l,r) to process pairs satisfying 𝑙 ≤𝑖 ≤𝑟,𝑙 ≤𝑗 ≤𝑟l≤i≤r,l≤j≤r. The recursive part of the above algorithm is implemented by solve(l,mid) and solve(mid,r). The remaining second category of pairs requires an additional algorithm.

    Examples

    三维偏序

    Given a sequence where each point has three attributes 𝑎𝑖,𝑏𝑖,𝑐𝑖ai,bi,ci, find how many pairs (𝑖,𝑗)(i,j) in the sequence satisfy 𝑎𝑗 ≤𝑎𝑖aj≤ai, 𝑏𝑗 ≤𝑏𝑖bj≤bi, 𝑐𝑗 ≤𝑐𝑖cj≤ci, and 𝑗 ≠𝑖j≠i.

    Solution

    Three-dimensional partial order is a classic CDQ divide and conquer problem.

    The problem asks us to count pairs of points in a sequence, so try CDQ divide and conquer.

    First sort the sequence by 𝑎a.

    Suppose we have written solve(l,r) and have recursively handled solve(l,mid) and solve(mid+1,r). What remains is to count, among pairs (𝑖,𝑗)(i,j) satisfying 𝑙 ≤𝑖 ≤𝑚𝑖𝑑l≤i≤mid and 𝑚𝑖𝑑 +1 ≤𝑗 ≤𝑟mid+1≤j≤r, how many also satisfy the constraints 𝑎𝑖 ≤𝑎𝑗ai≤aj, 𝑏𝑖 ≤𝑏𝑗bi≤bj, and 𝑐𝑖 ≤𝑐𝑗ci≤cj.

    With a little thought, we find that the constraint 𝑎𝑖 ≤𝑎𝑗ai≤aj is no longer useful: since 𝑖i is smaller than 𝑚𝑖𝑑mid and 𝑗j is larger than 𝑚𝑖𝑑mid, 𝑖i must be smaller than 𝑗j; after sorting the sequence by 𝑎a, we must have 𝑎𝑖 ≤𝑎𝑗ai≤aj. Two constraints remain: 𝑏𝑖 ≤𝑏𝑗bi≤bj and 𝑐𝑖 ≤𝑐𝑗ci≤cj. Based on these constraints, we can enumerate 𝑗j and find how many valid 𝑖i exist.

    To make enumeration convenient, sort all points in (𝑙,𝑚𝑖𝑑)(l,mid) and (𝑚𝑖𝑑 +1,𝑟)(mid+1,r) by their 𝑏b values in increasing order. Then enumerate each 𝑗j in order and insert all points 𝑖i with 𝑏𝑖 ≤𝑏𝑗bi≤bj into some data structure (here we choose a Fenwick tree). Now, by querying how many points in the Fenwick tree have 𝑐c values less than or equal to 𝑐𝑗cj, we know how many 𝑖i can validly match this point 𝑗j.

    When inserting a point whose 𝑐c value equals 𝑥x, we add one to position 𝑥x in the Fenwick tree. Querying how many points in the Fenwick tree are less than 𝑥x is essentially computing a prefix sum. As long as all 𝑐c values have been discretized beforehand, the complexity is correct.

    For each 𝑗j, we need to insert all points 𝑖i satisfying 𝑏𝑖 ≤𝑏𝑗bi≤bj into the Fenwick tree. Since all 𝑖i and 𝑗j have already been sorted by 𝑏b, inserting points into the Fenwick tree with two pointers reduces the number of insertions from 𝑂(𝑛2)O(n2) to 𝑂(𝑛)O(n).

    With this algorithmic process, we handle the information about the second category of pairs in 𝑂(𝑛log⁡𝑛)O(nlog⁡n) time. The time complexity of the algorithm is then 𝑇(𝑛) =𝑇(⌊𝑛2⌋) +𝑇(⌈𝑛2⌉) +𝑂(𝑛log⁡𝑛) =𝑂(𝑛log2⁡𝑛)T(n)=T(⌊n2⌋)+T(⌈n2⌉)+O(nlog⁡n)=O(nlog2⁡n).

    #include <algorithm>
#include <iostream>

constexpr int MAXN = 1e5 + 10;
constexpr int MAXK = 2e5 + 10;

int n, k;

struct Element {
  int a, b, c;
  int cnt;
  int res;

  bool operator!=(Element other) const {
    if (a != other.a) return true;
    if (b != other.b) return true;
    if (c != other.c) return true;
    return false;
  }
};

Element e[MAXN];
Element ue[MAXN];
int m, t;
int res[MAXN];

struct BinaryIndexedTree {
  int node[MAXK];

  int lowbit(int x) { return x & -x; }

  void Add(int pos, int val) {
    while (pos <= k) {
      node[pos] += val;
      pos += lowbit(pos);
    }
    return;
  }

  int Ask(int pos) {
    int res = 0;
    while (pos) {
      res += node[pos];
      pos -= lowbit(pos);
    }
    return res;
  }
} BIT;

bool cmpA(Element x, Element y) {
  if (x.a != y.a) return x.a < y.a;
  if (x.b != y.b) return x.b < y.b;
  return x.c < y.c;
}

bool cmpB(Element x, Element y) {
  if (x.b != y.b) return x.b < y.b;
  return x.c < y.c;
}

void CDQ(int l, int r) {
  if (l == r) return;
  int mid = (l + r) / 2;
  CDQ(l, mid);
  CDQ(mid + 1, r);
  std::sort(ue + l, ue + mid + 1, cmpB);
  std::sort(ue + mid + 1, ue + r + 1, cmpB);
  int i = l;
  int j = mid + 1;
  while (j <= r) {
    while (i <= mid && ue[i].b <= ue[j].b) {
      BIT.Add(ue[i].c, ue[i].cnt);
      i++;
    }
    ue[j].res += BIT.Ask(ue[j].c);
    j++;
  }
  for (int k = l; k < i; k++) BIT.Add(ue[k].c, -ue[k].cnt);
  return;
}

using std::cin;
using std::cout;

int main() {
  cin.tie(nullptr)->sync_with_stdio(false);
  cin >> n >> k;
  for (int i = 1; i <= n; i++) cin >> e[i].a >> e[i].b >> e[i].c;
  std::sort(e + 1, e + n + 1, cmpA);
  for (int i = 1; i <= n; i++) {
    t++;
    if (e[i] != e[i + 1]) {
      m++;
      ue[m].a = e[i].a;
      ue[m].b = e[i].b;
      ue[m].c = e[i].c;
      ue[m].cnt = t;
      t = 0;
    }
  }
  CDQ(1, m);
  for (int i = 1; i <= m; i++) res[ue[i].res + ue[i].cnt - 1] += ue[i].cnt;
  for (int i = 0; i < n; i++) cout << res[i] << '\n';
  return 0;
}

struct treearray {
  int ta[200010];

    for (; x <= n + 1; ub(x)) ta[x] += t;

    int r = 0;

    Optimizing 1D/1D Dynamic Programming Transitions with CDQ Divide and Conquer

    Related content: CDQ divide and conquer optimization for DP

    1D/1D dynamic programming refers to a specific class of DP problems where the DP array is one-dimensional and each transition is 𝑂(𝑛)O(n). Under suitable conditions, CDQ divide and conquer can sometimes reduce their time complexity from 𝑂(𝑛2)O(n2) to 𝑂(𝑛log2⁡𝑛)O(nlog2⁡n).

    For example, given a sequence where each element has two attributes 𝑎a and 𝑏b, suppose we want to compute a DP value with the following transition:

    𝑑𝑝𝑖 =1 +max𝑖−1𝑗=1𝑑𝑝𝑗[𝑎𝑗 <𝑎𝑖][𝑏𝑗 <𝑏𝑖]dpi=1+maxj=1i−1dpj[aj<ai][bj<bi]

    This is the DP equation for a two-dimensional longest increasing subsequence: only points 𝑗j satisfying 𝑗 <𝑖,𝑎𝑗 <𝑎𝑖,𝑏𝑗 <𝑏𝑖j<i,aj<ai,bj<bi can update the DP value of point 𝑖i.

    Direct transition is clearly 𝑂(𝑛2)O(n2). The following explains how to optimize the transition process using CDQ divide and conquer.

    We observe that the transition relation from 𝑑𝑝𝑗dpj to 𝑑𝑝𝑖dpi is also a relation between pairs of points, so we handle it similarly to how CDQ divide and conquer handles pair relations.

    This transition process is relatively standard. Suppose the interval currently being processed is (𝑙,𝑟)(l,r). The algorithm is roughly as follows:

    1. If 𝑙 =𝑟l=r, the maxmax part of 𝑑𝑝𝑟dpr has already been computed. Directly set 𝑑𝑝𝑟 ←𝑑𝑝𝑟 +1dpr←dpr+1 and return;
    2. Recursively call solve(l,mid);
    3. Process all transition relations with 𝑙 ≤𝑗 ≤𝑚𝑖𝑑l≤j≤mid and 𝑚𝑖𝑑 +1 ≤𝑖 ≤𝑟mid+1≤i≤r;
    4. Recursively call solve(mid+1,r).

    Step 3 is similar to using CDQ divide and conquer for three-dimensional partial order. When processing transitions with 𝑙 ≤𝑗 ≤𝑚𝑖𝑑l≤j≤mid and 𝑚𝑖𝑑 +1 ≤𝑖 ≤𝑟mid+1≤i≤r, the constraint 𝑗 <𝑖j<i no longer needs to be considered. Therefore, we still first sort all points 𝑖i and 𝑗j by their 𝑎a values, then insert points 𝑗j into a Fenwick tree using two pointers, and finally query the prefix maximum to update 𝑑𝑝𝑖dpi.

    Correctness Proof of the Transition Process

    The biggest difference between this CDQ implementation and the CDQ implementation for relations between pairs of points is the part that processes pairs with 𝑙 ≤𝑗 ≤𝑚𝑖𝑑l≤j≤mid and 𝑚𝑖𝑑 +1 ≤𝑖 ≤𝑟mid+1≤i≤r. In the CDQ implementation for point-pair relations, this part can be placed anywhere. However, when using CDQ divide and conquer to optimize DP, this process must be placed between 𝑠𝑜𝑙𝑣𝑒(𝑙,𝑚𝑖𝑑)solve(l,mid) and 𝑠𝑜𝑙𝑣𝑒(𝑚𝑖𝑑 +1,𝑟)solve(mid+1,r). The reason is that DP transitions are ordered and must satisfy two conditions; otherwise they are incorrect:

    1. All 𝑑𝑝𝑗dpj values used to compute 𝑑𝑝𝑖dpi must already be fully computed; no "semi-finished products" may exist;

    2. All 𝑑𝑝𝑗dpj values used to compute 𝑑𝑝𝑖dpi must be able to update 𝑑𝑝𝑖dpi; no such 𝑑𝑝𝑗dpj value may be missed.

    These two conditions are fairly easy to satisfy in the 𝑂(𝑛2)O(n2) brute-force method. After using CDQ divide and conquer, however, the transition order is clearly disrupted, so it is necessary to examine correctness.

Thus, we process all DP values in order; only the transition order has been split apart. Therefore, the algorithm is correct.

    Transforming Dynamic Problems into Static Problems

    In the first two cases, CDQ divide and conquer is used to halve a sequence and recursively process relations between pairs of points to obtain good complexity. In this section, however, the sequence being halved is not an ordinary sequence, but a time sequence.

    It applies to some data structure problems that need to support "perform xxx modification and then answer xxx query". This type of problem has two characteristics:

    • If the queries are processed offline, all operations naturally form a sequence ordered by time.
    • Each modification is closely related to later query operations. There may be 𝑂(𝑛2)O(n2) such "modification-query" relations.

    We can use CDQ divide and conquer on this operation sequence to process the relations between modifications and queries.

    Similar to CDQ divide and conquer for point-pair relations, suppose the sequence currently being divided is (𝑙,𝑟)(l,r). We first recursively process the modification-query relations in (𝑙,𝑚𝑖𝑑)(l,mid) and (𝑚𝑖𝑑,𝑟)(mid,r), then process all modification-query relations with 𝑙 ≤𝑖 ≤𝑚𝑖𝑑l≤i≤mid and 𝑚𝑖𝑑 +1 ≤𝑗 ≤𝑟mid+1≤j≤r, where 𝑖i is a modification and 𝑗j is a query.

    Note that if the modifications are independent of one another, we do not need to handle the temporal relation between 𝑙 ≤𝑖 ≤𝑚𝑖𝑑l≤i≤mid and 𝑚𝑖𝑑 +1 ≤𝑗 ≤𝑟mid+1≤j≤r, or between solve(l,mid) and solve(mid+1,r) (for example, ordinary addition and subtraction problems). But if modifications are not independent (such as assignment operations), the state of the sequence after a modification may depend on the previous sequence. In that case, the step that processes all modification-query relations crossing mid must be placed between solve(l,mid) and solve(mid+1,r). The reason is the same as for optimizing 1D/1D dynamic programming with CDQ divide and conquer: dividing in in-order traversal order ensures that every modification is executed strictly in chronological order.

    Rectangle Add, Rectangle Sum

    Maintain a two-dimensional array, supporting adding a number to a rectangular region and querying the sum of a rectangular region.

    Solution

    For the version of this problem without modifications, namely "given a two-dimensional array, answer multiple queries for the sum of a rectangular region", there is a classic approach using a scanline with a segment tree. Specifically, first split each rectangle into an insertion and a deletion operation, then split each query into differences of two-dimensional prefix sums, and finally process offline. However, the original problem has modifications, so this approach cannot be used directly.

    Try applying CDQ divide and conquer. We process all queries and modifications offline. These operations form a sequence, with 𝑂(𝑁2)O(N2) modification-query relations. Following the general CDQ divide and conquer process, divide all relations into three categories. At this divide-and-conquer level, only process modification-query relations crossing 𝑚𝑖𝑑mid; the remaining relations are handled recursively.

    We find that all modifications have already been completed before the queries. At this point, the original problem is equivalent to: "there are some static rectangles on a plane, and we repeatedly query the sum of a rectangular region".

    Use a scanline to process all modification-query relations crossing 𝑚𝑖𝑑mid in 𝑂(𝑛log⁡𝑛)O(nlog⁡n) time. The remaining work is to recursively divide and conquer the modification-query relations on the left and right sides.

    In this CDQ divide and conquer implementation, the same query is processed 𝑂(log⁡𝑛)O(log⁡n) times. This is fine, because the modifications contributing to this query each time are disjoint. The overall time complexity is 𝑇(𝑛) =𝑇(⌊𝑛2⌋) +𝑇(⌈𝑛2⌉) +𝑂(𝑛log⁡𝑛) =𝑂(𝑛log2⁡𝑛)T(n)=T(⌊n2⌋)+T(⌈n2⌉)+O(nlog⁡n)=O(nlog2⁡n).

    Observing the above algorithm, we see that at first we could only solve the static rectangle-add rectangle-sum problem, but after simply using CDQ divide and conquer, we can solve a dynamic rectangle-add rectangle-sum problem offline. The essence of transforming dynamic problems into static problems is that CDQ divide and conquer only processes modification-query relations crossing a certain point each time. Thus, we only need to consider the simple problem where "all queries occur after all modifications". This is why CDQ divide and conquer is called a "tool for transforming dynamic problems into static problems".

struct data {
  int l;
  int r;
  int x;

  friend bool operator<(data a, data b) { return a.r < b.r; }
};

  int l;
  int r;

  friend bool operator<(nod a, nod b) { return a.r < b.r; }
};

set<nod> c[2 * N];
set<int> bd;

void split(int mid) {  // 将一个节点拆成两个节点
  SDI it = s.lower_bound(data{0, mid, 0});
  data p = *it;
  if (mid == p.r) return;
  s.erase(p);
  s.insert(data{p.l, mid, p.x});
  s.insert(data{mid + 1, p.r, p.x});
  c[p.x].erase(nod{p.l, p.r});
  c[p.x].insert(nod{p.l, mid});
  c[p.x].insert(nod{mid + 1, p.r});
}

void del(set<data>::iterator it) {  // 删除一个迭代器
  bd.insert(it->l);
  SNI it1, it2;
  it1 = it2 = c[it->x].find(nod{it->l, it->r});
  ++it2;
  if (it2 != c[it->x].end()) bd.insert(it2->l);
  c[it->x].erase(it1);
  s.erase(it);
}

void ins(data p) {  // 插入一个节点
  s.insert(p);
  SNI it = c[p.x].insert(nod{p.l, p.r}).first;
  ++it;
  if (it != c[p.x].end()) {
    bd.insert(it->l);
  }
}

void stv(int l, int r, int x) {  // 区间赋值
  if (l != 1) split(l - 1);
  split(r);
  int p = l;  // split两下之后删掉所有区间
  while (p != r + 1) {
    SDI it = s.lower_bound(data{0, p, 0});
    p = it->r + 1;
    del(it);
  }
  ins(data{l, r, x});  // 扫一遍set处理所有变化的pre值
  for (set<int>::iterator it = bd.begin(); it != bd.end(); ++it) {
    SDI it1 = s.lower_bound(data{0, *it, 0});
    if (*it != it1->l)
      modify(*it, *it - 1);
    else {
      SNI it2 = c[it1->x].lower_bound(nod{0, *it});
      if (it2 != c[it1->x].begin())
        --it2, modify(*it, it2->r);
      else
        modify(*it, 0);
    }
  }
  bd.clear();
}

void ih() {

  int ccnt = 1;  // 将连续的一段插入到set中
  for (int i = 2; i <= n; i++)
    if (nc != a[i]) {
      s.insert(data{i - ccnt, i - 1, nc}), c[nc].insert(nod{i - ccnt, i - 1});
      nc = a[i];
      ccnt = 1;
    } else {
      ccnt++;
    }
  s.insert(data{n - ccnt + 1, n, a[n]}), c[a[n]].insert(nod{n - ccnt + 1, n});
}

struct treearray  // 树状数组
{
  int ta[N];

  void c(int x, int t) {
    for (; x <= n; x += x & (-x)) ta[x] += t;
  }

  void d(int x) {
    for (; x <= n; x += x & (-x)) ta[x] = 0;
  }

  int q(int x) {
    int r = 0;
    for (; x; x -= x & (-x)) r += ta[x];
    return r;
  }

  void clear() {
    for (int i = 1; i <= n; i++) ta[i] = 0;
  }
} ta;

int srt[N];

bool cmp1(const int& a, const int& b) { return pre[a] < pre[b]; }

void solve(int l1, int r1, int l2, int r2, int L, int R) {  // CDQ
  if (l1 == r1 || l2 == r2) return;
  int mid = (L + R) / 2;
  int mid1 = l1;
  while (mid1 != r1 && md[mid1 + 1].t <= mid) mid1++;
  int mid2 = l2;
  while (mid2 != r2 && qr[mid2 + 1].t <= mid) mid2++;
  solve(l1, mid1, l2, mid2, L, mid);
  solve(mid1, r1, mid2, r2, mid, R);
  if (l1 != mid1 && mid2 != r2) {
    sort(md + l1 + 1, md + mid1 + 1);
    sort(qr + mid2 + 1, qr + r2 + 1);
    for (int i = mid2 + 1, j = l1 + 1; i <= r2; i++) {  // 考虑左侧对右侧贡献
      while (j <= mid1 && md[j].pre < qr[i].l) ta.c(md[j].pos, md[j].va), j++;
      qr[i].ans += ta.q(qr[i].r) - ta.q(qr[i].l - 1);
    }
    for (int i = l1 + 1; i <= mid1; i++) ta.d(md[i].pos);
  }
}

    The country PS is a large country with many cities. King Louis has put great effort into urban transportation construction. Louis can build roads between some cities, and building roads between different cities has different costs.

    Louis wants to build the fewest roads needed to connect all cities in the country. However, due to certain factors, the cost of building roads between cities changes over time. Louis continuously receives news that the construction cost of some road has changed. After each message, he wants to immediately know the minimum total cost required to connect all cities. Louis asks you to complete this task.

    In one sentence: given a graph with dynamic edge-weight modifications, output the minimum total cost of the graph's minimum spanning tree after each edge-weight modification.

    Solution

    In fact, this problem can be solved by segment tree divide and conquer with LCT, but the constant factor of that implementation is too large and may require delicate constant optimization to pass. Therefore, consider using CDQ divide and conquer.

    Unlike ordinary problems solved by CDQ divide and conquer, here there is no modification-query relation for CDQ to divide on, because we cannot separately consider "what contribution modifying one edge makes to the minimum spanning tree of the whole graph". The traditional CDQ divide and conquer idea does not seem very effective.

    From the previous examples, we can see that ordinary CDQ divide and conquer has a special connection with segment trees: during CDQ divide and conquer, we implicitly build a segment tree (because the recursion tree of CDQ divide and conquer is a segment tree). Usual CDQ considers the relation between the left and right children of the segment tree. For this problem, however, we need to consider the relation between a parent and its child. In other words, when we are at the interval $solve(l,r)$, if we can find a way to make the graph size become a variable related to the interval length, we can solve this problem.

    How should the algorithm be designed in detail?

    Suppose we are constructing the edge set of the minimum spanning tree for interval (𝑙,𝑟)(l,r), and we already know the edge set of its parent's minimum spanning tree. For the edges that change in interval (𝑙,𝑟)(l,r), assign their weights to +∞+∞ and −∞−∞ respectively, run Kruskal once for each case, and find the edges that appear in the minimum spanning tree.

    For an edge:

    • If all modified edge weights in the minimum spanning tree are assigned +∞+∞, and this edge does not appear in the tree, then it cannot appear in the minimum spanning tree for the queries in (𝑙,𝑟)(l,r). Therefore, we only add the tree edges of the minimum spanning tree to the edge set of (𝑙,𝑟)(l,r).
    • If all modified edge weights in the minimum spanning tree are assigned −∞−∞, and this edge appears in the tree, then it must appear in the minimum spanning tree for interval (𝑙,𝑟)(l,r). In that case, we can use DSU to contract the endpoints of these edges and add their weights to the answer.

    In this way, we construct the edge set for interval (𝑙,𝑟)(l,r). The minimum spanning tree computed using these edges is equivalent to directly computing the minimum spanning tree of the original graph.

    Why is the complexity correct?

    First, modified edges are always added to our edge set, and the number of such edges is 𝑂(𝑙𝑒𝑛)O(len).

    Next, we need to prove that there are not too many unmodified edges in the edge set. We only add tree edges from the minimum spanning tree when all modified edge weights are set to +∞+∞, so the number of edges we add will not exceed the number of vertices in the current graph.

    Now we only need to prove that the number of vertices in the graph at each recursive level is 𝑂(𝑙𝑒𝑛)O(len), which implies that the number of edges in the graph is also 𝑂(𝑙𝑒𝑛)O(len).

    Proving that the number of vertices is a constant multiple of 𝑂(𝑙𝑒𝑛)O(len) is then simple. Each time we recurse downward, the contracted edges are unmodified edges that appear in the −∞−∞ spanning tree. Conversely, we have cut all modified edges that appear in the −∞−∞ spanning tree. Clearly, we cut at most 𝑙𝑒𝑛len edges, so the whole graph splits into at most 𝑂(𝑙𝑒𝑛)O(len) connected components, and the number of vertices in the new graph is 𝑂(𝑙𝑒𝑛)O(len). Thus, we have proved that every graph on which we run Kruskal is of size 𝑂(𝑙𝑒𝑛)O(len), so the time complexity of each level is 𝑂(𝑛log⁡𝑛)O(nlog⁡n).

    The time complexity is 𝑇(𝑛) =𝑇(⌊𝑛2⌋) +𝑇(⌈𝑛2⌉) +𝑂(𝑛log⁡𝑛) =𝑂(𝑛log2⁡𝑛)T(n)=T(⌊n2⌋)+T(⌈n2⌉)+O(nlog⁡n)=O(nlog2⁡n).

    The code implementation may be somewhat difficult. Note that DSU cannot use path compression, otherwise rollback is not supported. When performing contractions, it is also unnecessary to actually contract vertices; each level's Kruskal can be run directly on the DSU of the previous level.

struct bcj {
  int fa[20010];
  int size[20010];

  struct opt {
    int u;
    int v;
  };

  stack<opt> st;

  void ih() {
    for (int i = 1; i <= n; i++) fa[i] = i, size[i] = 1;
  }

  int f(int x) { return (fa[x] == x) ? x : f(fa[x]); }

  void u(int x, int y) {  // 带撤回
    int u = f(x);
    int v = f(y);
    if (u == v) return;
    if (size[u] < size[v]) swap(u, v);
    size[u] += size[v];
    fa[v] = u;
    opt o;
    o.u = u;
    o.v = v;
    st.push(o);
  }

  void undo() {
    opt o = st.top();
    st.pop();
    fa[o.v] = o.v;
    size[o.u] -= size[o.v];
  }

  void clear(int tim) {
    while (st.size() > tim) {
      undo();
    }
  }
} s, s1;

    tr.push_back(ve[dep][i]);
  }
  sort(tr.begin(), tr.end());
  for (int i = 0; i < tr.size(); i++) {  // 无用边
    if (s1.f(tr[i].u) == s1.f(tr[i].v)) {
      tr[i].mrk = -1;
      continue;
    }
    s1.u(tr[i].u, tr[i].v);
  }
