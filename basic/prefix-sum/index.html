    Prefix Sum and Difference Array

    Introduction

    Prefix sum and difference are commonly used techniques in programming contests. The former is used for quickly computing range sums, and the latter is used for efficiently performing range updates.

    Convention

    For convenience, this article assumes that the array {𝑎𝑖}{ai} is 1-indexed, and we define 𝑎0 =0a0=0.

    Prefix Sum

    A prefix sum can be simply understood as "the sum of the first 𝑛n elements of a sequence," and it is an important preprocessing technique.

    One-Dimensional Prefix Sum

    For a sequence {𝑎𝑖}{ai} of length 𝑛n, if you need to query the sum of elements in the range [𝑙,𝑟][l,r] multiple times, you can consider using a prefix sum. The prefix sum of a sequence is defined as

    𝑆𝑖=𝑖∑𝑗=1𝑎𝑗.Si=∑j=1iaj.

    It can be computed iteratively using the recurrence

    𝑆0=0, 𝑆𝑖=𝑆𝑖−1+𝑎𝑖.S0=0, Si=Si−1+ai.

    To query the sum of elements in range [𝑙,𝑟][l,r], you only need to compute the difference

    𝑆([𝑙,𝑟])=𝑆𝑟−𝑆𝑙−1.S([l,r])=Sr−Sl−1.

    Thus, with 𝑂(𝑛)O(n) preprocessing, a single range sum query can be reduced to 𝑂(1)O(1) time.

    C++ standard library provides the prefix sum function std::partial_sum, defined in the header <numeric>. Since C++17, the standard library also provides std::inclusive_scan, which offers the same functionality, also defined in the header <numeric>.

    Two-Dimensional / Multi-Dimensional Prefix Sum

    Extending one-dimensional prefix sum to multiple dimensions gives us multi-dimensional prefix sums. There are two common methods for computing multi-dimensional prefix sums.

    Based on Inclusion-Exclusion Principle

    This method is commonly used for two-dimensional prefix sums. Given a 2D array 𝐴A of size 𝑚 ×𝑛m×n, we want to compute its prefix sum 𝑆S. Then 𝑆S is also a 2D array of size 𝑚 ×𝑛m×n, and

    𝑆𝑖,𝑗=∑𝑖′≤𝑖∑𝑗′≤𝑗𝐴𝑖′,𝑗′.Si,j=∑i′≤i∑j′≤jAi′,j′.

    Analogous to the one-dimensional case, 𝑆𝑖,𝑗Si,j should be computable from 𝑆𝑖−1,𝑗Si−1,j or 𝑆𝑖,𝑗−1Si,j−1 to avoid redundant computation of previous sums. However, directly adding 𝑆𝑖−1,𝑗Si−1,j and 𝑆𝑖,𝑗−1Si,j−1, along with 𝐴𝑖,𝑗Ai,j, would double-count the overlapping portion 𝑆𝑖−1,𝑗−1Si−1,j−1, so this portion needs to be subtracted. This is the inclusion-exclusion principle. From this, we get the following recurrence:

    𝑆𝑖,𝑗=𝐴𝑖,𝑗+𝑆𝑖−1,𝑗+𝑆𝑖,𝑗−1−𝑆𝑖−1,𝑗−1.Si,j=Ai,j+Si−1,j+Si,j−1−Si−1,j−1.

    In implementation, simply iterate over all (𝑖,𝑗)(i,j) pairs to compute the sum.

    Example

    Consider a concrete example.

    Here, 𝑆S is the prefix sum of matrix 𝐴A. By definition, 𝑆3,3S3,3 is the sum of the submatrix in the dashed box in the left figure. Also, 𝑆3,2S3,2 is the sum of the blue submatrix, and 𝑆2,3S2,3 is the sum of the red submatrix. Their overlapping portion has sum 𝑆2,2S2,2. Thus, if we directly add 𝑆3,2S3,2 and 𝑆2,3S2,3, we would double-count 𝑆2,2S2,2, so we should have

    𝑆3,3=𝐴3,3+𝑆2,3+𝑆3,2−𝑆2,2=5+18+15−9=29.S3,3=A3,3+S2,3+S3,2−S2,2=5+18+15−9=29.

    Similarly, after preprocessing the 2D prefix sum, to query the sum of a submatrix with top-left corner (𝑖1,𝑗1)(i1,j1) and bottom-right corner (𝑖2,𝑗2)(i2,j2), we can compute

    𝑆𝑖2,𝑗2−𝑆𝑖1−1,𝑗2−𝑆𝑖2,𝑗1−1+𝑆𝑖1−1,𝑗1−1.Si2,j2−Si1−1,j2−Si2,j1−1+Si1−1,j1−1.

    This can be done in 𝑂(1)O(1) time.

    In the 2D case, the time complexity of the above algorithm is simply 𝑂(𝑚𝑛)O(mn), which is linear in the size of the given array. However, when the dimension 𝑘k increases, the number of terms in the inclusion-exclusion principle grows exponentially, and the time complexity becomes 𝑂(2𝑘𝑁)O(2kN), where 𝑘k is the number of dimensions and 𝑁N is the size of the given array. Therefore, this algorithm is no longer applicable.

#include <iostream>
#include <vector>

int n, m;
std::vector<std::vector<int>> a, ps;  // (n + 1) x (m + 1).

// Calculate the prefix sum of 2-d array.
void prefix_sum() {
  ps = a;
  for (int i = 1; i <= n; ++i)
    for (int j = 1; j <= m; ++j)
      ps[i][j] += ps[i - 1][j] + ps[i][j - 1] - ps[i - 1][j - 1];
}

// Find the sum of elements in submatrix [x1, y1] to [x2, y2].
int query(int x1, int y1, int x2, int y2) {
  return ps[x2][y2] - ps[x1 - 1][y2] - ps[x2][y1 - 1] + ps[x1 - 1][y1 - 1];
}

int main() {
  std::cin >> n >> m;
  a.assign(n + 1, std::vector<int>(m + 1));

  for (int i = 1; i <= n; i++)
    for (int j = 1; j <= m; j++) std::cin >> a[i][j];

  prefix_sum();

  int ans = 0;
  for (int l = 1; l <= std::min(n, m); ++l)
    for (int i = l; i <= n; i++)
      for (int j = l; j <= m; j++)
        if (query(i - l + 1, j - l + 1, i, j) == l * l) ans = std::max(ans, l);

  std::cout << ans << std::endl;
  return 0;
}

    Dimension-by-Dimension Prefix Sum

    For the general case, given a 𝑘k-dimensional array 𝐴A of size 𝑁N, we also want to compute its prefix sum 𝑆S. Here,

    𝑆𝑖1,⋯,𝑖𝑘=∑𝑖′1≤𝑖1⋯∑𝑖′𝑘≤𝑖𝑘𝐴𝑖′1,⋯,𝑖′𝑘.Si1,⋯,ik=∑i1′≤i1⋯∑ik′≤ikAi1′,⋯,ik′.

    From the above formula, we can see that a 𝑘k-dimensional prefix sum equals 𝑘k successive summations. Therefore, a straightforward algorithm is: each time consider only one dimension, fix all other dimensions, and compute several one-dimensional prefix sums. After summing over all 𝑘k dimensions, we get the 𝑘k-dimensional prefix sum.

    int N1, N2, N3;
std::vector<std::vector<std::vector<int>>> a,
    ps;  // (N1 + 1) x (N2 + 1) x (N3 + 1).

// Calculate prefix sum of 3d array.
void prefix_sum() {
  ps = a;

  // Prefix-sum for 3rd dimension.
  for (int i = 1; i <= N1; ++i)
    for (int j = 1; j <= N2; ++j)
      for (int k = 1; k <= N3; ++k) ps[i][j][k] += ps[i][j][k - 1];

  // Prefix-sum for 2nd dimension.
  for (int i = 1; i <= N1; ++i)
    for (int j = 1; j <= N2; ++j)
      for (int k = 1; k <= N3; ++k) ps[i][j][k] += ps[i][j - 1][k];

  // Prefix-sum for 1st dimension.
  for (int i = 1; i <= N1; ++i)
    for (int j = 1; j <= N2; ++j)
      for (int k = 1; k <= N3; ++k) ps[i][j][k] += ps[i - 1][j][k];
}

    Since each dimension only requires a single pass through the entire array, the algorithm has a time complexity of 𝑂(𝑘𝑁)O(kN), which is usually acceptable.

    Special Case: Subset Sum DP

    Cases with large dimensions frequently appear in a class of problems called Subset Sum (SOS). This is a special case of high-dimensional prefix sum.

    The problem description is as follows. Consider a function 𝑓f defined on all subsets of a set of size 𝑛n. We want to compute its subset sum function 𝑔g, which satisfies

    𝑔(𝑆)=∑𝑇⊆𝑆𝑓(𝑇).g(S)=∑T⊆Sf(T).

    That is, 𝑔(𝑆)g(S) equals the sum of 𝑓(𝑇)f(T) over all subsets 𝑇 ⊆𝑆T⊆S.

    First, the subset sum problem can be expressed in the form of high-dimensional prefix sum. Note that subsets of 𝑆S can be represented as 0-1 strings of length 𝑛n using state compression. If we treat each bit of the string as a dimension of the array index, then 𝑓f is actually an 𝑛n-dimensional array, and each dimension's index must be in {0,1}{0,1}. Also, the subset relation is equivalent to the index comparison relation, that is,

    𝑇⊆𝑆⟺∀𝑖(𝑡𝑖≤𝑠𝑖).T⊆S⟺∀i(ti≤si).

    Therefore, summing over subsets is equivalent to computing the prefix sum of this 𝑛n-dimensional array.

    Now, we can directly use the dimension-by-dimension prefix sum method described earlier to compute the subset sum. The time complexity is 𝑂(𝑛2𝑛)O(n2n).

    The inverse operation of subset sum needs to be performed using the inclusion-exclusion principle. The subset sum problem is also a necessary step in fast Möbius transform.

    Prefix Sum on Trees

    One-dimensional prefix sum can also be extended to rooted trees (with root at 11). By preprocessing prefix sums, we can quickly compute the sum of weights along a path on the tree.

    Node Weights

    First, we discuss the case where weights are stored at nodes. Let the weight at node 𝑥x be 𝑎𝑥ax. We can compute the sum of node weights on the path from the root to node 𝑥x using the recurrence

    𝑆1=𝑎1, 𝑆𝑥=𝑆fa⁡(𝑥)+𝑎𝑥S1=a1, Sx=Sfa⁡(x)+ax

    where fa⁡(𝑥)fa⁡(x) denotes the parent of 𝑥x. After preprocessing the prefix sum, the sum of node weights on the path connecting node 𝑥x and 𝑦y can be computed as

    𝑆𝑥+𝑆𝑦−𝑆lca⁡(𝑥,𝑦)−𝑆fa⁡(lca⁡(𝑥,𝑦))Sx+Sy−Slca⁡(x,y)−Sfa⁡(lca⁡(x,y))

    where lca⁡(𝑥,𝑦)lca⁡(x,y) denotes the lowest common ancestor of nodes 𝑥x and 𝑦y.

    Edge Weights

    The case where weights are stored on edges can be almost transformed into the node weight case. For all non-root nodes 𝑥 ≠1x≠1, let edge⁡(𝑥)edge⁡(x) denote the edge connecting node 𝑥x and its parent fa⁡(𝑥)fa⁡(x). Then we can assume that the edge weight is stored at the node farther from the root. That is, node 𝑥x stores the weight of edge edge⁡(𝑥)edge⁡(x). The root node stores a weight of 00. Then, using the recurrence discussed in the previous section, we can also preprocess 𝑆𝑥Sx, the sum of edge weights on the path from the root to node 𝑥x.

    At this point, the sum of node weights on the path connecting node 𝑥x and 𝑦y can be queried by

    𝑆𝑥+𝑆𝑦−2𝑆lca⁡(𝑥,𝑦).Sx+Sy−2Slca⁡(x,y).

    Note that, unlike the node weight case, the queried weight sum does not include the weight at lca⁡(𝑥,𝑦)lca⁡(x,y), because the edge weight stored there is not on the path being queried.

    Subtree Sum

    Unlike the array case, because the tree is not symmetric front and back, computing "prefix sum" bottom-up (from leaves to root) and top-down (from root to leaves) yields different results. In general, "prefix sum on trees" refers to the top-down computed prefix sum. For convenience, we call the bottom-up computed "prefix sum" subtree sum in this article.

    The sum of node weights in the subtree rooted at node 𝑥x, i.e., the corresponding subtree sum, is

    𝑇𝑥=∑𝑦∈desc⁡(𝑥)𝑎𝑥.Tx=∑y∈desc⁡(x)ax.

    where desc⁡(𝑥)desc⁡(x) denotes the set of all descendants of 𝑥x (including 𝑥x itself).

    Unlike prefix sum on trees, subtree sum cannot be applied to 𝑂(1)O(1) path weight sum queries, but it can be used to understand tree difference in the following section.

    Difference

    Difference is a strategy opposite to prefix sum, being the inverse operation of prefix sum. Rather than computing the difference of a given sequence, a more common scenario in contests is to maintain information about the difference sequence to perform multiple range updates. After all range updates are completed, the original sequence information can be restored through prefix sum to perform queries on the original sequence. Note that update operations must come before query operations.

    If you need to support mixed operations of multiple updates and queries, you need to use a Fenwick tree (Binary Indexed Tree), but their underlying ideas are shared.

    One-Dimensional Difference

    For a sequence {𝑎𝑖}{ai}, its difference sequence {𝐷𝑖}{Di} is defined as

    𝐷𝑖=𝑎𝑖−𝑎𝑖−1, 𝑎0=0.Di=ai−ai−1, a0=0.

    C++ standard library provides the difference function std::adjacent_difference, defined in the header <numeric>.

    The relationship between prefix sum and difference is as follows:

    Properties

    Let {𝐷𝑖}{Di} be the difference sequence of {𝑎𝑖}{ai}. Then we have

    • The sequence {𝑎𝑖}{ai} is the prefix sum of the sequence {𝐷𝑖}{Di}, that is

      𝑎𝑖=𝑖∑𝑗=1𝐷𝑗.ai=∑j=1iDj.

    • The prefix sum of the sequence {𝑎𝑖}{ai} is

      𝑆𝑖=𝑖∑𝑗=1𝑗∑𝑘=1𝐷𝑘=𝑖∑𝑗=1(𝑖−𝑗+1)𝐷𝑗.Si=∑j=1i∑k=1jDk=∑j=1i(i−j+1)Dj.

    Difference information is often used to maintain multiple operations of adding a constant to a range of a sequence, followed by one or more queries for the value at a specific position.

    Suppose we want to add 𝑣v to every element in the range [𝑙,𝑟][l,r] of the sequence {𝑎𝑖}{ai}. We can perform the following operation on its difference sequence {𝐷𝑖}{Di}:

    𝐷𝑙←𝐷𝑙+𝑣, 𝐷𝑟+1←𝐷𝑟+1−𝑣.Dl←Dl+v, Dr+1←Dr+1−v.

    After all update operations are completed, the updated values of {𝑎𝑖}{ai} can be restored by a prefix sum operation. A single update is 𝑂(1)O(1). For queries, a one-time 𝑂(𝑛)O(n) prefix sum operation is needed, after which each query is 𝑂(1)O(1).

    Two-Dimensional / Multi-Dimensional Difference

    Difference can also be extended to multiple dimensions. Treating multi-dimensional difference as the inverse operation of multi-dimensional prefix sum, then computing the original array from the multi-dimensional prefix sum can be done using the inclusion-exclusion principle. For example, the definition of 2D difference is

    𝐷𝑖,𝑗=𝑎𝑖,𝑗−𝑎𝑖−1,𝑗−𝑎𝑖,𝑗−1+𝑎𝑖−1,𝑗−1.Di,j=ai,j−ai−1,j−ai,j−1+ai−1,j−1.

    However, if you want to compute the entire difference array, a simpler and more efficient approach is dimension-by-dimension difference, i.e., enumerate all dimensions and compute the difference along each dimension.

    2D difference information is often used to maintain multiple rectangle additions on a 2D array. For example, to add 𝑣v to every element in the matrix with top-left corner (𝑥1,𝑦1)(x1,y1) and bottom-right corner (𝑥2,𝑦2)(x2,y2), you can perform the following operation on its difference array {𝐷𝑖,𝑗}{Di,j}:

    Difference on Trees

    Difference can be extended to rooted trees to implement range addition on tree paths. Depending on whether the maintained information is stored on nodes or edges, tree difference can be divided into node difference and edge difference, which differ slightly in implementation.     Node Difference

    If you want to add 𝑣v to all node weights on the path between node 𝑥x and 𝑦y, you can perform the following operation on its difference sequence {𝐷𝑥}{Dx}:

#include <iostream>
using namespace std;

constexpr int MAXN = 50010;

struct node {
  int to, next;
} edge[MAXN << 1];

int fa[MAXN][30], head[MAXN << 1];
int power[MAXN];
int depth[MAXN], lg[MAXN];
int n, k, ans = 0, tot = 0;

void add(int x, int y) {  // 加边
  edge[++tot].to = y;
  edge[tot].next = head[x];
  head[x] = tot;
}

void dfs(int now, int father) {  // dfs求最大压力
  fa[now][0] = father;
  depth[now] = depth[father] + 1;
  for (int i = 1; i <= lg[depth[now]]; ++i)
    fa[now][i] = fa[fa[now][i - 1]][i - 1];
  for (int i = head[now]; i; i = edge[i].next)
    if (edge[i].to != father) dfs(edge[i].to, now);
}

int lca(int x, int y) {  // 求LCA，最近公共祖先
  if (depth[x] < depth[y]) swap(x, y);
  while (depth[x] > depth[y]) x = fa[x][lg[depth[x] - depth[y]] - 1];
  if (x == y) return x;
  for (int k = lg[depth[x]] - 1; k >= 0; k--) {
    if (fa[x][k] != fa[y][k]) x = fa[x][k], y = fa[y][k];
  }
  return fa[x][0];
}

// 用dfs求最大压力，回溯时将子树的权值加上
void get_ans(int u, int father) {
  for (int i = head[u]; i; i = edge[i].next) {
    int to = edge[i].to;
    if (to == father) continue;
    get_ans(to, u);
    power[u] += power[to];
  }
  ans = max(ans, power[u]);
}

int main() {
  cin.tie(nullptr)->sync_with_stdio(false);
  cin >> n >> k;
  int x, y;
  for (int i = 1; i <= n; i++) {
    lg[i] = lg[i - 1] + (1 << lg[i - 1] == i);
  }
  for (int i = 1; i <= n - 1; i++) {  // 建图
    cin >> x >> y;
    add(x, y);
    add(y, x);
  }
  dfs(1, 0);
  int s, t;
  for (int i = 1; i <= k; i++) {
    cin >> s >> t;
    int ancestor = lca(s, t);
    // 树上差分
    power[s]++;
    power[t]++;
    power[ancestor]--;
    power[fa[ancestor][0]]--;
  }
  get_ans(1, 0);
  cout << ans << '\n';
  return 0;
}
