    Bit Operations

    Bit operations refer to unary and binary operations on the binary representation of integers, divided into bitwise operations and shifts. Bit operations are among the most fundamental operations in the CPU and are usually quite fast.

    Integers and Bit Sequences

    See also: Integer types, Two's complement

    We call a fixed-length sequence consisting only of 0 or 1 a bit sequence. The leftmost bit is called the most significant bit, and the rightmost bit is called the least significant bit.

    Computers use bit sequences to represent integers within a certain range. A bit sequence of length 𝑁N has only 2𝑁2N different states, so it can only establish a one-to-one correspondence with 2𝑁2N integers. This one-to-one correspondence can be divided into two types: signed and unsigned. Signed means the corresponding integers include negative numbers; unsigned means the corresponding integers are all non-negative.

    • For the unsigned correspondence, we can directly use the binary representation of the integer as the bit sequence, padding with 0 at the high bits if needed.

      Under the unsigned correspondence, a bit sequence of length 𝑁N can represent integers in [0,2𝑁 −1][0,2N−1].

    • For the signed correspondence, we have two representation rules: ones' complement and two's complement.

      For non-negative integers, the representation rule is the same as the unsigned rule; for negative integers, we take the bit sequence of its opposite number, bitwise negate it (changing 0 to 1 and 1 to 0) to get the ones' complement, then convert the ones' complement to an integer according to the unsigned correspondence, add one, then convert to a bit sequence according to the unsigned correspondence, discarding any overflow beyond the original bit sequence length. The resulting new sequence is called two's complement.

      Under the ones' complement correspondence, a bit sequence of length 𝑁N can represent integers in [ −2𝑁−1 +1,2𝑁−1 −1][−2N−1+1,2N−1−1].

      Under the two's complement correspondence, a bit sequence of length 𝑁N can represent integers in [ −2𝑁−1,2𝑁−1 −1][−2N−1,2N−1−1].

    Using 3-bit sequences as an example:

    Bit sequenceUnsigned integerSigned integer (ones' complement)Signed integer (two's complement)
    000000000
    001111111
    010222222
    011333333
    10044−3−3−4−4
    10155−2−2−3−3
    11066−1−1−2−2
    11177−0−0−1−1

    We can see that the main problem with ones' complement is the existence of −0−0, which is actually a non-existent "negative number," so we generally only use two's complement. Since when representing signed integers, the sign is determined solely by the most significant bit of the bit sequence, we call this bit the sign bit.

    Converting a bit sequence to an integer is also straightforward: for non-negative numbers, no special operation is needed; for ones' complement, negating gives the opposite number; for two's complement, negating and adding one gives the opposite number.

    Bitwise Operations

    Bitwise operations are operations that apply certain Boolean functions bit by bit to bit sequences. Formally, for a Boolean function 𝑓 :𝐁𝑘 →𝐁f:Bk→B, a bitwise operation is a function of the form

    𝐹:(𝐁𝑚)𝑘→𝐁𝑚((𝑝1,1,…,𝑝𝑚,1),…,(𝑝1,𝑘,…,𝑝𝑚,𝑘))↦(𝑓(𝑝1,1,…,𝑝1,𝑘),…,𝑓(𝑝𝑚,1,…,𝑝𝑚,𝑘))F:(Bm)k→Bm((p1,1,…,pm,1),…,(p1,k,…,pm,k))↦(f(p1,1,…,p1,k),…,f(pm,1,…,pm,k))

    where 𝑚m is the length of the bit sequence. Similarly, we generally only study unary and binary bitwise operations. Unless otherwise specified, the following discussion of bitwise operations is limited to unary and binary cases.

    Generally, we consider bitwise NOT, bitwise AND, bitwise OR, and bitwise XOR as basic bitwise operations. All other bitwise operations can be composed from these.

    Shifts

    See also: C++ bitwise operators.

    Shift is a type of binary operation that moves a bit sequence "bit by bit to the left or right." The first argument is the bit sequence, and the second argument is generally a non-negative integer. Moving left is called left shift, and moving right is called right shift. Based on how the vacated bits are filled, shift operations can be divided into arithmetic shift, logical shift, and circular shift. Among these:

    • Logical shift fills vacated bits with 0.
    • Arithmetic right shift fills vacated bits with the sign bit; arithmetic left shift is the same as logical left shift.
    • Circular shift fills vacated bits with the overflow bits.

    For example, for an 8-bit sequence 10 01 01 10:

    OperationResult
    Arithmetic left shift by 201 01 10 00
    Arithmetic right shift by 211 10 01 01
    Logical left shift by 201 01 10 00
    Logical right shift by 200 10 01 01
    Circular left shift by 201 01 10 10
    Circular right shift by 210 10 01 01

    In C++, we use a << b for left shift and a >> b for right shift. For specific shift rules, see C++ bitwise operators.

uint32_t rotl32(uint32_t value, unsigned int count) {
  const unsigned int mask = CHAR_BIT * sizeof(value) - 1;
  count &= mask;
  return (value << count) | (value >> (-count & mask));

uint32_t rotr32(uint32_t value, unsigned int count) {
  const unsigned int mask = CHAR_BIT * sizeof(value) - 1;
  count &= mask;
  return (value >> count) | (value << (-count & mask));
}

    Applications of Bit Operations

    Bit operations generally have three purposes:

    1. Perform certain computations efficiently, replacing other less efficient methods. See Compiler optimizations #Strength reduction.
    2. Represent sets (commonly used in state compression DP).
    3. The problem itself requires bit operations.

    Note that using bit operations to replace other computation methods often does not bring significant optimization, but makes the code more complex. Use with caution.

    Hamming Weight

    Hamming weight is the number of symbols in a string that differ from the zero-symbol (defined on the character set being used). For a binary number, its Hamming weight equals the number of 11s (i.e., popcount).

    To compute the Hamming weight of a number, we can solve it iteratively: we continuously remove the last bit in binary (i.e., right shift by 1), maintain an answer variable, and update the answer based on whether the lowest bit is 11.

    The code is as follows:

    1

int popcount(int x) {
  int cnt = 0;
  while (x) {
    cnt += x & 1;
    x >>= 1;
  }
  return cnt;
}

    Another way to compute the Hamming weight of a number is using the lowbit operation: we continuously subtract its lowbit1 from the number until the number becomes 00.

    The code is as follows:

    Constructing permutations with increasing Hamming weight

    In state compression DP, enumerating in order of increasing popcount can sometimes avoid enumerating duplicate states. This is one major use of constructing permutations with increasing Hamming weight.

    Let's explore how to construct such permutations in 𝑂(𝑛)O(n) time.

    We know that the smallest integer with Hamming weight 𝑛n is 2𝑛 −12n−1. If we can construct a successor with equal Hamming weight in constant time, we can construct the required permutation for 0 ∼𝑛0∼n in 𝑂(𝑛)O(n) time by enumerating Hamming weights, starting from 2𝑛 −12n−1 and continuously finding the next number.

    And finding the successor of a number 𝑥x with equal Hamming weight can be done as follows, using (10110)2(10110)2 as an example:

    • Move the rightmost 11 of (10110)2(10110)2 to the left. If it cannot be moved, move the 11 to its left, and so on, to get (11010)2(11010)2.

    • Then move all the 11s from the position where the last moved 11 originally was to the lowest bit to the rightmost side. Here, the last moved 11 was originally in the third position, so the last three bits 010010 become 001001, yielding (11001)2(11001)2.

    This process can be optimized using bit operations:

    1
2
      int t = x + (x & -x);
  x = t | ((((t & -t) / (x & -x)) >> 1) - 1);

    • In the first step, adding the lowbit to 𝑥x is equivalent to replacing the rightmost consecutive run of 11s in 𝑥x with a 11 to its left. For the binary number (10110)2(10110)2 mentioned earlier, adding its lowbit results in (11000)2(11000)2. This actually gives us the first part of our answer.

    • Next, we need to fill in the remaining 11s in the answer. The lowbit of 𝑡t is the position where the leftmost 11 of the rightmost consecutive run of 11s in 𝑥x moves to, while the lowbit of 𝑥x is the position of the rightmost 11 in that run. Still using (10110)2(10110)2 as an example, 𝑡 =(11000)2t=(11000)2, lowbit⁡(𝑡) =(01000)2lowbit⁡(t)=(01000)2, lowbit⁡(𝑥) =(00010)2lowbit⁡(x)=(00010)2.

    • The division operation in the following part is the most difficult to understand in this bit operation, but also the most critical. Let the original number have its rightmost consecutive run of 11s with the highest 11 at bit position 𝑟r (bit positions start from 0) and the lowest 11 at bit position 𝑙l. The lowbit of 𝑡t equals 1 << (r+1), and the lowbit of 𝑥x equals 1 << l. The result of (((t&-t)/(x&-x))>>1) is (1<<(r+1))/(1<<l)/2 = (1<<r)/(1<<l) = 1<<(r-l), which in binary is 11 followed by 𝑟 −𝑙r−l zeros. The number of zeros exactly equals the number of consecutive 11s minus 11. Taking our earlier number as an example, lowbit⁡(𝑡)/2lowbit⁡(𝑥) =(00100)2(00010)2 =(00010)2lowbit⁡(t)/2lowbit⁡(x)=(00100)2(00010)2=(00010)2. Subtracting 11 from this number gives the low bits we need to fill, and OR-ing with the original number gives the answer.

    Relevant Classes and Functions in C++

    GCC Built-in Functions

    GCC also provides some built-in functions for bit operations:

    • int __builtin_ffs(int x): Returns the position of the last 11 in the binary representation of 𝑥x, with positions numbered starting from 11 (the least significant bit is numbered 11). Returns 00 when 𝑥x is 00.
    • int __builtin_clz(unsigned int x): Returns the number of leading zeros in the binary representation of 𝑥x. When 𝑥x is 00, the result is undefined.
    • int __builtin_ctz(unsigned int x): Returns the number of trailing zeros in the binary representation of 𝑥x. When 𝑥x is 00, the result is undefined.
    • int __builtin_clrsb(int x): When the sign bit of 𝑥x is 00, returns the number of leading zeros in the binary representation of 𝑥x minus one; otherwise, returns the number of leading 11s minus one.
    • int __builtin_popcount(unsigned int x): Returns the number of 11s in the binary representation of 𝑥x.
    • int __builtin_parity(unsigned int x): Determines the parity (odd/even) of the number of 11s in the binary representation of 𝑥x.

    All these functions can have l or ll added to the function name (e.g., __builtin_popcountll) to change the parameter type to (unsigned)long or (unsigned)long long (the return type is still int).

    For example, sometimes we want to compute the logarithm base 2 of a number. Ignoring the special case of 00, this is equivalent to the number of bits in its binary representation minus 1. For an 𝑁N-bit integer 𝑛n, the number of bits in its binary representation can be expressed as N - __builtin_clz(n). Therefore, N - 1 - __builtin_clz(n) gives the logarithm base 2 of 𝑛n.

    Since these functions are built-in, they are highly optimized by the compiler and run very fast (some require only a single instruction).
