    Fast Walsh-Hadamard Transform

    Introduction

    Walsh Transform1 is a method used as an alternative to discrete Fourier transform in spectrum analysis, widely used in signal processing. FFT uses double type, but Walsh decomposes the signal under different oscillating frequency square waves, so all coefficients are integers of the same absolute value, which eliminates the need for floating-point multiplication and improves computation speed.

    Therefore, the core idea of FWT and FFT should be the same—they both transform an array. We denote the result of performing fast Walsh transform on array 𝐴A as 𝐹𝑊𝑇[𝐴]FWT[A].

    The core idea of FWT is:

    We need a new sequence 𝐶C, obtained from sequence 𝐴A and sequence 𝐵B through some operation rule, i.e., 𝐶 =𝐴 ⋅𝐵C=A⋅B;

    We first forward-transform to get 𝐹𝑊𝑇[𝐴],𝐹𝑊𝑇[𝐵]FWT[A],FWT[B], then according to 𝐹𝑊𝑇[𝐶] =𝐹𝑊𝑇[𝐴] ⋅𝐹𝑊𝑇[𝐵]FWT[C]=FWT[A]⋅FWT[B], we compute 𝐹𝑊𝑇[𝐶]FWT[C] in 𝑂(𝑛)O(n) time complexity, where ⋅⋅ is element-wise multiplication;

    Then we perform inverse transformation to get the original sequence 𝐶C. Time complexity is 𝑂(𝑛log⁡𝑛)O(nlog⁡n).

    In algorithm competitions, FWT is used to solve convolution problems with bitwise operations on indices.

    Formula: 𝐶𝑖 =∑𝑖=𝑗⊕𝑘𝐴𝑗𝐵𝑘Ci=∑i=j⊕kAjBk

    (Where ⊕⊕ is some binary bitwise operation)

    Below we give examples using ∪∪ (bitwise OR), ∩∩ (bitwise AND), and ⊕⊕ (bitwise XOR).

    FWT Operations

    OR Operation

    If 𝑘 =𝑖 ∪𝑗k=i∪j, then the positions where 𝑖i's binary has 1 and the positions where 𝑗j's binary has 1 must be a subset of the positions where 𝑘k's binary has 1.

    Now to get 𝐹𝑊𝑇[𝐶] =𝐹𝑊𝑇[𝐴] ⋅𝐹𝑊𝑇[𝐵]FWT[C]=FWT[A]⋅FWT[B], we need to construct the rule for this FWT.

    According to the definition, we can construct 𝐹𝑊𝑇[𝐴]𝑖 =𝐴′𝑖 =∑𝑖=𝑖∪𝑗𝐴𝑗FWT[A]i=Ai′=∑i=i∪jAj, representing 𝑗j whose binary 1s are a subset of 𝑖i's 1s.

    Then:

    𝐹𝑊𝑇[𝐴]𝑖⋅𝐹𝑊𝑇[𝐵]𝑖=(∑𝑖∪𝑗=𝑖𝐴𝑗)(∑𝑖∪𝑘=𝑖𝐵𝑘)=∑𝑖∪𝑗=𝑖∑𝑖∪𝑘=𝑖𝐴𝑗𝐵𝑘=∑𝑖∪(𝑗∪𝑘)=𝑖𝐴𝑗𝐵𝑘=𝐹𝑊𝑇[𝐶]𝑖FWT[A]i⋅FWT[B]i=(∑i∪j=iAj)(∑i∪k=iBk)=∑i∪j=i∑i∪k=iAjBk=∑i∪(j∪k)=iAjBk=FWT[C]i

    Now let's see how to compute 𝐹𝑊𝑇[𝐴]FWT[A].

    Enumerate would be too slow, with complexity 𝑂(𝑛2)O(n2). Since we can't enumerate all at once, consider divide-and-conquer.

    We bisect the entire interval. After bisecting, there is a pattern when writing indices in binary.

    Let 𝐴0A0 represent the first half of 𝐴A, and 𝐴1A1 the second half. 𝐴0A0 is the set of indices whose highest bit is 0—its subset is itself (since the highest bit is 0). But 𝐴1A1's highest bit is 1; the subsets that satisfy the condition are not only itself but also those with the highest bit as 0:

    𝐹𝑊𝑇[𝐴]=𝑚𝑒𝑟𝑔𝑒(𝐹𝑊𝑇[𝐴0],𝐹𝑊𝑇[𝐴0]+𝐹𝑊𝑇[𝐴1])FWT[A]=merge(FWT[A0],FWT[A0]+FWT[A1])

    Where merge concatenates two arrays like string concatenation, and ++ is ordinary addition, representing adding corresponding binary digits.

    This way, we can complete the concatenation in 𝑂(log⁡𝑛)O(log⁡n) time through bisection, and each concatenation requires one operation, so we get 𝐹𝑊𝑇[𝐴]FWT[A] in 𝑂(𝑛log⁡𝑛)O(nlog⁡n) time.

    Now for inversion. Since we know 𝐴0A0's subsets are itself (𝐴0 =𝐹𝑊𝑇[𝐴0]A0=FWT[A0]), and 𝐴1A1's subsets are 𝐹𝑊𝑇[𝐴0] +𝐹𝑊𝑇[𝐴1]FWT[A0]+FWT[A1], we can easily derive the inversion recurrence:

    𝑈𝐹𝑊𝑇[𝐴′]=𝑚𝑒𝑟𝑔𝑒(𝑈𝐹𝑊𝑇[𝐴′0],𝑈𝐹𝑊𝑇[𝐴′1]−𝑈𝐹𝑊𝑇[𝐴′0])UFWT[A′]=merge(UFWT[A0′],UFWT[A1′]−UFWT[A0′])

    Below we give the code implementation. It is easy to find that forward and inverse transforms can be merged into one function, with type =1type=1 for forward transform and type = −1type=−1 for inverse transform.

    void Or(ll *a, ll type) {  // Iterative implementation, smaller constant
  for (ll x = 2; x <= n; x <<= 1) {
    ll k = x >> 1;
    for (ll i = 0; i < n; i += x) {
      for (ll j = 0; j < k; j++) {
        (a[i + j + k] += a[i + j] * type) %= P;
      }
    }
  }
}

    AND Operation

    By analogy with OR operation, we can get similar conclusions:

    𝐹𝑊𝑇[𝐴]=𝑚𝑒𝑟𝑔𝑒(𝐹𝑊𝑇[𝐴0]+𝐹𝑊𝑇[𝐴1],𝐹𝑊𝑇[𝐴1])FWT[A]=merge(FWT[A0]+FWT[A1],FWT[A1])𝑈𝐹𝑊𝑇[𝐴′]=𝑚𝑒𝑟𝑔𝑒(𝑈𝐹𝑊𝑇[𝐴′0]−𝑈𝐹𝑊𝑇[𝐴′1],𝑈𝐹𝑊𝑇[𝐴′1])UFWT[A′]=merge(UFWT[A0′]−UFWT[A1′],UFWT[A1′])

    void And(ll *a, ll type) {
  for (ll x = 2; x <= n; x <<= 1) {
    ll k = x >> 1;
    for (ll i = 0; i < n; i += x) {

    XOR Operation

    XOR convolution is based on the following principle:

    If we let 𝑥 ∘𝑦x∘y represent the parity of the number of 1s in 𝑥 ∩𝑦x∩y, i.e., 𝑥 ∘𝑦 =popcnt(𝑥 ∩𝑦)mod2x∘y=popcnt(x∩y)mod2, then it's easy to have (𝑥 ∘𝑦) ⊕(𝑥 ∘𝑧) =𝑥 ∘(𝑦 ⊕𝑧)(x∘y)⊕(x∘z)=x∘(y⊕z).

    The computation of 𝐹𝑊𝑇[𝐴]FWT[A] is also easy to obtain.

    Let 𝐹𝑊𝑇[𝐴]𝑖 =∑𝑖∘𝑗=0𝐴𝑗 −∑𝑖∘𝑗=1𝐴𝑗FWT[A]i=∑i∘j=0Aj−∑i∘j=1Aj. Let's prove the correctness of 𝐹𝑊𝑇[𝐶] =𝐹𝑊𝑇[𝐴] ⋅𝐹𝑊𝑇[𝐵]FWT[C]=FWT[A]⋅FWT[B]:

    𝐹𝑊𝑇[𝐴]𝑖𝐹𝑊𝑇[𝐵]𝑖=(∑𝑖∘𝑗=0𝐴𝑗−∑𝑖∘𝑗=1𝐴𝑗)(∑𝑖∘𝑘=0𝐵𝑘−∑𝑖∘𝑘=1𝐵𝑘)=(∑𝑖∘𝑗=0𝐴𝑗∑𝑖∘𝑘=0𝐵𝑘+∑𝑖∘𝑗=1𝐴𝑗∑𝑖∘𝑘=1𝐵𝑘)−(∑𝑖∘𝑗=0𝐴𝑗∑𝑖∘𝑘=1𝐵𝑘+∑𝑖∘𝑗=1𝐴𝑗∑𝑖∘𝑘=0𝐵𝑘)=∑(𝑗⊕𝑘)∘𝑖=0𝐴𝑗𝐵𝑘−∑(𝑗⊕𝑘)∘𝑖=1𝐴𝑗𝐵𝑘=𝐹𝑊𝑇[𝐶]𝑖FWT[A]iFWT[B]i=(∑i∘j=0Aj−∑i∘j=1Aj)(∑i∘k=0Bk−∑i∘k=1Bk)=(∑i∘j=0Aj∑i∘k=0Bk+∑i∘j=1Aj∑i∘k=1Bk)−(∑i∘j=0Aj∑i∘k=1Bk+∑i∘j=1Aj∑i∘k=0Bk)=∑(j⊕k)∘i=0AjBk−∑(j⊕k)∘i=1AjBk=FWT[C]i

    Let's see how to quickly compute the values of 𝐴,𝐵A,B, still using divide-and-conquer:

    For subsequence 𝐹𝑊𝑇[𝐴0]FWT[A0] where 𝑖i's current bit is 0, when performing ∘∘ operations, we find that computing with 0 and 1 both yield the same result (because 0 ∩0 =0,0 ∩1 =00∩0=0,0∩1=0), so in 𝐹𝑊𝑇[𝐴] =∑𝑖∘𝑗=0𝐴𝑗 −∑𝑖∘𝑗=1𝐴𝑗FWT[A]=∑i∘j=0Aj−∑i∘j=1Aj, we have ∑𝑖∘𝑗=1𝐴𝑗 =0∑i∘j=1Aj=0.

    For subsequence 𝐴1A1 where 𝑖i's current bit is 1, when performing ∘∘ operations, we find that computing with 0 yields 0 and with 1 yields 1 (because 1 ∩0 =0,1 ∩1 =11∩0=0,1∩1=1).

    In summary:
