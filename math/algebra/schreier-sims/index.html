    Schreier-Sims Algorithm

    Introduction

    The Schreier-Sims algorithm is an algorithm in computational group theory, named after mathematicians Otto Schreier and Charles Sims. This algorithm can solve many problems in polynomial time, such as finding the order of a finite permutation group, checking whether a given permutation is contained in a given group, and so on. The Schreier-Sims algorithm was first introduced by Sims in 1970 based on the Schreier lemma. In 19811, Donald Knuth further improved the running time of the algorithm. Later, a faster randomized version of the algorithm was developed. Computer algebra systems (such as GAP and Magma) typically use highly optimized Monte Carlo versions of this algorithm2.

    Notation

    Following the conventions of computational group theory literature, this article uses right action for group actions, which means permutation composition proceeds from left to right. The group actions discussed in this article can all be viewed as permutation actions, although some algorithms also apply to more general group actions. Accordingly, the set of the group action is default to 𝑋 ={1,2,⋯,𝑛}X={1,2,⋯,n}, and its elements are called points. The result of permutation 𝑔g acting on point 𝑥x is denoted as 𝑥𝑔xg, and we sometimes say that permutation 𝑔g moves point 𝑥x to 𝑥𝑔xg. Finally, under the action of permutation group 𝐺G, the orbit of point 𝑥x is denoted as 𝑥𝐺 ={𝑥𝑔 :𝑔 ∈𝐺}xG={xg:g∈G}, and its stabilizer is denoted as 𝐺𝑥 ={𝑔 ∈𝐺 :𝑥𝑔 =𝑥}Gx={g∈G:xg=x}. The concept of stabilizer can be extended to a set 𝐵 ⊆𝑋B⊆X, and its stabilizer is defined as 𝐺𝐵 =⋂𝑥∈𝐵𝐺𝑥GB=⋂x∈BGx.

    Overview

    The main problem that the Schreier-Sims algorithm attempts to solve is:

    • Given a set 𝑆S of permutations on a set 𝑋X of size 𝑛n, how to efficiently store the permutation group 𝐺 =⟨𝑆⟩G=⟨S⟩ generated by 𝑆S in a computer, and complete a series of query tasks on this group?

    Obviously, such a group 𝐺G can be very large, far larger than the size of set 𝑋X and generating set 𝑆S. For example, the symmetric group 𝑆𝑛 =⟨(123⋯𝑛),(12)⟩Sn=⟨(123⋯n),(12)⟩ on 𝑛n elements has size 𝑛!n!, but it can be generated by only two permutations. Storing every element in the group is impractical.

    Similar to using the Gauss elimination method to construct a linear basis for a vector space, the idea of the Schreier-Sims algorithm is to find a "basis" for a finite permutation group 𝐺G:

    1. The algorithm's input is a generating set 𝑆S of 𝐺G, containing several permutations;
    2. If group 𝐺G is non-trivial, we can always find a point 𝛽β whose position changes under the action of group 𝐺G, i.e., |𝛽𝐺| >1|βG|>1;
    3. Find the orbit Δ =𝛽𝐺Δ=βG of point 𝛽β, and for each point 𝛿 ∈Δδ∈Δ in the orbit, find a permutation 𝑡𝛿tδ in group 𝐺G that can move point 𝛽β to 𝛿δ;
    4. Find a generating set 𝑆′S′ for the stabilizer 𝐺𝛽Gβ of point 𝛽β;
    5. Recursively call this algorithm on 𝐺′ =⟨𝑆′⟩G′=⟨S′⟩ until we obtain the trivial group {𝑒}{e}.

    The rationality of this approach is that the stabilizer 𝐺𝛽Gβ of point 𝛽β is a subgroup of group 𝐺G, and its (right) cosets form a partition of group 𝐺G, and these cosets are in one-to-one correspondence with the orbit 𝛽𝐺βG of point 𝛽β. The permutations 𝑡𝛿tδ obtained in step 3 are the representatives of these cosets. This set of coset representatives 𝑇T is called the transversal (or coset representative system) of the stabilizer 𝐺𝛽Gβ. In other words, every element 𝑔g in group 𝐺G corresponds uniquely to a pair (ℎ,𝑡) ∈𝐺𝛽 ×𝑇(h,t)∈Gβ×T, and 𝑔 =ℎ𝑡g=ht. Therefore, as long as we can store the subgroup 𝐺𝛽Gβ and the corresponding transversal 𝑇T, we can store the entire group 𝐺G. However, the problem of storing the subgroup 𝐺𝛽Gβ has already been solved—by recursively calling the algorithm.

    Of course, there are many details to sort out in the implementation of the algorithm, which is the main content of this article. But before that, we should examine the results obtained after calling the algorithm, see how the algorithm stores the group, and what query problems it can solve. To do this, we need to clarify some concepts.

    Stabilizer Chain

    Suppose we call this algorithm on group 𝐺 ={𝑆}G={S}, and it performs 𝑘k iterations; and in the 𝑖i-th iteration, the input is the set of permutations 𝑆(𝑖−1)S(i−1), the point found is 𝛽𝑖βi, the transversal obtained is 𝑇𝑖Ti, and the generating set for the stabilizer is 𝑆(𝑖)S(i). If we denote 𝐺(𝑖) =⟨𝑆(𝑖)⟩G(i)=⟨S(i)⟩. Then the algorithm actually obtains a chain of subgroups

    𝐺=𝐺(0)>𝐺(1)>⋯>𝐺(𝑘−1)>𝐺(𝑘)={𝑒}.G=G(0)>G(1)>⋯>G(k−1)>G(k)={e}.

    Moreover, each subgroup in the chain is a stabilizer

    𝐺(𝑖)=𝐺𝛽1,⋯,𝛽𝑖.G(i)=Gβ1,⋯,βi.

    Thus, the Schreier-Sims algorithm can be seen as computing such a stabilizer chain.

    Base and Strong Generating Set

    If a subset 𝐵B of set 𝑋X satisfies 𝐺𝐵 ={𝑒}GB={e}, then 𝐵B is called a base of the permutation group 𝐺G. Obviously, the algorithm above obtains a base 𝐵 ={𝛽1,⋯,𝛽𝑘}B={β1,⋯,βk}. This means that the result of permutation 𝑔 ∈𝐺g∈G acting on these points uniquely determines this permutation in group 𝐺G. Moreover, this base output by the algorithm also satisfies the condition

    𝐺(𝑖−1)=𝐺𝛽1,⋯,𝛽𝑖−1>𝐺𝛽1,⋯,𝛽𝑖−1,𝛽𝑖=𝐺(𝑖).G(i−1)=Gβ1,⋯,βi−1>Gβ1,⋯,βi−1,βi=G(i).

    That is, each point in the base carries effective information about the elements in the group. Such a base is called nonredundant. The algorithm always outputs a nonredundant base. The stabilizer chain corresponding to such a base is strictly decreasing.

    At the same time, the union of the generating sets obtained by the algorithm

    ¯𝑆=𝑘⋃𝑖=0𝑆𝑖S¯=⋃i=0kSi

    is also a generating set of group 𝐺G, and we have ⟨¯𝑆 ∩𝐺(𝑖)⟩ =𝐺(𝑖)⟨S¯∩G(i)⟩=G(i). A generating set satisfying this condition is called a strong generating set of group 𝐺G relative to base 𝐵B. Thus, the Schreier-Sims algorithm can also be seen as computing the base and strong generating set (BSGS) of group 𝐺G. This formulation is equivalent to the stabilizer-chain formulation, and this article does not distinguish between them.

    The algorithm also obtains a series of orbits Δ𝑖 =𝛽𝐺(𝑖−1)𝑖Δi=βiG(i−1) and corresponding transversals 𝑇𝑖Ti. These orbits are called the fundamental orbits of group 𝐺G. When this article mentions the stabilizer chain or base and strong generating set of group 𝐺G, it is always assumed that the corresponding fundamental orbits and transversals have been computed together.

    Data Structure

    This article will provide a series of pseudocode. In the pseudocode, the stabilizer chain (or base and strong generating set) of a group is stored in a data structure 𝐶C:

    𝐶=(𝑆,Δ,𝑇,𝐶′).C=(S,Δ,T,C′).

    The data members of this structure are: the generating set 𝑆S of the current group, the fundamental orbit ΔΔ, the corresponding transversal 𝑇T, and the stabilizer 𝐶′C′ stored as a nested substructure. Of course, 𝐶′C′ is also such a structure. The entire group is actually stored in a layered structure, with each layer describing a group in the stabilizer chain. The innermost layer is an empty struct, representing 𝐺(𝑘) ={𝑒}G(k)={e}.

    In the pseudocode, the members of this data structure can be accessed via 𝐶.𝑔𝑒𝑛𝑒𝑟𝑎𝑡𝑜𝑟𝑠C.generators, 𝐶.𝑜𝑟𝑏𝑖𝑡C.orbit, 𝐶.𝑡𝑟𝑎𝑛𝑠𝑣𝑒𝑟𝑠𝑎𝑙C.transversal, and 𝐶.𝑛𝑒𝑥𝑡C.next respectively. The first element of the orbit 𝐶.𝑜𝑟𝑏𝑖𝑡[0]C.orbit[0] is default to the base point 𝛽β, and the corresponding coset representative 𝐶.𝑡𝑟𝑎𝑛𝑠𝑣𝑒𝑟𝑠𝑎𝑙[𝛽]C.transversal[β] is default to the identity transformation 𝑒e. Note that although array index access is used here to access elements in the orbit and transversal, they may not necessarily be stored as arrays; rather, they should be understood as providing methods to access the first element of the orbit and to query the corresponding coset representative by a point in the orbit. The specific implementation details will be discussed later.

    Applications

    After obtaining the base and strong generating set of a group, we can solve a series of query problems about the group. Among them, the most basic, and also the most common in programming contests, are querying the order of the group and determining whether a permutation belongs to a given group.

    Order of a Group

    If we know the base and strong generating set of group 𝐺G, then applying Lagrange's theorem and the orbit-stabilizer theorem, the order of group 𝐺G can be computed as

    |𝐺|=𝑘∏𝑖=1[𝐺(𝑖−1):𝐺(𝑖)]=𝑘∏𝑖=1[𝐺(𝑖−1):𝐺(𝑖−1)𝛽𝑖]=𝑘∏𝑖=1|𝑇𝑖|.|G|=∏i=1k[G(i−1):G(i)]=∏i=1k[G(i−1):Gβi(i−1)]=∏i=1k|Ti|.

    Therefore, we can obtain the order of group 𝐺G by multiplying the sizes of all transversals 𝑇𝑖Ti (or equivalently, the lengths of the fundamental orbits Δ𝑖Δi).

    Membership Testing

    Knowing the base and strong generating set of group 𝐺G, we can also determine whether a given permutation ℎh belongs to group 𝐺G. This is called the membership testing problem.

    This problem can be solved recursively. To determine ℎ ∈𝐺(𝑖−1)h∈G(i−1), we must first find the representative 𝑡 ∈𝑇𝑖t∈Ti of the coset of 𝐺(𝑖)G(i) containing ℎh. If we can find it, then let ℎ′ =ℎ𝑡−1h′=ht−1, and we have ℎ =ℎ′𝑡h=h′t and ℎ ∈𝐺(𝑖−1)h∈G(i−1) is equivalent to ℎ′ ∈𝐺(𝑖)h′∈G(i); the problem reduces to determining ℎ′ ∈𝐺(𝑖)h′∈G(i). If we cannot find such 𝑡t, or if we have recursed to 𝐺(𝑘) ={𝑒}G(k)={e} but ℎ ≠𝑒h≠e, we can conclude that ℎ ∉𝐺h∉G.     The problem is what data structure to use to store the corresponding transversal 𝑇T.

    Direct Storage

    The simplest method, of course, is to directly store each element 𝑡t in the transversal 𝑇T. A single permutation stored in one-line notation requires exactly 𝑛n space, so storing such a transversal has space complexity 𝑂(|𝑇|𝑛)O(|T|n). The benefit of this is that accessing a single coset representative has 𝑂(1)O(1) time complexity, at the cost of 𝑂(|𝑇|𝑛)O(|T|n) time complexity for the initial computation of these coset representatives.

    Schreier Tree

    Another common approach is to implement a tree structure to store the transversal. It is called a Schreier tree (or Schreier vector)4. It takes 𝛽β as the root, and the elements 𝛿δ in the orbit ΔΔ as vertices. Each time a new vertex 𝛾 =𝛿𝑠γ=δs is obtained during the search, we connect an edge from the old vertex 𝛿δ to the new vertex 𝛾γ, and on the edge we record the index (or pointer) of the permutation 𝑠s in the generating set 𝑆S. Since the generating set is already stored, the additional space complexity for storing the transversal is 𝑂(|𝑇|)O(|T|). For cases where 𝑛n is very large, this can effectively save space, and the initial computation has complexity 𝑂(|𝑇|)O(|T|). However, the side effect is that each time we need to obtain a coset representative, we need to traverse the path from the vertex to the root, recalculating the coset representative, so the time complexity highly depends on the depth of the Schreier tree. In general cases, the tree depth can reach 𝑂(𝑛)O(n).

    In actual implementation, we need to weigh the time and space complexity of the algorithm based on the actual situation. For situations that may be encountered in programming contests, 𝑛n is usually not large, space is sufficient, and time complexity is often the bottleneck. As we will see later, the most time-consuming step of the Schreier-Sims algorithm requires multiple accesses to coset representatives, so using direct storage is often better. However, for some applications, 𝑛n may be very large and storage space may be more constrained, in which case it may be necessary to use the Schreier tree method to store the transversal. For such cases, to avoid excessively deep Schreier trees, researchers have proposed many methods to reconstruct a shallow Schreier tree when the tree becomes too deep. Interested readers can refer to the references at the end of this article.

    The Schreier-Sims Algorithm

    To solve the above problem, this section discusses an incremental implementation of the Schreier-Sims algorithm, which obtains a strong generating set of size 𝑂(𝑛2)O(n2).

    Filtering

    The core optimization of the Schreier-Sims algorithm over the naive algorithm is quite simple: it requires that before adding any Schreier generator to the generating set of the stabilizer, it must first go through filtering. Filtering means first determining whether the new Schreier generator already exists in the subgroup generated by the existing generators, and then only adding those that do not yet exist. To do this, we only need to use the membership testing algorithm MembershipTest(𝐶,ℎ)MembershipTest(C,h) from earlier.

    However, the precondition for being able to do this is that, based on the Schreier generators already generated by the current group, the stabilizer chain (or base and strong generating set) of the group they generate has long been constructed. This means that each time a new Schreier generator is added to the generating set of the stabilizer, we need to dynamically maintain the inner stabilizer chain for subsequent filtering. However, inserting one generator at the current layer may produce multiple Schreier generators, which may cause multiple updates to the inner structure; and each update of the inner structure may trigger multiple updates of the even more inner structure.

    It seems that the exponential explosion problem mentioned earlier still exists. Actually, it doesn't. Because we have done filtering in advance, only when the generator to be added really causes expansion of a certain layer's structure will that layer's structure be updated. This shows that the number of times a single layer's structure is updated is actually equal to the number of times the group stored in that layer strictly grows. However, a group of size |𝐺||G| has a subgroup chain of length at most log⁡|𝐺|log⁡|G|; because Lagrange's theorem guarantees that each time the subgroup chain length increases by one, the group size at least doubles. This shows that a single layer's structure is updated at most log⁡|𝐺|log⁡|G| times, so the final size of the strong generating set ¯𝑆S¯ is |𝐵|log⁡|𝐺||B|log⁡|G|.

    This estimate can be further improved. Since the group 𝐺G here is known to be a subgroup of the symmetric group 𝑆𝑛Sn on 𝑛n elements, the length of the subgroup chain of 𝐺G does not exceed that of 𝑆𝑛Sn. It can be proven6 that the length of a strictly increasing subgroup chain of 𝑆𝑛Sn does not exceed 3𝑛/23n/2. This shows that the number of times a single layer's structure is updated is actually 𝑂(𝑛)O(n). Obviously, the size of the base does not exceed 𝑛n. Therefore, the final size of the strong generating set ¯𝑆S¯ is 𝑂(𝑛2)O(n2).

    The filtering method mentioned here was proposed by Sims, and is also called the Sims filter. There is also a more complex filtering method proposed by Jerrum, also called the Jerrum filter, which can guarantee that the obtained strong generating set has size 𝑂(𝑛)O(n). Interested readers can study it on their own.

    For the filtering process, there is a small optimization: in the implementation of MembershipTest(𝐶,ℎ)MembershipTest(C,h), instead of outputting a boolean value, we output the final "sifted"7 ℎh (i.e., use 𝐫𝐞𝐭𝐮𝐫𝐧 ℎreturn h instead of lines 1010 and 1414 in the pseudocode). If the sifted ℎ ≠𝑒h≠e, then membership testing fails, and we can directly add the sifted ℎh rather than the original ℎh to the current layer. Here, the sifted ℎh has already had several coset representative factors removed, so it moves fewer elements, thus reducing local computation. This optimization has no effect on the overall complexity.

    Complexity Analysis

    To analyze the complexity of the Schreier-Sims algorithm, we need some notation. Let the length of the permutation be 𝑛n, and the size of the generating set be |𝑆| =𝑚|S|=m. Let the length of the (nonredundant) base obtained be |𝐵||B|. Moreover, let the number of generators in the 𝑖i-th layer from the outside be |𝑆𝑖−1||Si−1|, and the size of the transversal (or the length of the orbit) be |𝑇𝑖||Ti|. Below we analyze the time complexity required by the incremental implementation of the Schreier-Sims algorithm above. The algorithm consists of two main parts: filtering, and the computation of orbits, transversals, and Schreier generators.

    Both the initially input generators and the Schreier generators obtained in the algorithm need to be filtered, so the total number of filtering executions is 𝑂(∑|𝐵|𝑖=1|𝑆𝑖−1||𝑇𝑖| +|𝑆|)O(∑i=1|B||Si−1||Ti|+|S|). The total time complexity of the filtering process is 𝑂(𝜏|𝐵|∑|𝐵|𝑖=1|𝑆𝑖−1||𝑇𝑖| +𝜏|𝐵||𝑆|)O(τ|B|∑i=1|B||Si−1||Ti|+τ|B||S|).

// A permutation.
class Permutation {
  std::vector<int> perm;

  void shrink() {
    int m = perm.size();
    for (; m && perm[m - 1] == m - 1; --m);
    perm.resize(m);
  }

 public:
  Permutation() {}

  Permutation(const std::vector<int>& vec) : perm(vec) { shrink(); }

  int operator[](int i) const { return i < perm.size() ? perm[i] : i; }

  bool empty() const { return perm.empty(); }

  // First LHS then RHS.
  Permutation operator*(const Permutation& rhs) const {
    Permutation res;
    res.perm.resize(std::max(perm.size(), rhs.perm.size()));
    for (int i = 0; i < res.perm.size(); ++i) {
      res.perm[i] = rhs[(*this)[i]];
    }
    res.shrink();
    return res;
  }

  // First LHS^{-1} then RHS.
  Permutation operator/(const Permutation& rhs) const {
    Permutation res;
    res.perm.resize(std::max(perm.size(), rhs.perm.size()));
    for (int i = 0; i < res.perm.size(); ++i) {
      res.perm[(*this)[i]] = rhs[i];
    }
    res.shrink();
    return res;
  }

  // Inverse.
  Permutation inv() const {
    Permutation res;
    res.perm.resize(perm.size());
    for (int i = 0; i < res.perm.size(); ++i) {
      res.perm[(*this)[i]] = i;
    }
    return res;
  }
};

// A stabilizer chain (a.k.a., BSGS) for a group.
class PermutationGroup {
  size_t n, k;
  std::vector<bool> orbit;               // Orbit of the n-th point.
  std::vector<Permutation> generators;   // Generators.
  std::vector<Permutation> transversal;  // Inverse of coset representatives.
  PermutationGroup* next;                // Stabilizer.

  // Sift a permutation.
  void sift(Permutation& h) const {
    if (!n) return;
    int i = h[n - 1];
    if (!orbit[i]) return;
    h = h * transversal[i];
    next->sift(h);
  }

  // Add one more element into the transversal.
  void extend_transversal(Permutation t) {
    int i = t[n - 1];
    if (!orbit[i]) {
      ++k;
      orbit[i] = true;
      transversal[i] = t.inv();
      for (const auto& s : generators) {
        extend_transversal(t * s);
      }
    } else {
      next->extend(t * transversal[i]);
    }
  }

 public:
  PermutationGroup(int n)
      : n(n), k(1), orbit(n), transversal(n), next(nullptr) {
    if (!n) return;
    // Initialize the current layer.
    orbit[n - 1] = true;
    next = new PermutationGroup(n - 1);
  }

  // Destructor.
  ~PermutationGroup() {
    if (next) delete next;
  }

  // Add one more permutation into the group.
  void extend(Permutation g) {
    sift(g);
    if (g.empty()) return;
    generators.emplace_back(g);
    for (int i = 0; i < n; ++i) {
      if (orbit[i]) {
        extend_transversal(transversal[i] / g);
      }
    }
  }

  // Check whether a permutation belongs to the group.
  bool membership_test(Permutation h) const {
    sift(h);
    return h.empty();
  }

  // Return the size of the group.
  long long size() const { return n ? next->size() * k : 1LL; }
};

int main() {
  int n, m;
  std::cin >> n >> m;
  PermutationGroup group(n);
  // Read permutations and insert them to the group.
  std::vector<int> vec(n);
  for (; m; --m) {
    for (int& x : vec) {
      std::cin >> x;
      --x;  // Index starting at 0.
    }
    group.extend(Permutation(vec));
  }
  // Output the size of the group.
  std::cout << group.size();
  return 0;
}
