    Meissel-Lehmer Algorithm

    The Meissel-Lehmer algorithm is an algorithm that can compute the number of primes between 11 and 𝑛n in sub-linear time complexity.

    Notation

    [𝑥][x] denotes the result of rounding down 𝑥x.
    𝑝𝑘pk denotes the 𝑘k-th prime, with 𝑝1 =2p1=2.
    𝜋(𝑥)π(x) denotes the number of primes in the range 1 ∼𝑥1∼x.
    𝜇(𝑥)μ(x) denotes the Möbius function.
    For a set 𝑆S, #𝑆#S denotes the size of set 𝑆S.
    𝛿(𝑥)δ(x) denotes the smallest prime factor of 𝑥x.
    𝑃+(𝑥)P+(x) denotes the largest prime factor of 𝑥x.

    Meissel-Lehmer Algorithm for Computing 𝜋(𝑥)π(x)

    Define 𝜙(𝑥,𝑎)ϕ(x,a) as the number of positive integers less than 𝑥x such that all their prime factors are greater than 𝑝𝑎pa, i.e.:

    𝜙(𝑥,𝑎)=#{𝑛≤𝑥∣𝑛mod𝑝=0⟹𝑝>𝑝𝑎}(1)(1)ϕ(x,a)=#{n≤x∣nmodp=0⟹p>pa}

    Define 𝑃𝑘(𝑥,𝑎)Pk(x,a) as the number of positive integers less than 𝑥x that have exactly 𝑘k prime factors (with multiplicity) and all prime factors are greater than 𝑝𝑎pa, i.e.:

    𝑃𝑘(𝑥,𝑎)=#{𝑛≤𝑥∣𝑛=𝑞1𝑞2⋯𝑞𝑘⟹∀𝑖,𝑞𝑖>𝑝𝑎}(2)(2)Pk(x,a)=#{n≤x∣n=q1q2⋯qk⟹∀i,qi>pa}

    In particular, we define: 𝑃0(𝑥,𝑎) =1P0(x,a)=1, so we have:

    𝜙(𝑥,𝑎)=𝑃0(𝑥,𝑎)+𝑃1(𝑥,𝑎)+⋯+𝑃𝑘(𝑥,𝑎)+⋯ϕ(x,a)=P0(x,a)+P1(x,a)+⋯+Pk(x,a)+⋯

    This infinite sum can actually be expressed as a finite sum, because when 𝑝𝑘𝑎 >𝑥pak>x, we have 𝑃𝑘(𝑥,𝑎) =0Pk(x,a)=0.

    Let 𝑦y be an integer satisfying 𝑥1/3 ≤𝑦 ≤𝑥1/2x1/3≤y≤x1/2, and let 𝑎 =𝜋(𝑦)a=π(y).

    When 𝑘 ≥3k≥3, we have 𝑃1(𝑥,𝑎) =𝜋(𝑥) −𝑎P1(x,a)=π(x)−a and 𝑃𝑘(𝑥,𝑎) =0Pk(x,a)=0, from which we can derive:

    𝜋(𝑥)=𝜙(𝑥,𝑎)+𝑎−1−𝑃2(𝑥,𝑎)(3)(3)π(x)=ϕ(x,a)+a−1−P2(x,a)

    Thus, computing 𝜋(𝑥)π(x) can be reduced to computing 𝜙(𝑥,𝑎)ϕ(x,a) and 𝑃2(𝑥,𝑎)P2(x,a).

    Computing 𝑃2(𝑥,𝑎)P2(x,a)

    From equation (2)(2), we can derive that 𝑃2(𝑥,𝑎)P2(x,a) equals the number of prime pairs (𝑝,𝑞)(p,q) satisfying 𝑦 <𝑝 ≤𝑞y<p≤q and 𝑝𝑞 ≤𝑥pq≤x.

    First, we note that 𝑝 ∈[𝑦+1,√𝑥]p∈[y+1,x]. Moreover, for each 𝑝p, we have 𝑞 ∈[𝑝,𝑥/𝑝]q∈[p,x/p]. Therefore:

    𝑃2(𝑥,𝑎)=∑𝑦<𝑝≤√𝑥(𝜋(𝑥𝑝)−𝜋(𝑝)+1)(4)(4)P2(x,a)=∑y<p≤x(π(xp)−π(p)+1)

    When 𝑝 ∈[𝑦+1,√𝑥]p∈[y+1,x], we have 𝑥𝑝 ∈[1,𝑥𝑦]xp∈[1,xy]. Therefore, we can sieve the interval [1,𝑥𝑦][1,xy], and then compute 𝜋(𝑥𝑝) −𝜋(𝑝) +1π(xp)−π(p)+1 for all primes 𝑝 ∈[𝑦+1,√𝑥]p∈[y+1,x]. To reduce the space complexity of the above algorithm, we can consider block sieving with block length 𝐿L. If the block length 𝐿 =𝑦L=y, we can compute 𝑃2(𝑥,𝑎)P2(x,a) in 𝑂(𝑥𝑦log⁡log⁡𝑥)O(xylog⁡log⁡x) time complexity and 𝑂(𝑦)O(y) space complexity.

    Computing 𝜙(𝑥,𝑎)ϕ(x,a)

    For 𝑏 ≤𝑎b≤a, consider all positive integers not exceeding 𝑥x such that all their prime factors are greater than 𝑝𝑏−1pb−1. These numbers can be divided into two categories:

    1. Divisible by 𝑝𝑏pb;
    2. Not divisible by 𝑝𝑏pb.

    The number of numbers in the first category is 𝜙(𝑥𝑝𝑏,𝑏−1)ϕ(xpb,b−1), and the number in the second category is 𝜙(𝑥,𝑏)ϕ(x,b).

    Therefore, we conclude:

    Theorem 5.1: The function 𝜙ϕ satisfies the following properties

    𝜙(𝑢,0)=[𝑢](5)(5)ϕ(u,0)=[u]𝜙(𝑥,𝑏)=𝜙(𝑥,𝑏−1)−𝜙(𝑥𝑝𝑏,𝑏−1)(6)(6)ϕ(x,b)=ϕ(x,b−1)−ϕ(xpb,b−1)

    A simple method for computing 𝜙(𝑥,𝑎)ϕ(x,a) can be derived from this theorem: we repeatedly use equation (7)(7) until we finally get 𝜙(𝑢,0)ϕ(u,0). This process can be viewed as creating a rooted binary tree starting from the root node 𝜙(𝑥,𝑎)ϕ(x,a). Figure 1 illustrates this process. Using this method, we obtain the following formula:

    𝜙(𝑥,𝑎)=∑1≤𝑛≤𝑥𝑃+(𝑛)≤𝑦𝜇(𝑛)[𝑥/𝑛]ϕ(x,a)=∑1≤n≤xP+(n)≤yμ(n)[x/n]𝜙(𝑥,𝑎)↙↘𝜙(𝑥,𝑎−1)−𝜙(𝑥𝑝𝑎,𝑎−1)↙↓↓↘𝜙(𝑥,𝑎−2)𝜙(𝑥𝑝𝑎−1,𝑎−2)−𝜙(𝑥𝑝𝑎,𝑎−2)𝜙(𝑥𝑝𝑎𝑝𝑎−1,𝑎−2)⋮ϕ(x,a)↙↘ϕ(x,a−1)−ϕ(xpa,a−1)↙↓↓↘ϕ(x,a−2)ϕ(xpa−1,a−2)−ϕ(xpa,a−2)ϕ(xpapa−1,a−2)⋮

    The figure above shows the binary tree for computing 𝜙(𝑥,𝑎)ϕ(x,a): the sum of the weights of leaf nodes is 𝜙(𝑥,𝑎)ϕ(x,a).

    However, this requires computing too many things. Because 𝑦 ≥𝑥1/3y≥x1/3, simply computing the numbers that are products of at most 33 primes not exceeding 𝑦y would have at least 𝑥log3⁡𝑥xlog3⁡x terms using this method, which cannot meet our complexity requirements.

    To limit the "growth" of this binary tree, we need to change the original termination condition. This is the original termination condition.

    Termination condition 1: If 𝑏 =0b=0, do not apply equation (6)(6) to the node 𝜇(𝑛)𝜙(𝑥𝑛,𝑏)μ(n)ϕ(xn,b).

    We change it to a stronger termination condition:

    Termination condition 2: If either of the following 2 conditions is satisfied, do not apply equation (6)(6) to the node 𝜇(𝑛)𝜙(𝑥𝑛,𝑏)μ(n)ϕ(xn,b):

    1. 𝑏 =0b=0 and 𝑛 ≤𝑦n≤y;
    2. 𝑛 >𝑦n>y.

    We classify the leaves on the original binary tree according to Termination condition 2 into two types:

    1. If the leaf node 𝜇(𝑛)𝜙(𝑥𝑛,𝑏)μ(n)ϕ(xn,b) satisfies 𝑛 ≤𝑦n≤y, we call such leaves ordinary leaves;
    2. If the leaf node 𝜇(𝑛)𝜙(𝑥𝑛,𝑏)μ(n)ϕ(xn,b) satisfies 𝑛 >𝑦n>y and 𝑛 =𝑚𝑝𝑏(𝑚≤𝑦)n=mpb(m≤y), we call such nodes special leaves.

    From this we conclude:

    Theorem 5.2: We have:

    𝜙(𝑥,𝑎)=𝑆0+𝑆(7)(7)ϕ(x,a)=S0+S

    where 𝑆0S0 represents the contribution of ordinary leaves:

    𝑆0=∑𝑛≤𝑦𝜇(𝑛)[𝑥𝑛](8)(8)S0=∑n≤yμ(n)[xn]

    𝑆S represents the contribution of special leaves:

    𝑆=∑𝑛/𝛿(𝑛)≤𝑦≤𝑛𝜇(𝑛)𝜙(𝑥𝑛,𝜋(𝛿(𝑛))−1)(9)(9)S=∑n/δ(n)≤y≤nμ(n)ϕ(xn,π(δ(n))−1)

    Computing 𝑆0S0 can obviously be solved in 𝑂(𝑦log⁡log⁡𝑥)O(ylog⁡log⁡x) time complexity. Now we need to consider how to compute 𝑆S.
