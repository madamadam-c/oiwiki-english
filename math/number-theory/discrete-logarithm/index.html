    Discrete Logarithm

    Definition

    Prerequisite knowledge: Orders and Primitive Roots.

    The definition of discrete logarithm is similar to logarithm. Take a positive integer modulus 𝑚m that has a primitive root, and let 𝑔g be one of its primitive roots. For an integer 𝑎a with (𝑎,𝑚) =1(a,m)=1, we know there exists a unique integer 0 ≤𝑘 <𝜑(𝑚)0≤k<φ(m) such that

    𝑔𝑘≡𝑎(mod𝑚)gk≡a(modm)

    We call this 𝑘k the discrete logarithm of 𝑎a with base 𝑔g modulo 𝑚m, denoted 𝑘 =ind𝑔⁡𝑎k=indg⁡a, which can be simplified to ind⁡𝑎ind⁡a when no confusion arises.

    Obviously ind𝑔⁡1 =0indg⁡1=0, ind𝑔⁡𝑔 =1indg⁡g=1.

    Properties

    The properties of discrete logarithm are also similar to logarithm in many ways.

    Properties

    Let 𝑔g be a primitive root modulo 𝑚m, (𝑎,𝑚) =(𝑏,𝑚) =1(a,m)=(b,m)=1, then:

    1. ind𝑔⁡(𝑎𝑏) ≡ind𝑔⁡𝑎 +ind𝑔⁡𝑏(mod𝜑(𝑚))indg⁡(ab)≡indg⁡a+indg⁡b(modφ(m))

      Furthermore (∀𝑛 ∈𝐍),  ind𝑔⁡𝑎𝑛 ≡𝑛ind𝑔⁡𝑎(mod𝜑(𝑚))(∀n∈N),  indg⁡an≡nindg⁡a(modφ(m))

    2. If 𝑔1g1 is also a primitive root modulo 𝑚m, then ind𝑔⁡𝑎 ≡ind𝑔1⁡𝑎 ⋅ind𝑔⁡𝑔1(mod𝜑(𝑚))indg⁡a≡indg1⁡a⋅indg⁡g1(modφ(m))

    3. 𝑎 ≡𝑏(mod𝑚) ⟺ ind𝑔⁡𝑎 =ind𝑔⁡𝑏a≡b(modm)⟺indg⁡a=indg⁡b
    Proof
    1. 𝑔ind𝑔⁡(𝑎𝑏) ≡𝑎𝑏 ≡𝑔ind𝑔⁡𝑎𝑔ind𝑔⁡𝑏 ≡𝑔ind𝑔⁡𝑎+ind𝑔⁡𝑏(mod𝑚)gindg⁡(ab)≡ab≡gindg⁡agindg⁡b≡gindg⁡a+indg⁡b(modm)

    2. Let 𝑥 =ind𝑔1⁡𝑎x=indg1⁡a, then 𝑎 ≡𝑔𝑥1(mod𝑚)a≡g1x(modm). Also let 𝑦 =ind𝑔⁡𝑔1y=indg⁡g1, then 𝑔1 ≡𝑔𝑦(mod𝑚)g1≡gy(modm).

      Thus 𝑎 ≡𝑔𝑥𝑦(mod𝑚)a≡gxy(modm), i.e., ind𝑔⁡𝑎 ≡𝑥𝑦 ≡ind𝑔1⁡𝑎 ⋅ind𝑔⁡𝑔1(mod𝜑(𝑚))indg⁡a≡xy≡indg1⁡a⋅indg⁡g1(modφ(m))

    3. Note that:

      ind𝑔⁡𝑎=ind𝑔⁡𝑏⟺ind𝑔⁡𝑎≡ind𝑔⁡𝑏(mod𝜑(𝑚))⟺𝑔ind𝑔⁡𝑎≡𝑔ind𝑔⁡𝑏(mod𝑚)⟺𝑎≡𝑏(mod𝑚)indg⁡a=indg⁡b⟺indg⁡a≡indg⁡b(modφ(m))⟺gindg⁡a≡gindg⁡b(modm)⟺a≡b(modm)

    Baby-Step Giant-Step Algorithm

    Currently, there is still no polynomial-time classical algorithm for the discrete logarithm problem (the input size of the discrete logarithm problem is the number of bits of the input data). In cryptography, based on this point, many asymmetric encryption algorithms have been designed, such as Ed25519.

    In competitive programming, BSGS (baby-step giant-step) is often used to solve the discrete logarithm problem. Formally, for 𝑎,𝑏,𝑚 ∈𝐙+a,b,m∈Z+, this algorithm can solve in 𝑂(√𝑚)O(m) time:

    𝑎𝑥≡𝑏(mod𝑚)ax≡b(modm)

    where 𝑎 ⟂𝑚a⟂m. The solution 𝑥x satisfies 0 ≤𝑥 <𝑚0≤x<m. (Note that 𝑚m is not necessarily prime)

    Algorithm Description

    Let 𝑥 =𝐴⌈√𝑚⌉ −𝐵x=A⌈m⌉−B, where 0 ≤𝐴,𝐵 ≤⌈√𝑚⌉0≤A,B≤⌈m⌉, then we have 𝑎𝐴⌈√𝑚⌉−𝐵 ≡𝑏(mod𝑚)aA⌈m⌉−B≡b(modm), after slightly rearranging, we have 𝑎𝐴⌈√𝑚⌉ ≡𝑏𝑎𝐵(mod𝑚)aA⌈m⌉≡baB(modm).

    We know 𝑎,𝑏a,b, so we can first calculate all values of 𝑏𝑎𝐵baB on the right side, enumerate 𝐵B, store them with hash/map, then calculate 𝑎𝐴⌈√𝑚⌉aA⌈m⌉ one by one, enumerate 𝐴A, and check if there is a matching 𝑏𝑎𝐵baB. Thus we can get all 𝑥x, 𝑥 =𝐴⌈√𝑚⌉ −𝐵x=A⌈m⌉−B.

    Note that both 𝐴,𝐵A,B are less than ⌈√𝑚⌉⌈m⌉, so the time complexity is Θ(√𝑚)Θ(m), and using map adds an extra loglog.

    Why require 𝑎a to be coprime with 𝑚m?

    Note that what we compute are 𝐴,𝐵A,B. We need to ensure that from 𝑎𝐴⌈√𝑚⌉ ≡𝑏𝑎𝐵(mod𝑚)aA⌈m⌉≡baB(modm) we can deduce 𝑎𝐴⌈√𝑚⌉−𝐵 ≡𝑏(mod𝑚)aA⌈m⌉−B≡b(modm). The latter is obtained by dividing both sides by 𝑎𝐵aB, so we must have 𝑎𝐵 ⟂𝑚aB⟂m, i.e., 𝑎 ⟂𝑚a⟂m.

    Extended BSGS Algorithm

    For 𝑎,𝑏,𝑚 ∈𝐙+a,b,m∈Z+, solve:

    𝑎𝑥≡𝑏(mod𝑚)ax≡b(modm)

    where 𝑎,𝑚a,m are not necessarily coprime.

    When (𝑎,𝑚) =1(a,m)=1, 𝑎a has an inverse modulo 𝑚m, so BSGS can be used. So we try to make them coprime.

    Specifically, let 𝑑1 =(𝑎,𝑚)d1=(a,m). If 𝑑1 ∤𝑏d1∤b, then the original equation has no solution. Otherwise, divide both sides of the equation by 𝑑1d1:

    𝑎𝑑1⋅𝑎𝑥−1≡𝑏𝑑1(mod𝑚𝑑1)ad1⋅ax−1≡bd1(modmd1)

    If 𝑎a and 𝑚𝑑1md1 are still not coprime, divide again. Let 𝑑2 =(𝑎,𝑚𝑑1)d2=(a,md1). If 𝑑2 ∤𝑏𝑑1d2∤bd1, then the equation has no solution; otherwise, divide both sides by 𝑑2d2:

    𝑎2𝑑1𝑑2⋅𝑎𝑥−2≡𝑏𝑑1𝑑2(mod𝑚𝑑1𝑑2)a2d1d2⋅ax−2≡bd1d2(modmd1d2)

    Similarly, keep judging until 𝑎 ⟂𝑚𝑑1𝑑2⋯𝑑𝑘a⟂md1d2⋯dk.

    Let 𝐷 =∏𝑘𝑖=1𝑑𝑖D=∏i=1kdi, then the equation becomes:

    𝑎𝑘𝐷⋅𝑎𝑥−𝑘≡𝑏𝐷(mod𝑚𝐷)akD⋅ax−k≡bD(modmD)

    Since 𝑎 ⟂𝑚𝐷a⟂mD, we deduce 𝑎𝑘𝐷 ⟂𝑚𝐷akD⟂mD. Thus 𝑎𝑘𝐷akD has an inverse. Putting it on the right side, this becomes a regular BSGS problem. After solving 𝑥 −𝑘x−k, add 𝑘k to get the solution to the original equation.

    Note that the solution may be less than or equal to 𝑘k, so before eliminating factors, do a Θ(𝑘)Θ(k) enumeration, directly verify 𝑎𝑖 ≡𝑏(mod𝑚)ai≡b(modm), so this situation can be avoided.

    Fast Discrete Logarithm Based on Range Preprocessing

    The previous BSGS algorithm has a time complexity of 𝑂(√𝑚)O(m) per query, which is inefficient when the number of queries is large. If the modulus for each solution is a fixed prime number 𝑝p, we have a fast algorithm based on range preprocessing.

    We already know ind𝑔⁡(𝑎𝑏) ≡ind𝑔⁡𝑎 +ind𝑔⁡𝑏(mod𝑝 −1)indg⁡(ab)≡indg⁡a+indg⁡b(modp−1), so we can compute discrete logarithms for all prime numbers through the BSGS algorithm, and the discrete logarithm of a composite can be transformed into the sum of several known prime discrete logarithms through this formula. At this time, the complexity is still not optimal. We only preprocess part of the discrete logarithms. Specifically, we preprocess the discrete logarithms from 11 to 𝐿 =⌊√𝑝⌋ +1L=⌊p⌋+1. Note that the BSGS block length 𝐵B cannot be 𝑂(√𝐿)O(L), because the preprocessing part of BSGS (inserting into the hash table) has complexity 𝑂(𝐵)O(B), and there are 𝑂(𝜋(𝐿))O(π(L)) queries in total. The total time complexity is 𝑂(𝐵+𝜋(𝐿)𝑝𝐵)O(B+π(L)pB). At this time, taking 𝐵 =𝑂(√𝜋(𝐿)𝑝)B=O(π(L)p) is optimal. By the Prime Number Theorem 𝜋(𝑛) ∼𝑛log⁡𝑛π(n)∼nlog⁡n, the total preprocessing time complexity can be balanced to 𝑂(𝑝3/4log1/2⁡𝑝)O(p3/4log1/2⁡p).

    Next is how to find the answer. Suppose we need to find ind𝑔⁡𝑦indg⁡y. If 𝑦 ≤𝐿y≤L, return directly. Otherwise, let 𝑝 =𝑣𝑦 +𝑟p=vy+r, then 𝑣 =⌊𝑝𝑦⌋ <𝐿v=⌊py⌋<L, 𝑟 =𝑝mod𝑦r=pmody, 𝑦 =𝑝−𝑟𝑣y=p−rv, thus:

    ind𝑔⁡𝑦≡ind𝑔⁡(𝑝−𝑟)−ind𝑔⁡𝑣≡ind𝑔⁡(−𝑟)−ind𝑔⁡𝑣≡ind𝑔⁡(𝑝−1)+ind𝑔⁡𝑟−ind𝑔⁡𝑣(mod𝑝−1).indg⁡y≡indg⁡(p−r)−indg⁡v≡indg⁡(−r)−indg⁡v≡indg⁡(p−1)+indg⁡r−indg⁡v(modp−1).

    Note that ind𝑔⁡(𝑝 −1) =(𝑝 −1)/2indg⁡(p−1)=(p−1)/2, so we only need to recursively compute the discrete logarithm of 𝑟r.

    #include <cmath>
#include <iostream>
#include <unordered_map>
using namespace std;

const int N = 1'000'000;  // sqrt(P * sqrt(P) / ln(P))

unordered_map<int, int> M;
int Lg[N], p[N], t;
bool vis[N];
int P, g, B, sq, LP_1, inv;

int fadd(int x, int y, int P) {
  x += y;
  if (x >= P) x -= P;
  return x;
}

int fsub(int x, int y, int P) {
  x -= y;
  if (x < 0) x += P;
  return x;
}

int fmul(int x, int y, int P) { return 1ll * x * y % P; }

int qpow(int x, int y) {
  int ans = 1;
  while (y) {
    if (y & 1) ans = fmul(ans, x, P);
    x = fmul(x, x, P);
    y >>= 1;
  }
  return ans;
}

int calc(int x) {
  int s = x;
  for (int i = 0; i <= P / B; ++i) {
    if (M.find(s) != M.end()) return i * B + M[s];
    s = fmul(s, inv, P);
  }
  return -1;
}

void init() {
  int s = 1;
  for (int i = 0; i < B; ++i) {
    if (M.find(s) != M.end()) break;
    M[s] = i, s = fmul(s, g, P);
  }
  inv = qpow(qpow(g, B), P - 2);
  for (int i = 2; i <= sq; ++i) {
    if (!vis[i]) {
      p[++t] = i;
      Lg[i] = calc(i);
    }
    for (int j = 1; j <= t && p[j] * i <= sq; ++j) {
      vis[p[j] * i] = true;
      Lg[p[j] * i] = fadd(Lg[p[j]], Lg[i], P - 1);
      if (i % p[j] == 0) break;
    }
  }
}

int solve(int y) {
  if (y <= sq) return Lg[y];
  int v = P / y, r = P % y;
  if (r < y - r) return fadd(fsub(solve(r), Lg[v], P - 1), LP_1, P - 1);
  return fsub(solve(y - r), Lg[v + 1], P - 1);
}

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  cin >> P >> g;
  sq = sqrt(P) + 1;
  B = sqrt(1ll * P * sqrt(P) / log(P));
  init();
  LP_1 = (P - 1) / 2;  // g ^ LP_1 = P - 1 (mod P)
  int T;
  cin >> T;
  while (T--) {
    int x;
    cin >> x;
    cout << solve(x) << '\n';
  }
  return 0;
}
