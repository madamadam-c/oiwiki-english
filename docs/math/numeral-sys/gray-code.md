Gray code is a binary numeral system in which any two consecutive numbers differ in only one binary digit. For example, the Gray code sequence for 3-bit binary numbers is:

$$
000,001,011,010,110,111,101,100
$$

Note that the sequence indices are zero-based, meaning $G(0)=000$ and $G(4)=110$.

Gray code was proposed by Frank Gray of Bell Labs in the 1940s and was patented in 1953.

## Constructing Gray Code (Transformation)

There are many methods for constructing Gray code. We will first introduce manual construction methods, then provide the implementation code along with a correctness proof.

### Manual Construction

$k$-bit Gray code can be constructed using the following method. Starting from the all-zero Gray code, follow this strategy:

1.  Flip the least significant bit to get the next Gray code (e.g., $000\to 001$).
2.  Flip the bit to the left of the rightmost $1$ to get the next Gray code (e.g., $001\to 011$).

Alternating between these two strategies for $2^{k-1}$ iterations yields the complete $k$-bit Gray code sequence.

### Mirror Construction

$k$-bit Gray code can be quickly obtained from $(k-1)$-bit Gray code by reflecting it vertically and prefixing the reflected part with new bits, as shown in the diagram:

$$
\begin{matrix}
k=1\\
0\\ 1\\\\\\\\\\\\\\
\end{matrix}
\to \begin{matrix}\\
\color{Red}0\\\color{Red}1\\\color{Blue}1\\\color{Blue}0\\\\\\\\\\
\end{matrix}
\to \begin{matrix}
k=2\\
{\color{Red}0}0\\{\color{Red}0}1\\{\color{Blue}1}1\\{\color{Blue}1}0\\\\\\\\\\
\end{matrix}
\to \begin{matrix}\\
\color{Red}00\\\color{Red}01\\\color{Red}11\\\color{Red}10\\\color{Blue}10\\\color{Blue}11\\\color{Blue}01\\\color{Blue}00
\end{matrix}
\to \begin{matrix}
k=3\\
{\color{Red}0}00\\{\color{Red}0}01\\{\color{Red}0}11\\{\color{Red}0}10\\{\color{Blue}1}10\\{\color{Blue}1}11\\{\color{Blue}1}01\\{\color{Blue}1}00
\end{matrix}
$$

### Calculation Method

Let's examine the relationship between the binary representation of $n$ and $G(n)$. We can see that the $i$-th bit of $G(n)$ is $1$ if and only if the $i$-th bit of $n$ is $1$ and the $(i+1)$-th bit is $0$, or the $i$-th bit of $n$ is $0$ and the $(i+1)$-th bit is $1$. This can be expressed as an XOR operation:

$$
G(n)=n\oplus \left\lfloor\frac{n}{2}\right\rfloor
$$

```cpp
int g(int n) { return n ^ (n >> 1); }
```

### Correctness Proof

We will now prove that in the Gray code sequence generated by the formula above, any two consecutive Gray codes differ in exactly one binary digit.

Consider the difference between $n$ and $n+1$. Adding $1$ to $n$ turns all consecutive $1$s at the end of $n$ into $0$s (flipping them), and turns the lowest $0$ into $1$. We can represent the binary digits of $n$ and $n+1$ as follows:

$$
\begin{aligned}
(n)_2 &= \cdots0\underbrace{11\cdots11}_{k\text{ ones}}\\
(n+1)_2 &= \cdots1\underbrace{00\cdots00}_{k\text{ zeros}}
\end{aligned}
$$

When computing $g(n)$ and $g(n+1)$, the last $k$ bits both become $\displaystyle\underbrace{100\cdots00}_{k\text{ bits}}$, while the $(k+1)$-th bit differs because $n$ and $n+1$ are identical except for the last $k+1$ bits. Thus the $(k+1)$-th bit either XORs with $1$ in both cases or XORs with $0$ in both cases. In either scenario, the $(k+1)$-th bit is different. The bits beyond the last $k+1$ perform the same XOR operation and therefore remain identical.

Q.E.D.

## Reconstructing the Original Number from Gray Code (Inverse Transformation)

Now we consider the inverse transformation of Gray code: given a Gray code $g$, find the original number $n$. We traverse from the most significant bit to the least significant bit of the binary representation (the least significant digit has index $1$, i.e., the units place; the most significant digit has index $k$). The relationship between the $i$-th bit of $n$ and the $i$-th bit $g_i$ of $g$ is:

$$
\begin{aligned}
n_k &= g_k \\
n_{k-1} &= g_{k-1} \oplus n_k &&= g_k \oplus g_{k-1} \\
n_{k-2} &= g_{k-2} \oplus n_{k-1} &&= g_k \oplus g_{k-1} \oplus g_{k-2} \\
n_{k-3} &= g_{k-3} \oplus n_{k-2} &&= g_k \oplus g_{k-1} \oplus g_{k-2} \oplus g_{k-3} \\
&\vdots\\
n_{k-i} &=\displaystyle\bigoplus_{j=0}^ig_{k-j}
\end{aligned}
$$

```cpp
int rev_g(int g) {
  int n = 0;
  for (; g; g >>= 1) n ^= g;
  return n;
}
```

## Practical Applications

Gray code has several useful and sometimes unexpected applications:

-   The $k$-bit Gray code sequence can serve as a Hamiltonian cycle on the vertices of a $k$-dimensional hypercube (a square in 2D, a unit vector in 1D), where each bit of the Gray code represents a coordinate along one dimension.

-   Gray code is used to minimize signal transmission errors in digital-to-analog converters (such as sensors) because only one bit changes at a time.

-   Gray code can be used to solve the Tower of Hanoi problem.

    Let the number of disks be $n$. We start from the $n$-bit all-zero Gray code $G(0)$ and move to the next Gray code in sequence ($G(i)$ moves to $G(i+1)$). The $i$-th binary digit of the current Gray code represents the $i$-th disk from smallest to largest.

    Since only one binary digit changes per step, when the $i$-th digit changes, we move the $i$-th disk. During disk movement, except for the smallest disk, any other disk has only one placement option when moving. When moving the smallest disk, we always have two placement options. Our strategy is as follows:

    If $n$ is odd, the disk movement path is $f\to t\to r\to f\to t\to r\to\cdots$, where $f$ is the starting peg, $t$ is the final peg where all disks are stacked, and $r$ is the auxiliary peg.

    If $n$ is even: $f \to r \to t \to f \to r \to t \to \cdots$.

-   Gray code is also used in genetic algorithm theory.
