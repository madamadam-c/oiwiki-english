**Note**: Considering the practical needs of algorithm contests, this article does not comprehensively cover the syntax. It only discusses parts that may be useful in algorithm contests.

This article uses the **C++11** standard as its syntax reference. When semantics differ, **C++11** is used as the baseline. C++14, C++17, and later syntax is mentioned when appropriate and explicitly marked.

## `auto` Type Specifier

The `auto` type specifier is used to automatically deduce the type of variables and similar entities. For example:

```cpp
auto a = 1;        // a is int
auto b = a + 0.1;  // b is double
```

Note that `auto` removes references. If you do not want copy overhead, specify the reference manually:

```cpp
int a = 1;
int& b = a;
auto c = b;   // c is int, with copy overhead
auto& e = a;  // e is int&, with no copy overhead
```

## decltype Specifier

`decltype` can infer a type from an **entity** or an **expression**. Note that these two cases deduce types differently, and incorrect use may create dangling references. It is not commonly used in contests, so this section only gives a brief introduction.

```cpp
#include <iostream>
#include <vector>

int main() {
  int a = 1926;
  decltype(a) b;                 // deduced from an entity; b is int
  decltype(1 + 1) c;             // deduced from an expression; c is int
  decltype((a)) d = a;           // deduced from an expression; d is int&!
  std::vector<decltype(b)> vec;  // deduced from an entity; vec is std::vector<int>
  return 0;
}
```

## Range-Based `for` Loops

Use range-based `for` to traverse iterable objects. It has the same efficiency as iterator-based traversal. Both are usually more efficient than index-based traversal because no indexed addressing is needed.

The following is the simple syntax of a range-based `for` loop:

```cpp
for (item_declaration : range_initializer) statement
```

For example:

```cpp
std::array<int, 4> arr = {1, 2, 3, 4};
for (int x : arr) {
  std::cout << x << std::endl;
}
```

The code generated by the syntax above is equivalent to the following:

```cpp
std::array<int, 4> arr = {1, 2, 3, 4};
for (auto px = arr.begin(), ed = arr.end(); px != ed; ++px) {
  std::cout << *px << std::endl;
}
```

### item-declaration

Declares a variable used to receive elements from the container on the right. The variable type must match the element type in the container. You can use `auto` for automatic type deduction. For complex types, `auto&` is often used to avoid copy overhead.

### range-initializer

The range initializer can be any iterable object, such as an array or a class object that defines `begin` and `end` member functions. If an expression is used, the expression is evaluated only once.

Examples:

```cpp
int a[] = {1, 1, 4, 5, 1, 4};
std::vector<int> b{1, 1, 4, 5, 1, 4};
std::map<std::string, int> c{{"114", 114}, {"514", 514}};
for (int i : a) std::cout << i;
for (auto i : b) std::cout << i;
// The type of i below is std::pair<const std::string, int>&
for (auto& i : c) std::cout << i.first << i.second;
for (auto i : {1, 1, 4, 5, 1, 4}) std::cout << i;
```

### Supporting Range-Based `for` for Custom Types

You only need to provide `begin` and `end` member functions. Their return type must support comparison, increment, and dereference with the `*` operator.

Here is an example:

```cpp
#include <iostream>

struct C {
  int a[4];

  int* begin() { return a; }

  int* end() { return a + 4; }
};

int main() {
  C c = {1, 9, 2, 6};
  for (auto i : c) std::cout << i << " ";
  std::cout << std::endl;
  // output: 1 9 2 6
  return 0;
}
```

### Init-Statement (C++20)

C++20 also allows an init-statement, which can be used for features such as a loop counter:

```cpp
#include <iostream>
#include <vector>

int main() {
  std::vector<int> v = {0, 1, 2, 3, 4, 5};

  for (int counter = 0; auto i : v)  // the init-statement (C++20)
    std::cout << counter++ << ' ' << i << std::endl;
}
```

## Structured Bindings (C++17)

Structured binding is syntactic sugar provided by C++17. It conveniently extracts subobjects or references to subobjects, like this:

```cpp
struct C {
  int x{1}, y{2};
};

int arr[]{4, 5, 6};

auto [c1, c2] = C{};       // c1=1,c2=2; int type
auto& [a1, a2, a3] = arr;  // a1=arr[0],a2=arr[1],a3=arr[2]; int& type
```

Note the following:

-   The number of variables declared on the left must match the number of subobjects in the object on the right.
-   The type declaration must use `auto`.
-   You can use `&` to obtain references.

When traversing a `map` container, you can write:

```cpp
std::map<std::string, int> m = {{"k1", 1}, {"k2", 2}};

// Use "auto&" with no copy overhead
for (auto& [k, v] : m) {
  // k has type const std::string&, because keys are const-qualified
  // v has type int&
  std::cout << k << ' ' << v << std::endl;
}
```

## std::tuple

[`std::tuple`](https://en.cppreference.com/w/cpp/utility/tuple), defined in the header `<tuple>`, generalizes `std::pair` and can store multiple values of different types. Here is an example:

```cpp
#include <iostream>
#include <tuple>
#include <vector>

constexpr auto expr = 4 - 1;  // expr = 3

int main() {
  std::vector<int> vec = {1, 9, 2, 6, 0};
  std::tuple<int, int, std::string, std::vector<int>> tup =
      std::make_tuple(817, 114, "514", vec);

  // Use get<> to access a subobject; the angle brackets require an integral constant expression
  for (auto i : std::get<expr>(tup)) std::cout << i << " ";
  // Elements are numbered from 0, so std::get<3> gives us a std::vector<int>
  return 0;
}
```

Since C++17, structured bindings can be used to extract values:

```cpp
std::vector<int> vec = {1, 9, 2, 6, 0};
std::tuple<int, int, std::string, std::vector<int>> tup =
    std::make_tuple(817, 114, "514", vec);

auto& [a, b, c, d] = tup;  // C++17 Structured binding
std::cout << a << ' ' << b << c << std::endl;
std::cout << d.size() << ' ' << d[2] << std::endl;
```

### Member Functions

| Function    | Purpose                                            |
| ----------- | -------------------------------------------------- |
| `operator=` | Assigns the contents of one `tuple` to another     |
| `swap`      | Swaps the contents of two `tuple` objects          |

Example:

```cpp
constexpr std::tuple<int, int> tup = {1, 2};
std::tuple<int, int> tupA = {2, 3}, tupB;
tupB = tup;
tupB.swap(tupA);
```

### Non-Member Functions

| Function         | Purpose                                                             |
| ---------------- | ------------------------------------------------------------------- |
| `make_tuple`     | Creates a `tuple` object whose type is determined by the arguments  |
| `std::get`       | Tuple-like access to a specified element                            |
| `std::tie`       | Assigns tuple values to existing variables                          |
| `operator==` etc | Compares values in a `tuple` lexicographically                      |
| `std::swap`      | Specialized `std::swap` algorithm                                   |

Example:

```cpp
std::tuple<int, int> tupA = {2, 3}, tupB;
tupB = std::make_tuple(1, 2);
std::swap(tupA, tupB);
std::cout << std::get<1>(tupA) << std::endl;
int x;
std::tie(x, std::ignore) = tupB;
std::cout << x << std::endl;
```

`std::tie` assigns tuple elements to existing variables, and `std::ignore` can be used to skip unwanted elements. Structured bindings directly declare new variables, support value or reference binding, and must accept all elements.

## Function Objects

An object that can use the function call operator `operator()` is called a function object (FunctionObject).

It is not a language feature, but rather a [concept or requirement](https://en.cppreference.com/w/cpp/named_req/FunctionObject) that is widely used in the standard library.

Function objects can roughly be divided into two categories:

1.  Function pointers
2.  Class objects that overload `operator()`

[lambda](./lambda.md) is a typical example of the second category. It stores captured contents in member variables and overloads the function call operator.

## std::function

???+ warning "Pay attention to performance overhead"
    `std::function` introduces some performance overhead. According to the [benchmark](./lambda.md#recursion-in-lambda), it usually causes a performance loss of 2 to 3 times or more.
    
    This is because it uses type erasure, which is usually implemented through virtual functions. Calling virtual functions introduces additional [overhead](https://stackoverflow.com/questions/5057382/what-is-the-performance-overhead-of-stdfunction).
    
    Consider using [**Lambda Expressions**](./lambda.md) or [**function objects**](#function-objects) instead.

`std::function` is a general-purpose function wrapper defined in the header `<functional>`.

An instance of `std::function` can store, copy, and call any [**Callable**](https://en.cppreference.com/w/cpp/named_req/Callable) object, including [**Lambda Expressions**](./lambda.md), member function pointers, or other [**function objects**](#function-objects).

If a `std::function` contains no callable object, such as after default construction, calling it throws a [`std::bad_function_call`](https://en.cppreference.com/w/cpp/utility/functional/bad_function_call) exception.

```cpp
#include <functional>
#include <iostream>

struct Foo {
  Foo(int num) : num_(num) {}

  void print_add(int i) const { std::cout << num_ + i << '\n'; }

  int num_;
};

void print_num(int i) { std::cout << i << '\n'; }

struct PrintNum {
  void operator()(int i) const { std::cout << i << '\n'; }
};

int main() {
  // Store a free function
  std::function<void(int)> f_display = print_num;
  f_display(-9);

  // Store a lambda
  std::function<void()> f_display_42 = []() { print_num(42); };
  f_display_42();

  // Store a call to a member function
  std::function<void(const Foo&, int)> f_add_display = &Foo::print_add;
  const Foo foo(314159);
  f_add_display(foo, 1);
  f_add_display(314159, 1);

  // Store a call to a data member accessor
  std::function<int(Foo const&)> f_num = &Foo::num_;
  std::cout << "num_: " << f_num(foo) << '\n';

  // Store a call to a function object
  std::function<void(int)> f_display_obj = PrintNum();
  f_display_obj(18);
}
```

## Variadic Function Templates

Before C++11, class templates and function templates could only accept a fixed number of template parameters. C++11 allows **any number and any type** of template parameters.

Only variadic **function** templates are briefly introduced here.

The following code declares a function template `fun` that can accept any number and any type of template parameters as its template parameters.

```cpp
template <typename... Clazz>
void fun(Clazz... paras) {}
```

`paras` is a function parameter pack, accepting zero or more function arguments. `Clazz` is a template parameter pack, accepting zero or more template arguments, whether non-type, type, or template arguments. When marked with `typename`, it accepts only types.

You can understand it simply as follows:

-   A template parameter pack is usually a group of type names, though it may also use compile-time constants or template names.
-   A function parameter pack is usually a group of variable names.

Now the `fun` function can be called like this:

```cpp
fun();
fun(1);
fun(1, 2, 3);
fun(1, 0.0, "abc");
```

### Parameter Pack Expansion

#### Parameter Pack Expansion Syntax

Parameter pack expansion is very simple: use `...`, and the expanded items are automatically separated by `,`. For example:

```cpp
template <class A, class... C>
void func(A arg1, C... arg2) {
  // C is a template parameter pack
  tuple<A, C...>();  // expands to tuple<int, int, double, bool>();

  // arg2 is a function parameter pack
  func(arg2...);  // expands to func( 2, 1.1, true );
}

func(1, 2, 1.1, true);
```

Expansion can also include required operations, for example:

```cpp
template <class A, class... C>
void func(A arg1, C... arg2) {
  func((arg2 + 1)...);
  // expands to func( (2+1) , (1.1+1), (2.1f+1) );
}

func(1, 2, 1.1, 2.1f);
```

#### Terminating Function

The function above cannot run because the number of parameters keeps decreasing and eventually becomes an empty argument list, causing an error.

We need to specify a termination condition. A normal function can be provided like this:

```cpp
void func() {}

template <class A, class... C>
void func(A arg1, C... arg2) {
  std::cout << arg1 << std::endl;
  func((arg2 + 1)...);
}

func(1, 2, 1.1, 2.1f);
```

In this way, when the number of arguments is nonzero the template is called, and when the argument list is empty the normal function is called, so the program runs correctly.

### Fold Expressions (C++17)

C++17 provides a convenient syntax for processing a **function parameter pack**. Its syntax is as follows and must be wrapped in parentheses:

1.  `( pack op ... )`, which becomes `(E1 op (... op (EN-1 op EN)))`
2.  `( ... op pack )`, which becomes `(((E1 op E2) op ...) op EN)`
3.  `( pack op ... op init )`, which becomes `(E1 op (... op (EN−1 op (EN op I))))`
4.  `( init op ... op pack )`, which becomes `((((I op E1) op E2) op ...) op EN)`

A simple demonstration makes it easier to understand:

```cpp
template <class... C>
void func(C... args) {
  (std::cout << ... << args) << std::endl;
  // Syntax 4, equivalent to:
  // ( ( ( std::cout << 1 ) << 2.1 ) << true ) << std::endl;
  // Output: 12.11. Note that true is printed as 1 because boolalpha is not specified here

  std::cout << (args && ...) << std::endl;
  // Syntax 1, equivalent to:
  // std::cout << ( 1 && ( 2.1 && true ) ) ) << std::endl;
  // Output: 1
}

func(1, 2.1, true);
```

### Abbreviated Function Templates (C++20)

Since C++20, you can directly use `auto ...` as parameter types to write an abbreviated function template:

```cpp
void func(auto... args) { (std::cout << ... << args) << std::endl; }
```

Note that it is still essentially a function template, equivalent to the following:

```cpp
template <class... T>
void func(T... args) {
  (std::cout << ... << args) << std::endl;
}
```

## Ranges Library (C++20)

> The ranges library is an extension of the iterator and generic algorithm libraries. It makes iterators and algorithms more powerful through composition and reduces errors.

A range is a traversable sequence, including arrays, containers, views, and so on.

When complex operations need to be performed on containers or other ranges, the [ranges library](https://en.cppreference.com/w/cpp/ranges) can make algorithms easier and clearer to write.

### Views

A view is a lightweight object that implements algorithms through specific mechanisms, such as custom iterators, and provides more ways to traverse ranges to meet different needs.

The ranges library has implemented several commonly used views, roughly divided into two kinds:

1.  **Range factories**, which construct special ranges. Using these factories avoids manually constructing containers, reduces overhead, and directly generates a range.
2.  **Range adaptors**, which provide varied traversal support. They can be called like functions or connected with the pipe operator `|` for chained calls.

As [**RangeAdaptorClosureObject**](https://en.cppreference.com/w/cpp/named_req/RangeAdaptorClosureObject)s, **range adaptors** are also [**function objects**](#function-objects). They overload `operator|`, allowing them to be assembled like pipelines.

??? note "Pipe operator"
    The `|` here should be understood as a pipe operator rather than a bitwise OR operator. This usage comes from [pipes](https://en.wikipedia.org/wiki/Pipeline_(Unix)) in Linux.

Even in complex operations, readability can be maintained. It has the following property:

If A, B, and C are range adaptor closure objects, R is a range, and the other letters are possible valid arguments, the expression

    R | A(a) | B(b) | C(c, d)

is equivalent to

    C(B(A(R, a), b), c, d)

The following uses `ranges::take_view` and `ranges::iota_view` as examples:

```cpp
#include <iostream>
#include <ranges>

int main() {
  const auto even = [](int i) { return 0 == i % 2; };

  for (int i : std::views::iota(0, 6) | std::views::filter(even))
    std::cout << i << ' ';
}
```

1.  The range factory `std::views::iota(0, 6)` generates a range of integers from 0 to 5.
2.  The range adaptor `std::views::filter(even)` filters the previous range and generates a range containing only even numbers.
3.  The two operations are linked with the pipe operator.

The code above does not allocate additional heap space to store the range generated at each step. The actual generation and filtering happen during traversal, more specifically during internal iterator construction, increment, and dereference, so it has zero overhead.

At the same time, the lifetime of elements inside a **range adaptor** is the same as the lifetime of the external input range. If the external range, such as a container or range factory, has already been destroyed, then traversing these views is equivalent to dereferencing a dangling pointer and is undefined behavior.

To avoid this, the lifetime of an adaptor should strictly be within the lifetime of any range it uses.

???+ note "When the range is destroyed, all elements in the view dangle"
    ```cpp
    #include <iostream>
    #include <ranges>
    #include <vector>
    
    using namespace std;
    
    int main() {
      auto view = [] {
        vector<int> vec{1, 2, 3, 4, 5};
        return vec | std::views::filter([](int i) { return 0 == i % 2; });
      }();
    
      for (int i : view) cout << i << ' ';  // runtime undefined behavior
    
      return 0;
    }
    ```

### Constrained Algorithms

> C++20 provides constrained versions of most algorithms in namespace std::ranges. They can specify ranges using iterator-sentinel pairs or a single range argument, and support projections and pointer-to-member callable objects. It also changes the return types of most algorithms to return all potentially useful information computed during algorithm execution.

These algorithms can be understood as improved versions of the old standard library algorithms. They are all function objects and provide friendlier overloads and argument type checks, based on [`concept`](https://en.cppreference.com/w/cpp/language/constraints). Let us first compare `std::sort` and `ranges::sort` as an example:

```cpp
#include <algorithm>
#include <iostream>
#include <vector>

using namespace std;

int main() {
  vector<int> vec{4, 2, 5, 3, 1};

  sort(vec.begin(), vec.end());  // {1, 2, 3, 4, 5}

  for (const int i : vec) cout << i << ", ";
  cout << '\n';

  ranges::sort(vec, ranges::greater{});  // {5, 4, 3, 2, 1}

  for (const int i : vec) cout << i << ", ";

  return 0;
}
```

`ranges::sort` and `sort` have the same algorithm implementation, but `ranges::sort` provides range-based overloads, making arguments more concise. Most other algorithms in namespace `std` also have corresponding range overloads in namespace `ranges`.

Using these range arguments together with the views from the previous section allows us to keep code readable while performing complex operations. Here is an example:

```cpp
#include <algorithm>
#include <array>
#include <iostream>
#include <ranges>

using namespace std;

int main() {
  const auto& inputs = views::iota(0u, 9u);  // produce the integer sequence from 0 to 8
  const auto& chunks = inputs | views::chunk(3);  // split the sequence into chunks of 3 elements
  const auto& cartesian_product =
      views::cartesian_product(chunks, chunks);  // compute the Cartesian product of the chunks with themselves

  for (const auto [l_chunk, r_chunk] : cartesian_product)
    // Compute the sum of integers in the two chunks from the Cartesian product
    cout << ranges::fold_left(l_chunk, 0u, plus{}) +
                ranges::fold_left(r_chunk, 0u, plus{})
         << ' ';
}
```

???+ note "Output:"
    6 15 24 15 24 33 24 33 42
