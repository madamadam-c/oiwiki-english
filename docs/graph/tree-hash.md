When determining whether some trees are isomorphic, we often convert these trees into hash values for storage to reduce complexity.

Tree hashing is very flexible and can be designed in various ways; however, if designed arbitrarily, it is likely to be incorrect and may be cracked. The following introduces a type of method that is easy to implement and not easily cracked.

## Method

This type of method requires a hash function for multisets. The hash value of a subtree rooted at a node is the hash value of the multiset formed by the hash values of all its children as roots, i.e.:

$$
h_x = f(\{ h_i \mid i \in son(x) \})
$$

where $h_x$ denotes the hash value of the subtree rooted at $x$, and $f$ is the hash function for multisets.

Using the hash function used in the code as an example:

$$
f(S) = \left( c + \sum_{x \in S} g(x) \right) \bmod m
$$

where $c$ is a constant, typically just use $1$. $m$ is the modulus, typically use $2^{32}$ or $2^{64}$ for natural overflow, or use a large prime. $g$ is an integer-to-integer mapping, the code uses xor shift, but other functions can also be used; however, polynomials are not recommended. To prevent the problem setter from cracking xor hash, a random constant can be XORed before and after the mapping.

This hash is very easy to write. If root changing is needed, in the second DP, we only need to subtract the subtree hash.

### [BJOI2015] Tree Isomorphism

The isomorphism referred to in this problem is for rooted trees, while the method introduced above is for rooted trees. Therefore, only when the roots are the same will two non-isomorphic rooted trees have the same hash value. Since the data range is small, we can brute-force compute the hash value for each vertex as the root, sort them, and compare.

If the data range is large, we can also use root-changing DP to traverse the tree twice to compute the hash value for each vertex as the root. We can also use the multiset hash function above: store the hash values for each vertex as root into a multiset, then compute the hash value of the multiset for comparison (method one).

We can also optimize the complexity by finding the centroid. A tree has at most two centroids, so we only need to compute the hash values with them as roots. Then, we can either compare these hash values separately (method two), or take one centroid's hash value as the whole tree's hash value when there is one centroid, or take the smaller (or larger) when there are two centroids.

### HDU 6647 Bracket Sequences on Tree

The problem asks for the number of essentially different bracket sequence schemes generated by traversing a rooted tree.

First, it can be noted that two different non-isomorphic rooted trees will definitely not generate the same bracket sequence. We first consider the number of essentially different bracket sequence schemes that can be generated by traversing a rooted tree. Suppose the root of the subtree we are considering is $u$, and let $f(u)$ denote the number of schemes for this subtree. Starting from $u$, we can choose any order to traverse downward, producing $|son(u)|!$ permutations. For each child vertex $v$, its subtree has $f(v)$ schemes. Therefore, $f(u) = |son(u)|! \cdot \prod_{v \in son(u)} f(v)$. However, isomorphic subtrees will cause duplicates, so $f(u)$ needs to divide by the product of factorials of the occurrences of each essentially different subtree, similar to permutations of multisets.

Through the above DP, we can compute the number of schemes for the root node. Then, through root-changing DP, transfer the hash value and scheme information from the parent node to the child node to compute the hash value and number of schemes with each node as the root. Each different subtree only needs to be counted once.
