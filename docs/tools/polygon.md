This page briefly introduces the multi-person collaborative problem creation platform Polygon.

## Introduction

### What is Polygon

Website: [Index Page - Polygon](https://polygon.codeforces.com)

Polygon is a problem creation platform that supports multi-person collaboration with very complete functionality. The official description is "Polygon provides a platform for creation of programming contest problems."

To create problems on Codeforces (CF), you must use Polygon. When creating problems elsewhere, especially for multi-person collaboration, using Polygon is also a good choice.

### Advantages

-   There is a version control system, so when multiple people collaborate it won't become a mess, and there is no need to pass files to each other.

-   The problem creation system is complete, validator, generator, checker, and solutions are tightly integrated, and output is automatically generated.

-   You can set tags for solutions, both wrong solutions AC and correct solutions not AC will give warnings, making it convenient to eliminate wrong solutions one by one.

-   You can easily do stress testing, and the generated data can be directly added to the problem data.

-   If problems are found, you can create issues, without being flooded by messages but never having a fix.

-   Prepare for future CF problem creation.

## Problem List

The problem list displays basic information about a problem, such as the statement, solution writing status, data generation status, and std, validator, and checker settings.

You can double-click the "Name" column in the problem list to write notes, such as things you need to remind yourself to do (need to add more tests/need to write tutorial), or the planned score distribution for this problem. You can fill in according to your needs, or leave it empty.

In "Rev.", "x/y" means x is the current problem version, and y is the package version. If they are different, y will be displayed in red.

In "Edit session", "Start" means your account hasn't viewed this problem yet, "Continue (x) Discard" means your account is at the x-th version of this problem. Clicking "Start" or "Continue (x)" will enter the problem management interface, clicking "Discard" will **irreversibly** discard all your changes and return to the state of not having viewed this problem.

If your account has unsubmitted changes for a problem, the entire row for that problem in the problem list will turn red.

### General Info

On this page, you can set the problem's time limit, memory limit, problem type, problem tags, and contest.

At the bottom of the page, "statement sketch" and "tutorial sketch" can edit **drafts** of the statement and solution. Note that these two items will not appear on the official statement or solution.

### Statement

This page is used to write the statement and solution. You can also use the "Review" button to view the statement, validator, and checker, generally used for review.

Both the statement and solution need to use TeX syntax, Markdown cannot be used. For example, you need to use `\textbf{text}` instead of `**text**`. However, what Polygon actually supports is a very small subset of TeX, you can try it yourself.

You can use the "In HTML" link at the very top to view the rendered statement, and "Tutorial in HTML" to view the rendered solution.

If you need to add images in the statement, you need to first upload the image in "Statement Resource Files" below, then add `\includegraphics{filename.png}` in the statement.

### Files

"Source Files" is used to store code **other than solutions**, such as validators, checkers, generators, and interactors for IO-style interactive problems.

If these codes need to include other files, for example [Tree-Generator](https://github.com/ouuan/Tree-Generator), they need to be placed in "Resource Files".

For grader-style interactive problems, see the [official tutorial](https://codeforces.com/blog/entry/66916).

### Checker

testlib.h provides some built-in checkers, with brief introductions in the selection box. You can also select and then click "View source" to view the source code.

If you need to write your own checker, please refer to the [checker tutorial](./testlib/checker.md).

The "Checker tests" below is used to add several groups of outputs and their corresponding expected evaluation results through "Add test", then click "Run tests" to test whether the checker correctly returns the evaluation results.

### Interactor

Only IO-style interactive problems need this, please refer to the [interactor tutorial](./testlib/interactor.md).

### Validator

Validators are used to check data legality. For writing, please refer to the [validator tutorial](./testlib/validator.md).

The "Validator tests" below is similar to "Checker tests", it needs to provide input and whether it is expected to be legal, used to test the validator.

### Tests

This page is used to manage data.

On Polygon, the recommended approach is to use a small number of [generators](./testlib/generator.md) with **command line parameters** to generate data, rather than writing a bunch of generators or modifying the generator for each group of data generated. And, you only need to generate input, output will be automatically generated.

"Testset" is a test set. If creating problems for CF, you need to manually add "pretests" as a Testset, and "pretests" needs to be a subset of "tests".

"Add Test" is used to manually add a group of data, generally used for manually inputting samples or smaller data. Although you can upload data through files, this is **not recommended**, data should either be manually input or generated by a generator with some parameters.

If "Use in statements" is checked, this group of data will become a sample and automatically added to the statement. If you need the statement to display something other than the sample's input/output (generally used for interactive problems), you can click "If you want to specify custom content of input or output data for statements click here", then input what you want to display in the statement.

The bottom of the Tests page is used to input scripts for generating data, such as `generator-name [params] > test-index`. You can use `generator-name [params] > $`, so you don't need to manually specify the test point number.

You can refer to the [tutorial provided by Polygon](https://polygon.codeforces.com/docs/freemarker-manual) to use Freemarker to batch generate scripts.

"Preview Tests" can preview the generated data.

### Stresses

This page is used for stress testing.

Click "Add Stress" to add a group of stress testing. "Script pattern" is a script for generating data, where you can use things like "[10..100]" to represent randomly selecting within a range.

Then run the stress testing. If an error is found, it will display "Crashed", and you can add this group of data to Tests with one click.

### Solution Files

This page is used to put code for solving this problem, it can be correct solutions or wrong solutions. Uploading wrong solutions can conveniently eliminate them, or remind yourself that you need to eliminate them.

### Invocations

This page is used to run solutions.

Select the code and test points to run, then you can click into the list ("View") to view detailed information.

The evaluation status "FL" means evaluation error, generally the data didn't pass validate or the validator/checker/interactor had an RE. "RJ" has two situations: one is "FL", the other is this code didn't pass the first test point.

If the time used is between half and twice the limit, it will be marked in yellow.

If there are variables in the data that don't reach the minimum or maximum value, it will remind at the bottom.

### Issues

Used to create issues.

### Packages

Package contains all information about a problem. When creating problems for CF, it is the basis for CF evaluation (for example, if you need to fix problems during the contest, only updating the package will affect CF). At other times, it can be used for export.

"Verify" tests that all solutions match their tags (AC, WA, TLE), and that the checker passes checker tests, and the validator passes validator tests.

### Manage access

Manage problem permissions.

### Sidebar

The first section displays some basic information. If anything doesn't conform to the specification (such as tests not containing pretests, duplicate test points), it will be displayed in yellow, and hovering the mouse will show specific information.

"View changes" can view the history of modifications. Note that "switch" cannot be used to roll back to a certain version, it can only be used to make non-conflicting modifications on top of a certain version, which is actually meaningless, so switch is essentially equivalent to read-only.

"Update Working Copy" is to get (others') updates.

"Commit Changes" is to submit your updates.

When committing, if there are non-standard items that need warnings, they will be listed.

## Contest Management

If you want to create a contest, you can create it through "New Contest", which makes it more convenient to manage problems.

The "Add problems?" in the upper right of the problem list in the contest management page is to add an existing problem to the contest.

The sidebar's "New problem" is to create a new problem and add it to the contest.

The "Manage problem access" above is to view each problem's permissions, and the "Manage developers list" below is to manage people who have access to this contest. Creating a problem through "New problem" and adding a new developer will automatically add permissions, but problems added through "Add problems?" will not give existing developers permissions.

The sidebar can also preview all statements, all solutions, all validators & checkers, download the entire contest package, and renumber problems.

## Conflict Resolution

When multiple people collaborate using Polygon to create problems, if the current modified problem version is different from the remote problem version, and when fetching the latest version from remote or submitting updates, the modified files cannot be automatically merged, a conflict (Conflicted) will occur.

After a conflict occurs, Polygon will provide a "Resolve conflicts" option in the conflicted problem options, where users can resolve the conflicts for conflicted files.
