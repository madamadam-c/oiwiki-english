    Sqrt Tree

    Introduction

    Given a sequence ⟨𝑎𝑖⟩𝑛𝑖=1⟨ai⟩i=1n of length n and an associative operation ∘∘ (for example, gcd,min,max, +,and,or,xorgcd,min,max,+,and,or,xor are all associative), each range query [𝑙,𝑟][l,r] asks us to compute 𝑎𝑙 ∘𝑎𝑙+1 ∘⋯ ∘𝑎𝑟al∘al+1∘⋯∘ar.

    A Sqrt Tree can be preprocessed in 𝑂(𝑛log⁡log⁡𝑛)O(nlog⁡log⁡n) time and answer queries in 𝑂(1)O(1) time.

    Explanation

    Blocking The Sequence

    First split the whole sequence into 𝑂(√𝑛)O(n) blocks, each of size 𝑂(√𝑛)O(n). For each block, compute:

    1. Prefix range answers 𝑃𝑖Pi inside the block.
    2. Suffix range answers 𝑆𝑖Si inside the block.
    3. An additional array ⟨𝐵𝑖,𝑗⟩⟨Bi,j⟩ denoting the range answer from block 𝑖i to block 𝑗j.

    For example, suppose ∘∘ is addition ++ and the sequence is {1,2,3,4,5,6,7,8,9}{1,2,3,4,5,6,7,8,9}.

    First split the sequence into three blocks: {1,2,3},{4,5,6},{7,8,9}{1,2,3},{4,5,6},{7,8,9}.

    The prefix and suffix range answers of each block are

    𝑃1={1,3,6},𝑆1={6,5,3}𝑃2={4,9,15},𝑆2={15,11,6}𝑃3={7,15,24},𝑆3={24,17,9}P1={1,3,6},S1={6,5,3}P2={4,9,15},S2={15,11,6}P3={7,15,24},S3={24,17,9}

    The 𝐵B array is:

    𝐵=⎡⎢ ⎢⎣62145015390024⎤⎥ ⎥⎦B=[62145015390024]

    (For invalid cases with 𝑖 >𝑗i>j, assume the answer is 0.)

    Clearly these values can be preprocessed in 𝑂(𝑛)O(n) time, and the space complexity is also 𝑂(𝑛)O(n). After preprocessing, they answer cross-block queries in 𝑂(1)O(1) time. Queries whose whole interval lies in one block still cannot be handled, so more structure is needed.

    Building A Tree

    A natural idea is to recursively build the same structure inside every block to support in-block queries. For a block of size 11, queries can be answered in 𝑂(1)O(1) time. This builds a tree where each node represents an interval of the sequence. Leaf intervals have length 11 or 22. A node of size 𝑘k has 𝑂(√𝑘)O(k) children, so the whole tree has height 𝑂(log⁡log⁡𝑛)O(log⁡log⁡n), and the total interval length on each level is 𝑂(𝑛)O(n). Thus the construction complexity is 𝑂(𝑛log⁡log⁡𝑛)O(nlog⁡log⁡n).

    Proof Of The Tree Height

    By definition, for 𝑛n elements, let 𝑇(𝑛)T(n) be the height of the subtree that controls them. Then

    𝑇(𝑛)=𝑇(√𝑛)+1T(n)=T(n)+1

    Substitute 𝑛 =2𝑚n=2m:

    𝑇(2𝑚)=𝑇(2𝑚2)+1T(2m)=T(2m2)+1

    Define 𝑆(𝑚) =𝑇(2𝑚)S(m)=T(2m). Then

    𝑆(𝑚)=𝑆(𝑚2)+1S(m)=S(m2)+1

    By the master theorem, 𝑆(𝑚) =𝑂(log⁡𝑚)S(m)=O(log⁡m), so 𝑇(𝑛) =𝑆(log⁡𝑛) =𝑂(log⁡log⁡𝑛)T(n)=S(log⁡n)=O(log⁡log⁡n).

    Now queries can be answered in 𝑂(log⁡log⁡𝑛)O(log⁡log⁡n) time. For a query [𝑙,𝑟][l,r], find the minimum-length node 𝑢u such that 𝑢u contains [𝑙,𝑟][l,r]. Then [𝑙,𝑟][l,r] must cross blocks in 𝑢u's block decomposition, so the answer can be computed in 𝑂(1)O(1) time. The total query complexity is 𝑂(log⁡log⁡𝑛)O(log⁡log⁡n) because the tree height is 𝑂(log⁡log⁡𝑛)O(log⁡log⁡n). This process can still be optimized.

    Optimizing Query Complexity

    One can binary search the height and test validity in 𝑂(1)O(1), reducing the complexity to 𝑂(log⁡log⁡log⁡𝑛)O(log⁡log⁡log⁡n). We can make it faster.

    Assume that:

    1. The size of every block is a power of 22.
    2. Block sizes are identical on the same level.

    To achieve this, append some 00 elements to the end of the sequence so that its length becomes a power of 22. Although some blocks may become twice as large as before, their size is still 𝑂(√𝑘)O(k), so preprocessing a decomposition is still 𝑂(𝑛)O(n).

    Now it is easy to determine whether a query interval is fully contained in one block. For interval [𝑙,𝑟][l,r] (0-indexed), write the endpoints in binary. For example, for 𝑘 =4,𝑙 =39,𝑟 =46k=4,l=39,r=46:

    𝑙=3910=1001112,𝑟=4610=1011102l=3910=1001112,r=4610=1011102

    On each level the interval length is fixed, and block sizes are also fixed (in this example 2𝑘 =24 =162k=24=16). These blocks fully cover the sequence, so the first block represents [0,15][0,15] (binary [0000002,0011112][0000002,0011112]), the second block represents [16,31][16,31] (binary [0100002,0111112][0100002,0111112]), and so on. Positions of elements in the same block differ only in the last 𝑘k bits (in this example 𝑘 =4k=4). The example's 𝑙,𝑟l,r also differ only in the last 𝑘k bits, so they are in the same block.

    Therefore we only need to check whether the two endpoints differ only in the last 𝑘k bits, i.e. 𝑙 ⊕𝑟 ≤2𝑘 −1l⊕r≤2k−1. We can quickly find the level containing the answer interval:

    1. For every 𝑖 ∈[1,𝑛]i∈[1,n], find 𝑖i's highest 11 bit.
    2. For a query [𝑙,𝑟][l,r], compute the highest set bit of 𝑙 ⊕𝑟l⊕r to determine the level.

    This lets us answer queries in 𝑂(1)O(1) time.

    Updating Elements

    Sqrt Tree supports updates. Both point updates and range updates can be supported.

    Point Updates

    Consider a point assignment 𝑎𝑥 =𝑣𝑎𝑙ax=val. We want to update the maintained information efficiently.

    Naive Implementation

    First consider what changes after one point update. For a node of length 𝑙l and its corresponding sequences ⟨𝑃𝑖⟩,⟨𝑆𝑖⟩,⟨𝐵𝑖,𝑗⟩⟨Pi⟩,⟨Si⟩,⟨Bi,j⟩, in ⟨𝑃𝑖⟩⟨Pi⟩ and ⟨𝑆𝑖⟩⟨Si⟩ only 𝑂(√𝑙)O(l) elements change, but in ⟨𝐵𝑖,𝑗⟩⟨Bi,j⟩ 𝑂(𝑙)O(l) elements change. Thus 𝑂(𝑙)O(l) elements are updated at this tree node. The point-update complexity on a Sqrt Tree is therefore 𝑂(𝑛 +√𝑛 +√√𝑛 +⋯) =𝑂(𝑛)O(n+n+n+⋯)=O(n).

    Replacing The B Array With A Sqrt Tree

    The bottleneck is updating the root's ⟨𝐵𝑖,𝑗⟩⟨Bi,j⟩. Replace the root's ⟨𝐵𝑖,𝑗⟩⟨Bi,j⟩ by another Sqrt Tree called 𝑖𝑛𝑑𝑒𝑥index. It has the same role as the original two-dimensional array: maintaining answers for whole-block ranges. Other non-root nodes still use ⟨𝐵𝑖,𝑗⟩⟨Bi,j⟩. If the root of a Sqrt Tree has an 𝑖𝑛𝑑𝑒𝑥index structure, call it indexed; if the root has a ⟨𝐵𝑖,𝑗⟩⟨Bi,j⟩ structure, call it unindexed. The 𝑖𝑛𝑑𝑒𝑥index tree itself is unindexed.

    Update the 𝑖𝑛𝑑𝑒𝑥index tree as follows:

    1. In 𝑂(√𝑛)O(n) time, update ⟨𝑃𝑖⟩⟨Pi⟩ and ⟨𝑆𝑖⟩⟨Si⟩.
    2. Update 𝑖𝑛𝑑𝑒𝑥index. Its length is 𝑂(𝑛)O(n), but only one element, representing the changed block, must be updated. This step costs 𝑂(√𝑛)O(n) with the naive algorithm.
    3. Enter the changed child and update its information with the naive algorithm in 𝑂(√𝑛)O(n) time.

    Query complexity remains 𝑂(1)O(1) because the 𝑖𝑛𝑑𝑒𝑥index tree is used at most once. Thus point-update complexity becomes 𝑂(√𝑛)O(n).

    Updating A Range

    Sqrt Tree also supports range assignment Update⁡(𝑙,𝑟,𝑥)Update⁡(l,r,x), which changes all numbers in [𝑙,𝑟][l,r] to 𝑥x. There are two implementations: one updates information in 𝑂(√𝑛log⁡log⁡𝑛)O(nlog⁡log⁡n) and queries in 𝑂(1)O(1); the other updates in 𝑂(√𝑛)O(n) but increases query time to 𝑂(log⁡log⁡𝑛)O(log⁡log⁡n).

    We can put lazy tags on a Sqrt Tree like on a segment tree. The difference is that pushing a node's lazy tag down can cost 𝑂(√𝑛)O(n), so instead of pushing tags during queries, we check whether a parent has a tag and push it then.

    First Implementation

    In the first implementation, only level-11 nodes (whose interval length is 𝑂(√𝑛)O(n)) receive lazy tags. When a tag is pushed down, the whole subtree is updated directly in 𝑂(√𝑛log⁡log⁡𝑛)O(nlog⁡log⁡n). The process is:

    1. For level-11 nodes fully covered by the modified interval, add a lazy tag.

    2. At most two blocks are only partially covered. Rebuild these two blocks in 𝑂(√𝑛log⁡log⁡𝑛)O(nlog⁡log⁡n) time. If a block already has a lazy tag, push it down while rebuilding.

    3. Update the root's ⟨𝑃𝑖⟩⟨Pi⟩ and ⟨𝑆𝑖⟩⟨Si⟩ in 𝑂(√𝑛)O(n) time.

    4. Rebuild the 𝑖𝑛𝑑𝑒𝑥index tree in 𝑂(√𝑛log⁡log⁡𝑛)O(nlog⁡log⁡n) time.

    To answer queries with lazy tags:

    1. If the query is contained in a block with a lazy tag, compute the answer from the tag.

    2. If the query spans multiple blocks, only the leftmost and rightmost incomplete blocks need special handling. Middle blocks are queried from the 𝑖𝑛𝑑𝑒𝑥index tree, because the 𝑖𝑛𝑑𝑒𝑥index tree is rebuilt after every update, in 𝑂(1)O(1) time.

    Thus query complexity remains 𝑂(1)O(1).

    Second Implementation

    In this implementation, every node may receive a lazy tag. When answering a query, we must consider lazy tags on ancestors, so query complexity becomes 𝑂(log⁡log⁡𝑛)O(log⁡log⁡n). Updates are faster:

    1. Add lazy tags to blocks fully covered by the modified interval in 𝑂(√𝑛)O(n) time.
    2. For partially covered blocks, update ⟨𝑃𝑖⟩⟨Pi⟩ and ⟨𝑆𝑖⟩⟨Si⟩ in 𝑂(√𝑛)O(n) time, since there are only two such blocks.
    3. Update the 𝑖𝑛𝑑𝑒𝑥index tree in 𝑂(√𝑛)O(n) time using the same update algorithm.
    4. For unindexed subtrees, update their ⟨𝐵𝑖,𝑗⟩⟨Bi,j⟩.
    5. Recursively update the two intervals that are not fully covered.

    The time complexity is 𝑂(√𝑛 +√√𝑛 +⋯) =𝑂(√𝑛)O(n+n+⋯)=O(n).

    SqrtTreeItem op(const SqrtTreeItem &a, const SqrtTreeItem &b);

int log2Up(int n) {
  int res = 0;
  while ((1 << res) < n) {
    res++;
  }
  return res;
}

class SqrtTree {
 private:
  int n, lg, indexSz;
  vector<SqrtTreeItem> v;
  vector<int> clz, layers, onLayer;
  vector<vector<SqrtTreeItem>> pref, suf, between;

  void buildBlock(int layer, int l, int r) {
    pref[layer][l] = v[l];
    for (int i = l + 1; i < r; i++) {
      pref[layer][i] = op(pref[layer][i - 1], v[i]);
    }
    suf[layer][r - 1] = v[r - 1];
    for (int i = r - 2; i >= l; i--) {
      suf[layer][i] = op(v[i], suf[layer][i + 1]);
    }
  }

  void buildBetween(int layer, int lBound, int rBound, int betweenOffs) {
    int bSzLog = (layers[layer] + 1) >> 1;
    int bCntLog = layers[layer] >> 1;
    int bSz = 1 << bSzLog;
    int bCnt = (rBound - lBound + bSz - 1) >> bSzLog;
    for (int i = 0; i < bCnt; i++) {
      SqrtTreeItem ans;
      for (int j = i; j < bCnt; j++) {
        SqrtTreeItem add = suf[layer][lBound + (j << bSzLog)];
        ans = (i == j) ? add : op(ans, add);
        between[layer - 1][betweenOffs + lBound + (i << bCntLog) + j] = ans;
      }
    }
  }

  void buildBetweenZero() {
    int bSzLog = (lg + 1) >> 1;
    for (int i = 0; i < indexSz; i++) {
      v[n + i] = suf[0][i << bSzLog];
    }
    build(1, n, n + indexSz, (1 << lg) - n);
  }

  void updateBetweenZero(int bid) {
    int bSzLog = (lg + 1) >> 1;
    v[n + bid] = suf[0][bid << bSzLog];
    update(1, n, n + indexSz, (1 << lg) - n, n + bid);
  }

  void build(int layer, int lBound, int rBound, int betweenOffs) {
    if (layer >= (int)layers.size()) {
      return;
    }
    int bSz = 1 << ((layers[layer] + 1) >> 1);
    for (int l = lBound; l < rBound; l += bSz) {
      int r = min(l + bSz, rBound);
      buildBlock(layer, l, r);
      build(layer + 1, l, r, betweenOffs);
    }
    if (layer == 0) {
      buildBetweenZero();
    } else {
      buildBetween(layer, lBound, rBound, betweenOffs);
    }
  }

  void update(int layer, int lBound, int rBound, int betweenOffs, int x) {
    if (layer >= (int)layers.size()) {
      return;
    }
    int bSzLog = (layers[layer] + 1) >> 1;
    int bSz = 1 << bSzLog;
    int blockIdx = (x - lBound) >> bSzLog;
    int l = lBound + (blockIdx << bSzLog);
    int r = min(l + bSz, rBound);
    buildBlock(layer, l, r);
    if (layer == 0) {
      updateBetweenZero(blockIdx);
    } else {
      buildBetween(layer, lBound, rBound, betweenOffs);
    }
    update(layer + 1, l, r, betweenOffs, x);
  }

  SqrtTreeItem query(int l, int r, int betweenOffs, int base) {
    if (l == r) {
      return v[l];
    }
    if (l + 1 == r) {
      return op(v[l], v[r]);
    }
    int layer = onLayer[clz[(l - base) ^ (r - base)]];
    int bSzLog = (layers[layer] + 1) >> 1;
    int bCntLog = layers[layer] >> 1;
    int lBound = (((l - base) >> layers[layer]) << layers[layer]) + base;
    int lBlock = ((l - lBound) >> bSzLog) + 1;
    int rBlock = ((r - lBound) >> bSzLog) - 1;
    SqrtTreeItem ans = suf[layer][l];
    if (lBlock <= rBlock) {
      SqrtTreeItem add =
          (layer == 0) ? (query(n + lBlock, n + rBlock, (1 << lg) - n, n))
                       : (between[layer - 1][betweenOffs + lBound +
                                             (lBlock << bCntLog) + rBlock]);
      ans = op(ans, add);
    }
    ans = op(ans, pref[layer][r]);
    return ans;
  }

 public:
  SqrtTreeItem query(int l, int r) { return query(l, r, 0, 0); }

  void update(int x, const SqrtTreeItem &item) {
    v[x] = item;
    update(0, 0, n, 0, x);
  }

  SqrtTree(const vector<SqrtTreeItem> &a)
      : n((int)a.size()), lg(log2Up(n)), v(a), clz(1 << lg), onLayer(lg + 1) {
    clz[0] = 0;
    for (int i = 1; i < (int)clz.size(); i++) {
      clz[i] = clz[i >> 1] + 1;
    }
    int tlg = lg;
    while (tlg > 1) {
      onLayer[tlg] = (int)layers.size();
      layers.push_back(tlg);
      tlg = (tlg + 1) >> 1;
    }
    for (int i = lg - 1; i >= 0; i--) {
      onLayer[i] = max(onLayer[i], onLayer[i + 1]);
    }
    int betweenLayers = max(0, (int)layers.size() - 1);
    int bSzLog = (lg + 1) >> 1;
    int bSz = 1 << bSzLog;
    indexSz = (n + bSz - 1) >> bSzLog;
    v.resize(n + indexSz);
    pref.assign(layers.size(), vector<SqrtTreeItem>(n + indexSz));
    suf.assign(layers.size(), vector<SqrtTreeItem>(n + indexSz));
    between.assign(betweenLayers, vector<SqrtTreeItem>((1 << lg) + bSz));
    build(0, 0, n, 0);
  }
};
