    WBLT

    introduce

    Weight Balanced Leafy Tree, hereinafter referred to as WBLT, is a balanced tree. Compared with other balanced trees, it has the main advantages of simple implementation and small constants. It supports interval operations and is durable.

    Weight Balanced Leafy Tree, as the name suggests, is a combination of Weight Balanced Tree and Leafy Tree.

    Each node of Weight Balanced Tree stores the size of the subtree under this node, and the tree height is guaranteed by keeping the size relationship between the left and right subtrees within a certain range.

    The original information maintained by Leafy Tree is only stored on the leaf nodes of the tree, while non-leaf nodes are only used to maintain child node information and maintain the shape of the data structure. The line segment tree we are familiar with is a Leafy Tree.

    The trees in this article all refer to binary Leafy Tree, that is, the number of child nodes of each node can only be 00 or 22. 𝑛n in this article refers to the number of leaf nodes of the tree. For a tree with 𝑛n leaf nodes, the total number of nodes is 2𝑛 −12n−1. Therefore, the space occupied by WBLT is Θ(𝑛)Θ(n).

    Basic structure and balance maintenance

    This section introduces the basic structure of WBLT, defines the concept of 𝛼α-balance of a tree, and explains how to maintain the balance of the tree through rotation or merging.

    Node information

    To implement a basic WBLT, you only need to record the following information for each node:

    • lc[x], rc[x]: left and right child nodes;
    • sz[x]: The number of leaf nodes in the subtree rooted at 𝑥x.

    To implement a balanced tree using WBLT, you also need to record key value-related information at each node:

    • val[x]: The key value at node 𝑥x.

    Because only leaf nodes actually store key values, the information stored at other nodes is merged from their child nodes to facilitate subsequent queries.

    For example, a common merging method is to store the larger key value of two child nodes in the node. In this way, each node stores the maximum value of the key values ​​of all leaf nodes in the subtree with it as the root. Based on this, the node information update method is as follows:

    concept of balance

    For a tree, its balance degree at a non-leaf node 𝑥x can be defined as

    𝜌(𝑥)=min{𝑤(𝑇left⁡(𝑥)),𝑤(𝑇right⁡(𝑥))}𝑤(𝑇𝑥).ρ(x)=min{w(Tleft⁡(x)),w(Tright⁡(x))}w(Tx).

    Among them, 𝑇𝑥Tx represents the subtree rooted at 𝑥x, 𝑤( ⋅)w(⋅) represents the weight of the subtree (the number of its leaf nodes), and left⁡(𝑥)left⁡(x) and right⁡(𝑥)right⁡(x) represent the left and right leaf nodes of 𝑥x respectively. In particular, 𝜌(𝑥) =1/2ρ(x)=1/2 is specified at leaf nodes.

    For 𝛼 ∈(0,1/2]α∈(0,1/2], if the balance degree of a node 𝑥x is 𝜌(𝑥) ≥𝛼ρ(x)≥α, the node is said to be ** 𝛼α -balanced**. A tree is said to be 𝛼α -balanced if every node in the tree is 𝛼α -balanced. The set of such trees is denoted 𝐵𝐵[𝛼]BB[α] . A tree is 𝛼α -balanced if and only if it itself is 𝛼α -balanced, and its left and right subtrees are both 𝛼α -balanced or it is a leaf node.

    The tree is 𝛼α -balanced, with the obvious benefit that its height is 𝑂(log⁡𝑛)O(log⁡n). This is because every time you move one step from a leaf node to the root, the number of leaf nodes contained in the subtree will be expanded to at least 1/(1 −𝛼)1/(1−α) times of the original, so it can only be moved 𝑂(log11−𝛼⁡𝑛) =𝑂(log⁡𝑛)O(log11−α⁡n)=O(log⁡n) times. This ensures that in a 𝛼α -balanced tree, the complexity of a single query is always strictly 𝑂(log⁡𝑛)O(log⁡n), and the constants of the algorithm are positively related to log⁡(1/(1−𝛼))log⁡(1/(1−α)) (based on 22). When 𝛼α is within the reasonable range provided below, this constant is approximately 2 ∼3.52∼3.5 .

    Balance maintenance of WBLT can usually be performed by rotating or merging. WBLT implemented in both ways, the complexity of single insertion, deletion and other operations is strictly 𝑂(log⁡𝑛)O(log⁡n). However, unlike the fixed-priority Treap, the structure of WBLT is not unique. Therefore, the structures of the trees maintained by the two methods are different, although this does not affect their use. Of course, balanced maintenance can also adopt a strategy similar to scapegoat tree, using refactoring to evenly amortize the complexity of 𝑂(log⁡𝑛)O(log⁡n), but this will lose the advantages of WBLT persistence and interval operations, so it is not recommended.

    The following describes the methods of maintaining balance through rotation and merging respectively, and implements the corresponding functions for balance maintenance and merging operations. After encapsulating these functions, there is no difference between the two methods of maintaining tree balance in the subsequent implementation of specific balanced trees. Moreover, no matter which method is used, the time complexity of a single operation of maintaining balance is 𝑂(1)O(1), and the complexity of a single merge of tree 𝑇1T1 and tree 𝑇2T2 is 𝑂(∣log⁡𝑤(𝑇1)𝑤(𝑇2)∣)O(|log⁡w(T1)w(T2)|).

    omit weight symbol

    In order to maintain the balance of the tree, only the weight information of the subtree needs to be retained. Therefore, for convenience of expression, the following two sections discussing balance maintenance will use the notation of a tree and its weights interchangeably. For example, the weight of subtree 𝑥x is also represented by 𝑥x instead of 𝑤(𝑥)w(x). Similarly, the tree obtained by merging subtrees 𝑥x and 𝑦y is also represented by its weight, which is directly written as tree 𝑥 +𝑦x+y.

The results of the two implementations are completely consistent, but the second implementation is more convenient for WBLT persistence.

    However, if 𝑤w itself is too heavy, such an operation may move too much weight to the right subtree, thus making the left subtree in the new tree too light, that is, 𝑧 <𝛼(𝑥 +𝑦)z<α(x+y). In this case, because the weights of subtree 𝑧z and subtree 𝑦y are too small, we can only consider splitting 𝑤w into two subtrees and connecting them to 𝑧z and 𝑦y respectively to become two subtrees of the new tree. This is equivalent to first rotating node 𝑤w to node 𝑥x, and then rotating it to the root node. Likewise, we can expect that the tree obtained in this way will reach equilibrium, with the shape shown in the upper tree in the figure.

    • When 𝑤 ≤𝛽𝑥w≤βx, the single-spin strategy should be selected;
    • When 𝑤 >𝛽𝑥w>βx, the double-spin strategy should be selected.

    𝜏(𝑇𝑖,𝑇′𝑖−1)∈𝑂(log⁡𝑤(𝑇′𝑖)𝑤(𝑇′𝑖−1))+𝑂(1).τ(Ti,Ti−1′)∈O(log⁡w(Ti′)w(Ti−1′))+O(1).

    From this, the total complexity of the merge is

    𝑂(ℓ∑𝑖=2(1+log⁡𝑤(𝑇′𝑖)𝑤(𝑇′𝑖−1)))⊆𝑂(ℓ+log⁡𝑤(𝑇′ℓ))⊆𝑂(log⁡𝑛).O(∑i=2ℓ(1+log⁡w(Ti′)w(Ti−1′)))⊆O(ℓ+log⁡w(Tℓ′))⊆O(log⁡n).

    This also shows that the total complexity of the splitting algorithm is 𝑂(log⁡𝑛)O(log⁡n).

constexpr double ALPHA = 0.292;

int id, rt, ch[N][2], sz[N], val[N];
int pool[N], top;

void push_up(int x) {
  sz[x] = sz[ch[x][0]] + sz[ch[x][1]];
  val[x] = val[ch[x][1]];
}

// Return a new empty node.
int new_node() {
  int x = top ? pool[--top] : ++id;
  sz[x] = val[x] = ch[x][0] = ch[x][1] = 0;
  return x;
}

// Release a node for later use.
void del_node(int& x) {
  pool[top++] = x;
  x = 0;
}

// Return a new leaf node of value v.
int new_leaf(int v) {
  int x = new_node();
  val[x] = v;
  sz[x] = 1;
  return x;
}

int join(int x, int y) {
  int z = new_node();

  ch[z][1] = y;
  push_up(z);
  return z;

      return true;
    } else {

      push_up(x);
      balance(x);

int count_less_than(int x, int v) {
  if (!x) return 0;

  while (sz[x] > 1) {
    if (val[ch[x][0]] < v) {
      res += sz[ch[x][0]];
      x = ch[x][1];
    } else {
      x = ch[x][0];
    }

  return res + (val[x] < v ? 1 : 0);
}

int find_rank(int v) { return count_less_than(rt, v) + 1; }

// Find the k-th element in the subtree at x.
// It is guaranteed that such an element exists.
int find_kth(int x, int k) {
  while (sz[x] > 1) {
    if (sz[ch[x][0]] >= k) {
      x = ch[x][0];
    } else {
      k -= sz[ch[x][0]];
      x = ch[x][1];
    }
  }
  return val[x];
}

int find_kth(int k) { return k > sz[rt] || k <= 0 ? -1 : find_kth(rt, k); }

// Find the predecessor of v.
int find_prev(int v) { return find_kth(find_rank(v) - 1); }

// Find the successor of v.
int find_next(int v) { return find_kth(find_rank(v + 1)); }

}

  if (lz[x]) {
    lazy_reverse(ch[x][0]);
    lazy_reverse(ch[x][1]);
    lz[x] = 0;

}
