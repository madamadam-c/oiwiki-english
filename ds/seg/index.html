    Segment Tree Basics

    introduce

    Line segment tree is a data structure commonly used in algorithm competitions to maintain interval information.

    The line segment tree can implement single point modification, interval modification, interval query (interval summation, interval maximum value, interval minimum value) and other operations within the time complexity of 𝑂(log⁡𝑁)O(log⁡N).

    The basic structure and construction of line segment trees

    process

    The line segment tree divides each interval whose length is not 11 into two left and right intervals for recursive solution, divides the entire line segment into a tree structure, and obtains the information of the interval by merging the information of the left and right intervals. This data structure can easily perform most interval operations.

    There is a size-55 array 𝑎 ={10,11,12,13,14}a={10,11,12,13,14}. To convert it into a line segment tree, there is the following method: set the root node number of the line segment tree to 11, use array 𝑑d to save our line segment tree, and 𝑑𝑖di to save the value of the node numbered 𝑖i on the line segment tree (the value maintained by each node here is the sum of the intervals represented by this node).

    We first give the shape of this line segment tree, as shown in the figure:

    The interval marked in red font in each node in the figure represents the position interval on the 𝑎a array governed by the node. For example, the interval governed by 𝑑1d1 is [1,5][1,5] (𝑎1,𝑎2,⋯,𝑎5a1,a2,⋯,a5), that is, the value stored in 𝑑1d1 is 𝑎1 +𝑎2 +⋯ +𝑎5a1+a2+⋯+a5, and 𝑑1 =60d1=60 represents 𝑎1 +𝑎2 +⋯ +𝑎5 =60a1+a2+⋯+a5=60.

    It is not difficult to find through observation that the left child node of 𝑑𝑖di is 𝑑2×𝑖d2×i, and the right child node of 𝑑𝑖di is 𝑑2×𝑖+1d2×i+1. If 𝑑𝑖di represents the interval [𝑠,𝑡][s,t] (that is, 𝑑𝑖 =𝑎𝑠 +𝑎𝑠+1 +⋯ +𝑎𝑡di=as+as+1+⋯+at), then the left child node of 𝑑𝑖di represents the interval [𝑠,𝑠+𝑡2][s,s+t2], and the right child node of 𝑑𝑖di represents the interval [𝑠+𝑡2 +1,𝑡][s+t2+1,t].

    During implementation, we consider recursive tree building. Assume that the current root node is 𝑝p. If the length of the interval governed by the root node is already 11, the node can be initialized directly according to the value of the corresponding position in the 𝑎a array. Otherwise, we divide the interval into two sub-intervals from the midpoint, enter the left and right sub-nodes to recursively build trees, and finally merge the information of the two sub-nodes.

    void build(int s, int t, int p) {
  // Create a line segment tree for the interval [s,t], the current root number is p
  if (s == t) {
    d[p] = a[s];
    return;
  }
  int m = s + ((t - s) >> 1);
  // The shift operator has lower precedence than addition and subtraction, so parentheses are added
  // If written as (s + t) >> 1 it may exceed the range of int
  build(s, m, p * 2), build(m + 1, t, p * 2 + 1);
  // Recursively build trees for the left and right intervals
  d[p] = d[p * 2] + d[(p * 2) + 1];
}

    Regarding the space of the line segment tree: If heap storage is used (2𝑝2p is the left son of 𝑝p, 2𝑝 +12p+1 is the right son of 𝑝p), if there are 𝑛n leaf nodes, the maximum range of the d array is 2⌈log⁡𝑛⌉+12⌈log⁡n⌉+1.

    Analysis: It is easy to know that the depth of the line segment tree is ⌈log⁡𝑛⌉⌈log⁡n⌉, so in the case of heap storage, the number of leaf nodes (including useless leaf nodes) is 2⌈log⁡𝑛⌉2⌈log⁡n⌉, and since it is a complete binary tree, its total number of nodes is 2⌈log⁡𝑛⌉+1 −12⌈log⁡n⌉+1−1. Of course, if you are too lazy to calculate, you can directly set the array length to 4𝑛4n, because the maximum value of 2⌈log⁡𝑛⌉+1−1𝑛2⌈log⁡n⌉+1−1n is obtained at 𝑛 =2𝑥 +1(𝑥 ∈𝑁+)n=2x+1(x∈N+), and the number of nodes at this time is 2⌈log⁡𝑛⌉+1 −1 =2𝑥+2 −1 =4𝑛 −52⌈log⁡n⌉+1−1=2x+2−1=4n−5.

    However, there are useless leaf nodes in heap storage. You can consider using a memory pool to manage line segment tree nodes and obtain them from the pool whenever a new node is needed. Considering bottom-up, every two bottom-level nodes must be merged into an upper-level node. Therefore, it can be proved similar to the Huffman tree. If there are 𝑛n leaf nodes, such a line segment tree has a total of 2𝑛 −12n−1 nodes. Its space efficiency is better than heap storage and is the best possible situation.

    Such a segment tree can be maintained bottom-up; see "The Power of Statistics - Zhang Kunwei".

    Interval query of line segment tree

    process

    Interval query, such as finding the sum of the interval [𝑙,𝑟][l,r] (that is, 𝑎𝑙 +𝑎𝑙+1 +⋯ +𝑎𝑟al+al+1+⋯+ar), finding the maximum/minimum value of the interval, etc.

    Still taking the first picture as an example, if you want to query the sum of the interval [1,5][1,5], just get the value of 𝑑1d1 (6060) directly.

    If the interval to be queried is [3,5][3,5], the value of the interval cannot be obtained directly at this time, but [3,5][3,5] can be split into [3,3][3,3] and [4,5][4,5], and the answer to this interval can be obtained by merging the answers of these two intervals.

    Generally, if the interval to be queried is [𝑙,𝑟][l,r], it can be split into up to 𝑂(log⁡𝑛)O(log⁡n) maximum intervals, and the answer to [𝑙,𝑟][l,r] can be obtained by merging these intervals.

    int getsum(int l, int r, int s, int t, int p) {
  // [l, r] is the query interval, [s, t] is the interval included by the current node, p is the number of the current node
  if (l <= s && t <= r)
    return d[p];  // When the current interval is a subset of the query interval, the sum of the current interval is directly returned.
  int m = s + ((t - s) >> 1), sum = 0;
  if (l <= m) sum += getsum(l, r, s, m, p * 2);
  // If the interval [s, m] represented by the left son intersects with the query interval, then the left son is recursively queried
  if (r > m) sum += getsum(l, r, m + 1, t, p * 2 + 1);
  // If the interval [m + 1, t] represented by the right son intersects with the query interval, then the right son is recursively queried
  return sum;
}

    Interval modification and lazy marking of line segment trees

    process

    If it is required to modify the interval [𝑙,𝑟][l,r], all nodes contained in the interval [𝑙,𝑟][l,r] must be traversed and modified once, and the time complexity is unbearable. We are going to introduce something called "lazy mark" here.

    Lazy marking, simply put, delays changes to node information, thereby reducing the number of potentially unnecessary operations. Each time a modification is performed, we use a marking method to indicate that the interval corresponding to the node has been changed in a certain operation, but the information of the node's child nodes is not updated. Substantial modifications will be made only the next time the marked node is accessed.

    Still taking the original picture as an example, we will perform several operations of adding a value to the number in the interval. We now add a 𝑡𝑖ti to each node, indicating the tag value of the node.

But don't worry, although the modification has not been carried out yet, when we want to query the information of these two sub-nodes, we will use the mark to modify the information of these two sub-nodes so that the query results are still accurate.

    Now the values ​​of the two nodes 66 and 77 have become the latest values, and the query results are also accurate.

    // [l, r] is the modification interval, c is the change amount of the modified element, [s, t] is the interval included by the current node, p
// is the number of the current node
void update(int l, int r, int c, int s, int t, int p) {
  // When the current interval is a subset of the modified interval, directly modify the value of the current node, then mark it and end the modification.
  if (l <= s && t <= r) {
    d[p] += (t - s + 1) * c, b[p] += c;
    return;
  }
  int m = s + ((t - s) >> 1);
  if (b[p] && s != t) {
    // If the lazy tag of the current node is not empty, update the values ​​​​of the two child nodes of the current node and the lazy tag value.
    d[p * 2] += b[p] * (m - s + 1), d[p * 2 + 1] += b[p] * (t - m);
    b[p * 2] += b[p], b[p * 2 + 1] += b[p];  // Pass tags down to child nodes
    b[p] = 0;                                // Clear the mark of the current node
  }
  if (l <= m) update(l, r, c, s, m, p * 2);
  if (r > m) update(l, r, c, m + 1, t, p * 2 + 1);
  d[p] = d[p * 2] + d[p * 2 + 1];
}

    Dynamic open point segment tree

    As mentioned earlier, in the case of heap storage, an array of size 4𝑛4n needs to be opened for the line segment tree. In order to save space, we can not build the tree all at once, but initially only create one root node to represent the entire interval. When we need to access a certain sub-range, we create a child node representing this range. In this way, we no longer use 2𝑝2p and 2𝑝 +12p+1 to represent the sons of the 𝑝p node, but use lsls and rsrs to record the number of the son. In short, the core idea of ​​the dynamic open-point line segment tree is: nodes are only created when needed.

    The time complexity of a single operation is constant, 𝑂(log⁡𝑛)O(log⁡n). Since each operation may create and access a new series of nodes, the number of nodes after 𝑚m single-point operations is 𝑂(𝑚log⁡𝑛)O(mlog⁡n). At most, only 2𝑛 −12n−1 nodes are needed, so there is no waste.
