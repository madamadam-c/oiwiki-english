    Dancing Links

    This page introduces the exact cover problem, the repeated cover problem, Algorithm X for solving these two problems, and the doubly linked cross list Dancing Links used to optimize Algorithm X. This page also introduces how to use DLX with modeling to solve some search problems.

    Exact Cover Problem

    Definition

    The exact cover problem is: given many sets 𝑆𝑖(1 ≤𝑖 ≤𝑛)Si(1≤i≤n) and a set 𝑋X, find an unordered tuple (𝑇1,𝑇2,⋯,𝑇𝑚)(T1,T2,⋯,Tm) satisfying the following conditions:

    1. ∀𝑖,𝑗 ∈[1,𝑚],𝑇𝑖⋂𝑇𝑗 =∅(𝑖 ≠𝑗)∀i,j∈[1,m],Ti⋂Tj=∅(i≠j)
    2. 𝑋 =𝑚⋃𝑖=1𝑇𝑖X=⋃i=1mTi
    3. ∀𝑖 ∈[1,𝑚],𝑇𝑖 ∈{𝑆1,𝑆2,⋯,𝑆𝑛}∀i∈[1,m],Ti∈{S1,S2,⋯,Sn}

    Explanation

    For example, if we are given

    𝑆1={5,9,17}𝑆2={1,8,119}𝑆3={3,5,17}𝑆4={1,8}𝑆5={3,119}𝑆6={8,9,119}𝑋={1,3,5,8,9,17,119}S1={5,9,17}S2={1,8,119}S3={3,5,17}S4={1,8}S5={3,119}S6={8,9,119}X={1,3,5,8,9,17,119}

    then (𝑆1,𝑆4,𝑆5)(S1,S4,S5) is a valid solution.

    Given a 01 matrix, you may choose some rows so that each column1 has exactly one 1 in the end. For example, modeling the example above gives the following matrix:

    Here row 𝑖i represents 𝑆𝑖Si, and the entries in this row represent [1 ∈𝑆𝑖],[3 ∈𝑆𝑖],[5 ∈𝑆𝑖],⋯,[119 ∈𝑆𝑖][1∈Si],[3∈Si],[5∈Si],⋯,[119∈Si] in order.

    Implementation

    Each check requires 𝑂(𝑛𝑚)O(nm) time. Therefore, the total complexity is 𝑂(𝑛𝑚 ⋅2𝑛)O(nm⋅2n).

    Repeated Cover Problem

    The repeated cover problem is similar to the exact cover problem, but it has no restriction on element overlap. The Algorithm X introduced below was originally designed for exact cover problems, but with some modifications and optimizations (marked where they appear), it can also efficiently solve repeated cover problems.

    Algorithm X

    Donald E. Knuth proposed Algorithm X. Its idea is similar to the brute-force methods above, but it is easier to optimize.

    Process

    Continuing with the example above, we obtain the following 01 matrix:

    It is strongly recommended to simulate the process of deleting, restoring, and backtracking through the matrix yourself before continuing.

    From the steps above, the process of Algorithm X can be summarized as follows:

    1. For the current matrix 𝑀M, select and mark a row 𝑟r, and add 𝑟r to 𝑆S.
    2. If all choices of 𝑟r have been tried and no solution is found, terminate the algorithm and output that there is no solution.
    3. Mark the rows 𝑟𝑖ri and columns 𝑐𝑖ci related to 𝑟r (related rows and columns are defined in the same way as in step 2 of Algorithm X; the same applies below).
    4. Delete all marked rows and columns to obtain a new matrix 𝑀′M′.

    5. If 𝑀′M′ is empty and 𝑟r is all 11s, terminate the algorithm and output the set 𝑆S consisting of the deleted rows.

      If 𝑀′M′ is empty and 𝑟r is not all 11s, restore the rows 𝑟𝑖ri and columns 𝑐𝑖ci related to 𝑟r, and jump to step 1.

      If 𝑀′M′ is not empty, jump to step 1.

    It is easy to see that Algorithm X requires many operations that delete rows, delete columns, restore rows, and restore columns.

    A naive idea is to store the matrix in a two-dimensional array, and then use four arrays to store, for each row, the indices of adjacent rows, so that each deletion and restoration only needs to update elements in the four arrays. However, because in matrices from typical problems the number of 0s is far greater than the number of 1s, the space complexity of this approach is unacceptable.

    Donald E. Knuth came up with using a doubly linked cross list to maintain these operations.

    The process of continuously jumping on the doubly linked cross list is vividly compared to "dancing", so the doubly linked cross list used to optimize Algorithm X is also called "Dancing Links".

    Algorithm X Optimized by Dancing Links

    Preprocessor Directive

    1

    Definition

    Process

    remove Operation

    remove(c) means deleting column 𝑐c and the rows and columns related to it in Dancing Links.

    First delete 𝑐c. At this point:

    • The right node of the node to the left of 𝑐c should be the right node of 𝑐c.
    • The left node of the node to the right of 𝑐c should be the left node of 𝑐c.

    That is, L[R[c]] = L[c], R[L[c]] = R[c];.

    Then go downward along this column and delete every row encountered.

    How do we delete each row? Enumerate the pointer 𝑗j in the current row. At this point:

    • The down node of the node above 𝑗j should be the down node of 𝑗j.
    • The up node of the node below 𝑗j should be the up node of 𝑗j.

    Remember to update the number of elements in each column.

    That is, U[D[j]] = U[j], D[U[j]] = D[j], --siz[col[j]];.

    dance Operation

    dance() is the process of recursively deleting and restoring rows and columns.

    1. If node 00 has no right node, the matrix is empty; record the answer and return.
    2. Select the column with the fewest elements and delete this column.
    3. Traverse all rows in this column that have a 11, and enumerate whether each is selected.
    4. Recursively call dance(). If it is feasible, return; if not, restore the selected row.
    5. If there is no solution, return.

    Properties

    The number of recursive and backtracking steps in DLX is related to the number of 11s in the matrix, and is unrelated to parameters such as 𝑟,𝑐r,c of the matrix. Therefore, its time complexity is exponential. The theoretical complexity is roughly around 𝑂(𝑐𝑛)O(cn), where 𝑐c is a constant very close to 11, and 𝑛n is the number of 11s in the matrix.

    In practice, however, DLX performs well and can generally solve most problems.

    Modeling

    The difficulty of DLX lies not entirely in building the linked list, but in modeling.

    Please make sure you have fully mastered the DLX template before continuing.

    Whenever we get a problem, we should consider what the rows and columns represent:

    • Rows represent decisions, because each row corresponds to a set, and therefore corresponds to selecting or not selecting it.

    • Columns represent states, because column 𝑖i corresponds to some condition 𝑃𝑖Pi.

    For a certain row, because the values in different columns vary, we define a decision through different states.

    int i, j;

      for (j = L[i]; j != i; j = L[j]) U[D[j]] = D[U[j]] = j, ++siz[col[j]];
    L[R[c]] = R[L[c]] = c;
  }

    int i, j, c = R[0];
    if (!R[0]) {
      int cur_ans = 0;
      for (i = 1; i < dep; ++i) {
        int cur_row = (stk[i] - 1) / 9 / 9 + 1;
        int cur_col = (stk[i] - 1) / 9 % 9 + 1;
        int cur_num = (stk[i] - 1) % 9 + 1;
        cur_ans += GetWeight(cur_row, cur_col, cur_num);
      }
      ans = std::max(ans, cur_ans);
      return;
    }
    for (i = R[0]; i != 0; i = R[i])
      if (siz[i] < siz[c]) c = i;
    remove(c);
    for (i = D[c]; i != c; i = D[i]) {
      stk[dep] = row[i];
      for (j = R[i]; j != i; j = R[j]) remove(col[j]);
      dance(dep + 1);
      for (j = L[i]; j != i; j = L[j]) recover(col[j]);
    }
    recover(c);
  }
