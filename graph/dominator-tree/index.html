    Dominator Tree

    Preface

    The concept of "domination" was introduced by Reese T. Prosser in a paper on network flow in 1959, but no specific algorithm was proposed; it was not until 1969 that Edward S. Lowry and C. W. Medlock first proposed an effective algorithm. The most widely used Lengauer–Tarjan algorithm was proposed by Lengauer and Tarjan in 1979 in a paper.

    In the OI community, the concept of a dominator tree was first introduced in ZJOI2012 Disaster, where it was also called an "extinction tree"; Chen Sunli also introduced this algorithm in a 2020 national training team paper.

    Currently, dominator trees are not popular in competitive programming, and related practice problems are rare; however, dominator trees are widely used in industry, especially in compiler-related fields.

    This article introduces the concept of dominator trees and several methods for solving them.

    Domination Relation

    Consider an arbitrary directed graph with a designated entry node 𝑠s. For a node 𝑢u, if every path from 𝑠s to 𝑢u passes through a node 𝑣v, then we say 𝑣v dominates 𝑢u, and 𝑣v is called a dominator of 𝑢u, denoted 𝑣 𝑑𝑜𝑚 𝑢v dom u.

    Nodes unreachable from 𝑠s have no meaningful domination relation; therefore, unless otherwise specified, we assume 𝑠s can reach every node in the graph.

    For example, in this directed graph, 22 is dominated by 11, 33 is dominated by 11 and 22, 44 is dominated by 11, 22, and 33, 55 is dominated by 11 and 22, etc.

    Lemmas

    In the lemmas below, assume 𝑢,𝑣,𝑤 ≠𝑠u,v,w≠s.

    Lemma 1: 𝑠s dominates all nodes; every node dominates itself.

    Proof: Obviously, every path from 𝑠s to 𝑢u must pass through both 𝑠s and 𝑢u.

    Lemma 2: The domination relation derived from simple paths is the same as that derived from all paths.

    Proof: For non-simple paths, let 𝑆S be the set of nodes traversed between two visits to the same node. If we delete all nodes in 𝑆S, each non-simple path can be mapped to a simple path.

    Nodes in 𝑆S that appear on non-simple paths but not on simple paths cannot be dominators, because there exists at least one simple path from 𝑠s to 𝑢u that does not include this node; meanwhile, nodes on both simple and non-simple paths only need to be discussed on simple paths.

    Therefore, removing non-simple paths does not affect the domination relation.

    Lemma 3: If 𝑢 𝑑𝑜𝑚 𝑣u dom v and 𝑣 𝑑𝑜𝑚 𝑤v dom w, then 𝑢 𝑑𝑜𝑚 𝑤u dom w.

    Proof: Paths passing through 𝑤w must pass through 𝑣v, and paths passing through 𝑣v must pass through 𝑢u, so paths passing through 𝑤w must pass through 𝑢u, i.e., 𝑢 𝑑𝑜𝑚 𝑤u dom w.

    Lemma 4: If 𝑢 𝑑𝑜𝑚 𝑣u dom v and 𝑣 𝑑𝑜𝑚 𝑢v dom u, then 𝑢 =𝑣u=v.

    Proof: Assume 𝑢 ≠𝑣u≠v. Then every path reaching 𝑣v has already passed through 𝑢u, and every path reaching 𝑢u has already passed through 𝑣v, a contradiction.

    Lemma 5: If 𝑢 ≠𝑣 ≠𝑤u≠v≠w, 𝑢 𝑑𝑜𝑚 𝑤u dom w and 𝑣 𝑑𝑜𝑚 𝑤v dom w, then either 𝑢 𝑑𝑜𝑚 𝑣u dom v or 𝑣 𝑑𝑜𝑚 𝑢v dom u.

    Proof: Consider a path 𝑠 →⋯ →𝑢 →⋯ →𝑣 →⋯ →𝑤s→⋯→u→⋯→v→⋯→w. If 𝑢u and 𝑣v have no domination relation, then there exists a path from 𝑠s to 𝑣v that does not pass through 𝑢u, i.e., a path 𝑠 →⋯ →𝑣 →⋯ →𝑤s→⋯→v→⋯→w, contradicting 𝑢 𝑑𝑜𝑚 𝑤u dom w.

    Solving Domination Relations

    Node Deletion Method

    An equivalent condition to the definition: if we delete a node from the graph and some nodes become unreachable, then the deleted node dominates those unreachable nodes.

    // Assume the graph has n nodes, start node s = 1
std::bitset<N> vis;
std::vector<int> edge[N];
std::vector<int> dom[N];

void dfs(int u, int del) {
  vis[u] = true;
  for (int v : edge[u]) {
    if (v == del or vis[v]) {
      continue;
    }
    dfs(v, del);
  }
}

void getdom() {
  for (int i = 2; i <= n; ++i) {
    vis.reset();
    dfs(1, i);
    for (int j = 1; j <= n; ++j) {
      if (!vis[j]) {
        dom[j].push_back(i);
      }
    }
  }
}

    Dataflow Iteration Method

    The dataflow iteration method is also an uncommon topic in OI. Here we give a brief introduction.

    Dataflow analysis is a concept in compiler theory, used to analyze how data flows along program execution paths; the dataflow iteration method lists equations on nodes of a program's flow graph and iteratively solves them to obtain dataflow values at certain points. Here, we treat the directed graph as a program flow graph.

    In this problem, the equation is:

    $$

    dom(u)={u} \cup \left(\bigcap_{v\in pre(u)}{dom(v)}\right)

    $$

    where 𝑝𝑟𝑒(𝑢)pre(u) is the set of predecessor nodes of 𝑢u. This equation can be derived from Lemma 3.

    In plain terms, the set of dominators of a node is the intersection of the dominator sets of all its predecessor nodes, union with itself. Based on this equation, we iteratively update the dominator set for each node until the answer stabilizes.

    To improve efficiency, we want each predecessor of the current node to have already completed this iteration. Therefore, we use depth-first ordering to get the reverse postorder of the graph and iterate in that order.

    The reference implementation of the core code is given below. Here, the predecessor set of each node and the reverse postorder of the graph need to be preprocessed, but this is not the main topic of this article, so no reference implementation is provided here.

    std::vector<int> pre[N];  // Predecessor nodes of each node
std::vector<int> ord;     // Reverse postorder of the graph
std::bitset<N> dom[N];
std::vector<int> Dom[N];

void getdom() {
  dom[1][1] = true;
  flag = true;
  while (flag) {
    flag = false;
    for (int u : ord) {
      std::bitset<N> tmp;
      tmp[u] = true;
      for (int v : pre[u]) {
        tmp &= dom[v];
      }
      if (tmp != dom[u]) {
        dom[u] = tmp;
        flag = true;
      }
    }
  }
  for (int i = 2; i <= n; ++i) {
    for (int j = 1; j <= n; ++j) {
      if (dom[i][j]) {
        Dom[i].push_back(j);
      }
    }
  }
}

    The time complexity of this algorithm is 𝑂(𝑛2)O(n2).

    Dominator Tree

    In the previous section, we found that for every node except 𝑠s, there are at least two dominators: 𝑠s and the node itself.

    Among the dominators of an arbitrary node 𝑢u, the dominator 𝑣v that is closest to 𝑢u (excluding 𝑢u itself) is called the immediate dominator of 𝑢u, denoted 𝑖𝑑𝑜𝑚(𝑢) =𝑣idom(u)=v. Obviously, except for 𝑠s which has no immediate dominator, every node has exactly one immediate dominator.

    If we draw an edge from 𝑖𝑑𝑜𝑚(𝑢)idom(u) to 𝑢u for every node 𝑢 ≠𝑠u≠s, we get a directed graph with 𝑛n nodes and 𝑛 −1n−1 edges. By Lemma 3 and Lemma 4, the domination relation never forms a cycle, so these edges never form a cycle, and the resulting graph is a tree. We call this tree the dominator tree of the original graph.

    Solving Dominator Trees

    Solving from Dom Sets

    Consider the dominator set {𝑠1,𝑠2,…,𝑠𝑘}{s1,s2,…,sk} of some node 𝑢u. There must exist a path 𝑠 →⋯ →𝑠1 →⋯ →𝑠2 →⋯ →⋯ →𝑠𝑘 →⋯ →𝑢s→⋯→s1→⋯→s2→⋯→⋯→sk→⋯→u. Clearly, the immediate dominator of 𝑢u is 𝑠𝑘sk. Therefore, the definition of immediate dominator is equivalent to:

    For a node 𝑢u with dominator set 𝑆S, if 𝑣 ∈𝑆v∈S satisfies ∀𝑤 ∈𝑆 ∖{𝑢,𝑣},𝑤 𝑑𝑜𝑚 𝑣∀w∈S∖{u,v},w dom v, then 𝑖𝑑𝑜𝑚(𝑢) =𝑣idom(u)=v.

    Therefore, after obtaining the dominator set of each node using the algorithm described earlier, we can easily obtain the immediate dominator of each node according to the above definition, and thus construct the dominator tree. The reference code is given below.

void getidom() {
  for (int u = 2; u <= n; ++u) {
    for (int v : Dom[u]) {

}

    Special Case: Trees

    Clearly, the dominator tree of a tree graph is itself.

    Special Case: DAGs

    We observe that DAGs have a nice property: when solving by topological order, the solutions obtained earlier do not affect subsequent solutions. We can use this property to efficiently compute the dominator tree of a DAG.

    Note

    It is important to note that the DAG here can only have one source. If there are multiple sources, nodes dominated by different sources may have multiple parents in the dominator tree, making the domination relation not expressible simply as a dominator tree.

    Lemma 6: In a directed graph, 𝑣 𝑑𝑜𝑚 𝑢v dom u if and only if ∀𝑤 ∈𝑝𝑟𝑒(𝑢),𝑣 𝑑𝑜𝑚 𝑤∀w∈pre(u),v dom w.

    Proof: First, we prove sufficiency. Consider any path from 𝑠s to 𝑢u. It must pass through some node 𝑤 ∈𝑝𝑟𝑒(𝑢)w∈pre(u). Since 𝑣v dominates this node, any path from 𝑠s to 𝑢u must pass through 𝑣v, so we get 𝑣 𝑑𝑜𝑚 𝑢v dom u.

    Now for necessity. If ∃𝑤 ∈𝑝𝑟𝑒(𝑢)∃w∈pre(u) such that 𝑣v does not dominate 𝑤w, then there exists a path 𝑠 →⋯ →𝑤 →⋯ →𝑢s→⋯→w→⋯→u that does not pass through 𝑣v, so 𝑣v does not dominate 𝑢u.

    We find that the dominator of 𝑢u must be a common ancestor of all its predecessors in the dominator tree. Therefore, the immediate dominator of 𝑢u is the LCA of all predecessors in the dominator tree. Considering using binary lifting to compute LCA, we can support adding one node at a time, so the above algorithm is clearly feasible.

    std::stack<int> sta;
std::vector<int> e[N], g[N], tree[N];  // g is the reverse graph, tree is the dominator tree
int n, s, in[N], tpn[N], dep[N], idom[N];  // n is total nodes, s is start node, in is indegree

void topo(int s) {
  sta.push(s);
  while (!sta.empty()) {
    int u = sta.top();
    sta.pop();
    tpn[++tot] = u;
    for (int v : e[u]) {
      --in[v];
      if (!in[v]) {
        sta.push(v);
      }
    }
  }
}

int lca(int u, int v) {
  if (dep[u] < dep[v]) {
    std::swap(u, v);
  }
  for (int i = 15; i >= 0; --i) {
    if (dep[fth[u][i]] >= dep[v]) {
      u = fth[u][i];
    }
  }
  if (u == v) {
    return u;
  }
  for (int i = 15; i >= 0; --i) {
    if (fth[u][i] != fth[v][i]) {
      u = fth[u][i];
      v = fth[v][i];
    }
  }
  return fth[u][0];
}

void build() {
  topo(s);
  for (int i = 1; i <= n; ++i)
    for (int j = 0; j <= 15; ++j) fth[i][j] = s;
  for (int i = 1; i <= n; ++i) {
    int u = tpn[i];
    if (g[u].size()) {
      int v = g[u][0];
      for (int j = 1, q = g[u].size(); j < q; ++j) {
        v = lca(v, g[u][j]);
      }
      tree[v].push_back(u);
      fth[u][0] = v;
      dep[u] = dep[v] + 1;
      for (int i = 1; i <= 15; ++i) {
        fth[u][i] = fth[fth[u][i - 1]][i - 1];
      }
    }
  }
}

    Lengauer–Tarjan Algorithm

    The Lengauer–Tarjan algorithm is one of the most famous algorithms for solving dominator trees, computing the dominator tree of a directed graph in 𝑂(𝑛𝛼(𝑛,𝑚))O(nα(n,m)) time. This algorithm introduces the concept of semi-dominators and uses them to find immediate dominators.

    Conventions

    First, we perform a DFS from 𝑠s on this directed graph. The traversed nodes and edges form a tree 𝑇T. We call traversed edges tree edges and the rest non-tree edges. Let 𝑑𝑓𝑛(𝑢)dfn(u) denote the order in which node 𝑢u is visited; define 𝑢 <𝑣u<v if and only if 𝑑𝑓𝑛(𝑢) <𝑑𝑓𝑛(𝑣)dfn(u)<dfn(v).

    Semi-Dominators

    The semi-dominator of a node 𝑢u is the smallest node 𝑣v such that there is a path from 𝑣v to 𝑢u where, except for 𝑢u and 𝑣v, every node on the path is greater than 𝑢u. Formally, the semi-dominator 𝑠𝑑𝑜𝑚(𝑢)sdom(u) of 𝑢u is defined as:

    𝑠𝑑𝑜𝑚(𝑢) =min(𝑣|∃𝑣 =𝑣0 →𝑣1 →⋯ →𝑣𝑘 =𝑢,∀1 ≤𝑖 ≤𝑘 −1,𝑣𝑖 >𝑢)sdom(u)=min(v|∃v=v0→v1→⋯→vk=u,∀1≤i≤k−1,vi>u)

    We observe that semi-dominators have some useful properties:

    Lemma 7: For any node 𝑢u, 𝑠𝑑𝑜𝑚(𝑢) <𝑢sdom(u)<u.

    Proof: By definition, the parent 𝑓𝑎(𝑢)fa(u) of 𝑢u in 𝑇T also satisfies the condition to be a semi-dominator, and 𝑓𝑎(𝑢) <𝑢fa(u)<u. Therefore, no node greater than 𝑢u can be its semi-dominator.

    Lemma 8: For any node 𝑢u, 𝑖𝑑𝑜𝑚(𝑢)idom(u) is an ancestor of 𝑢u in 𝑇T.

    Proof: The path from 𝑠s to 𝑢u in 𝑇T corresponds to a path in the original graph, so 𝑖𝑑𝑜𝑚(𝑢)idom(u) must be on this path.

    Lemma 9: For any node 𝑢u, 𝑠𝑑𝑜𝑚(𝑢)sdom(u) is an ancestor of 𝑢u in 𝑇T.

    Proof: Suppose 𝑠𝑑𝑜𝑚(𝑢)sdom(u) is not an ancestor of 𝑢u. Then 𝑠𝑑𝑜𝑚(𝑢)sdom(u) cannot connect to any node with DFS order greater than or equal to 𝑢u (otherwise this node should be in the subtree of 𝑠𝑑𝑜𝑚(𝑢)sdom(u) rather than another subtree), a contradiction.

    Lemma 10: For any node 𝑢u, 𝑖𝑑𝑜𝑚(𝑢)idom(u) is an ancestor of 𝑠𝑑𝑜𝑚(𝑢)sdom(u).

    Proof: Consider that we can go from 𝑠s to 𝑠𝑑𝑜𝑚(𝑢)sdom(u), then along the path in the definition to 𝑢u. By definition, nodes on the path from 𝑠𝑑𝑜𝑚(𝑢)sdom(u) to 𝑢u do not dominate 𝑢u, so 𝑖𝑑𝑜𝑚(𝑢)idom(u) must be an ancestor of 𝑠𝑑𝑜𝑚(𝑢)sdom(u).

    Lemma 11: For any nodes 𝑢 ≠𝑣u≠v where 𝑣v is an ancestor of 𝑢u, either 𝑣v is an ancestor of 𝑖𝑑𝑜𝑚(𝑢)idom(u), or 𝑖𝑑𝑜𝑚(𝑢)idom(u) is an ancestor of 𝑖𝑑𝑜𝑚(𝑣)idom(v).

    Proof: For any node 𝑤w between 𝑣v and 𝑖𝑑𝑜𝑚(𝑣)idom(v), by the definition of immediate dominator, there exists a path from 𝑠s to 𝑖𝑑𝑜𝑚(𝑣)idom(v) then to 𝑣v that does not pass through 𝑤w. Therefore, these nodes 𝑤w are not 𝑖𝑑𝑜𝑚(𝑢)idom(u). So 𝑖𝑑𝑜𝑚(𝑢)idom(u) is either a descendant of 𝑣v or an ancestor of 𝑖𝑑𝑜𝑚(𝑣)idom(v).

    From the above lemmas, we can derive the following theorem:

    Theorem 1: The semi-dominator of a node 𝑢u is the minimum among the semi-dominators of all ancestors of 𝑢u's predecessors and 𝑢u's dominators in 𝑇T that are greater than 𝑢u. Formally, 𝑠𝑑𝑜𝑚(𝑢) =min({𝑣|∃𝑣 →𝑢,𝑣 <𝑢} ∪{𝑠𝑑𝑜𝑚(𝑤)|𝑤 >𝑢 𝑎𝑛𝑑 ∃𝑤 →⋯ →𝑣 →𝑢})sdom(u)=min({v|∃v→u,v<u}∪{sdom(w)|w>u and ∃w→⋯→v→u}).

    Proof: Let 𝑥x equal the right side of the equation.

    First, we prove 𝑠𝑑𝑜𝑚(𝑢) ≤𝑥sdom(u)≤x. By Lemma 7, this statement is equivalent to proving that both cases in the definition satisfy the semi-dominator condition. When 𝑥x is a predecessor of 𝑢u, this is obvious. For the second part, consider the path 𝑥 =𝑣0 →⋯ →𝑣𝑗 =𝑤x=v0→⋯→vj=w from the semi-dominator definition and a path 𝑤 =𝑣𝑗 →⋯ →𝑣𝑘 =𝑣w=vj→⋯→vk=v in 𝑇T satisfying ∀𝑖 ∈[𝑗,𝑘 −1],𝑣𝑖 ≥𝑤 >𝑢∀i∈[j,k−1],vi≥w>u, along with the path 𝑣 →𝑢v→u. Concatenating these gives a path satisfying the semi-dominator definition.

    Then we prove 𝑠𝑑𝑜𝑚(𝑢) ≥𝑥sdom(u)≥x. Consider the path 𝑠𝑑𝑜𝑚(𝑢) =𝑣0 →𝑣1 →⋯ →𝑣𝑘 =𝑢sdom(u)=v0→v1→⋯→vk=u from 𝑢u to its semi-dominator. It is clear that 𝑘 =1k=1 and 𝑘 >1k>1 correspond to the two selection methods in the definition. If 𝑘 =1k=1, there is a directed edge 𝑠𝑑𝑜𝑚(𝑢) →𝑢sdom(u)→u, which proves the case by Lemma 7. If 𝑘 >1k>1, let 𝑗j be the minimum index satisfying 𝑗 ≥1j≥1 and 𝑣𝑗vj is an ancestor of 𝑣𝑘−1vk−1 in 𝑇T. Since 𝑘k satisfies the above condition, such 𝑗j must exist.

    To prove 𝑣0 →⋯ →𝑣𝑗v0→⋯→vj is a path satisfying the semi-dominator condition for 𝑣𝑗vj, we need ∀𝑖 ∈[1,𝑗),𝑣𝑖 >𝑣𝑗∀i∈[1,j),vi>vj. If not, let 𝑖i be the smallest index such that 𝑣𝑖 <𝑣𝑗vi<vj. By Lemma 11, 𝑣𝑖vi is an ancestor of 𝑣𝑗vj, which contradicts the definition of 𝑗j. Thus 𝑠𝑑𝑜𝑚(𝑣𝑗) ≤𝑠𝑑𝑜𝑚(𝑢)sdom(vj)≤sdom(u). Since 𝑠𝑑𝑜𝑚(𝑣𝑗) ≤𝑥sdom(vj)≤x and 𝑣𝑗vj's semi-dominator is at least 𝑥x (as 𝑣𝑗 ≤𝑢vj≤u), we have 𝑠𝑑𝑜𝑚(𝑢) ≤𝑥sdom(u)≤x. Therefore 𝑥 =𝑠𝑑𝑜𝑚(𝑢)x=sdom(u).

    By Theorem 1, we can compute the semi-dominator of each node. The bottleneck in computing semi-dominators is the second case. We use a weighted union-find with path compression and update the minimum during compression.

int find(int x) {
  if (fa[x] == x) {
    return x;
  }
  int tmp = fa[x];
  fa[x] = find(fa[x]);
  if (dfn[sdm[mn[tmp]]] < dfn[sdm[mn[x]]]) {
    mn[x] = mn[tmp];
  }
  return fa[x];
}

void getsdom() {
  dfs(1);
  for (int i = 1; i <= n; ++i) {
    mn[i] = fa[i] = sdm[i] = i;
  }
  for (int i = dfc; i >= 2; --i) {
    int u = pos[i], res = INF;
    for (int j = h[1][u]; j; j = e[j].x) {
      int v = e[j].v;
      if (!dfn[v]) {
        continue;
      }
      find(v);
      if (dfn[v] < dfn[u]) {
        res = std::min(res, dfn[v]);
      } else {
        res = std::min(res, dfn[sdm[mn[v]]]);
      }
    }
    sdm[u] = pos[res];
    fa[u] = fth[u];
  }
}

      if (dfn[v] < dfn[u]) {

      } else {

      } else {
        idm[v] = mn[v];
      }
    }
    h[2][u] = 0;

    int u = pos[i];
    if (idm[u] != sdm[u]) {

    }

int find(int x) {
  if (fa[x] == x) {
    return x;
  }
  int tmp = fa[x];
  fa[x] = find(fa[x]);
  if (dfn[sdm[mn[tmp]]] < dfn[sdm[mn[x]]]) {
    mn[x] = mn[tmp];
  }
  return fa[x];
}

    #include <iostream>
#include <stack>
#include <vector>

using std::cin;
using std::cout;
using std::stack;
using std::vector;

constexpr int MAX = 65536;
int n, x, tot;
int d[MAX], w[MAX], siz[MAX], p[MAX], f[MAX][17];
vector<int> e[MAX], g[MAX], h[MAX];
stack<int> s;

void topo() {
  s.push(0);
  for (int i = 1; i <= n; ++i) {
    if (!w[i]) {
      e[0].push_back(i);
      g[i].push_back(0);
      ++w[i];
    }
  }
  while (!s.empty()) {
    int x = s.top();
    s.pop();
    p[++tot] = x;
    for (int i : e[x]) {
      --w[i];
      if (!w[i]) {
        s.push(i);
      }
    }
  }
}

int lca(int u, int v) {
  if (d[u] < d[v]) {
    std::swap(u, v);
  }
  for (int i = 15; i >= 0; --i) {
    if (d[f[u][i]] >= d[v]) {
      u = f[u][i];
    }
  }
  if (u == v) {
    return u;
  }
  for (int i = 15; i >= 0; --i) {
    if (f[u][i] != f[v][i]) {
      u = f[u][i];
      v = f[v][i];
    }
  }
  return f[u][0];
}

void dfs(int x) {
  siz[x] = 1;
  for (int i : h[x]) {
    dfs(i);
    siz[x] += siz[i];
  }
}

void build() {
  for (int i = 2; i <= n + 1; ++i) {
    int x = p[i], y = g[x][0];
    for (int j = 1, q = g[x].size(); j < q; ++j) {
      y = lca(y, g[x][j]);
    }
    h[y].push_back(x);
    d[x] = d[y] + 1;
    f[x][0] = y;
    for (int i = 1; i <= 15; ++i) {
      f[x][i] = f[f[x][i - 1]][i - 1];
    }
  }
}

int main() {
  cin >> n;
  for (int i = 1; i <= n; ++i) {
    while (true) {
      cin >> x;
      if (!x) {
        break;
      }
      e[x].push_back(i);
      g[i].push_back(x);
      ++w[i];
    }
  }
  topo();
  build();
  dfs(0);
  for (int i = 1; i <= n; ++i) {

  }

}
