    Quadrangle Inequality Optimization

    Quadrangle-inequality optimization exploits monotonicity of the optimal decision in a DP transition. It is therefore also often called decision-monotonicity optimization for DP.

    Prerequisites

    Consider the simplest setting, where we need to solve the following family of optimization problems:

    𝑓(𝑖)=min1≤𝑗≤𝑖𝑤(𝑗,𝑖)(1≤𝑖≤𝑛)(1)(1)f(i)=min1≤j≤iw(j,i)(1≤i≤n)

    Assume here that the cost function 𝑤(𝑗,𝑖)w(j,i) can be computed in 𝑂(1)O(1) time.

    Convention

    DP transitions can often be written as a family of optimization problems. In (1), the problem has parameter 𝑖i, and both the objective function and the feasible set may depend on 𝑖i. For brevity, the optimization problem with parameter 𝑖i is called problem 𝑖i; a feasible value 𝑗j is called decision 𝑗j; and the optimal objective value is called the state 𝑓(𝑖)f(i). Let opt⁡(𝑖)opt⁡(i) denote the smallest optimal decision for problem 𝑖i.

    In the general case, solving all these problems costs 𝑂(𝑛2)O(n2), because problem 𝑖i may have to inspect every possible decision 𝑗j. If the optimal decisions are monotone, the decision space can be restricted and the total complexity improved.

    • Decision monotonicity: for any 𝑖1 <𝑖2i1<i2, opt⁡(𝑖1) ≤opt⁡(𝑖2)opt⁡(i1)≤opt⁡(i2).
    Remark

    The set of optimal decisions for a problem need not be an interval. Decision monotonicity can be defined on optimal-decision sets: for sets 𝐴A and 𝐵B, define 𝐴 ≤𝐵A≤B iff for any 𝑎 ∈𝐴a∈A and 𝑏 ∈𝐵b∈B, both min{𝑎,𝑏} ∈𝐴min{a,b}∈A and max{𝑎,𝑏} ∈𝐵max{a,b}∈B hold. This implies monotonicity of the smallest and largest optimal decisions, which is the definition used here. All results stated for the smallest optimal decision also apply to the largest optimal decision. When implementing, always consistently choose either the smallest or the largest optimal decision, because it is possible that optmax⁡(𝑖1) >optmin⁡(𝑖2)optmax⁡(i1)>optmin⁡(i2) for some 𝑖1 <𝑖2i1<i2.

    Problems with the same smallest optimal decision form an interval. These intervals, viewed as a function of the smallest optimal decision, are strictly increasing: if 𝑗1 =opt⁡(𝑖1)j1=opt⁡(i1), 𝑗2 =opt⁡(𝑖2)j2=opt⁡(i2), and 𝑗1 <𝑗2j1<j2, then 𝑖1 <𝑖2i1<i2.

    The most common way to prove decision monotonicity is the quadrangle inequality. In other contexts it is also called the Monge property for matrices 𝐴𝑗,𝑖Aj,i, or submodularity for functions of intervals 𝑓([𝑗,𝑖])f([j,i]).

    • Quadrangle inequality: if for any 𝑎 ≤𝑏 ≤𝑐 ≤𝑑a≤b≤c≤d,

      𝑤(𝑎,𝑐)+𝑤(𝑏,𝑑)≤𝑤(𝑎,𝑑)+𝑤(𝑏,𝑐),w(a,c)+w(b,d)≤w(a,d)+w(b,c),

      then 𝑤w is said to satisfy the quadrangle inequality, often remembered as "crossing is no larger than containing". If equality always holds, 𝑤w satisfies the quadrangle identity.

    Unless otherwise stated, assume 𝑎 ≤𝑏 ≤𝑐 ≤𝑑a≤b≤c≤d. The quadrangle inequality is a sufficient, but not necessary, condition for decision monotonicity.

    Theorem 1

    If 𝑤w satisfies the quadrangle inequality, then problem (1) has decision monotonicity.

    Proof

    Suppose, for contradiction, that for some 𝑐 <𝑑c<d we have 𝑎 =opt⁡(𝑑) <opt⁡(𝑐) =𝑏a=opt⁡(d)<opt⁡(c)=b. Then 𝑎 <𝑏 ≤𝑐 <𝑑a<b≤c<d. Optimality gives 𝑤(𝑎,𝑑) ≤𝑤(𝑏,𝑑)w(a,d)≤w(b,d) and 𝑤(𝑏,𝑐) <𝑤(𝑎,𝑐)w(b,c)<w(a,c), so 𝑤(𝑎,𝑑) −𝑤(𝑏,𝑑) ≤0 <𝑤(𝑎,𝑐) −𝑤(𝑏,𝑐)w(a,d)−w(b,d)≤0<w(a,c)−w(b,c), contradicting the quadrangle inequality.

    Equivalently, the quadrangle inequality says that the mixed second difference Δ𝑖Δ𝑗𝑤(𝑗,𝑖)ΔiΔjw(j,i) is non-positive on its natural domain.

    With decision monotonicity, many algorithms reduce the complexity to 𝑂(𝑛log⁡𝑛)O(nlog⁡n). Which one to use depends on how 𝑤(𝑗,𝑖)w(j,i) can be accessed. Unless stated otherwise, this article assumes random access: 𝑤(𝑗,𝑖)w(j,i) can be queried or computed in 𝑂(1)O(1). We also discuss two weaker access patterns:

    • Moving access: 𝑤(𝑗,𝑖)w(j,i) can be updated from 𝑤(𝑗 ±1,𝑖)w(j±1,i) or 𝑤(𝑗,𝑖 ±1)w(j,i±1) in 𝑂(1)O(1) time, similarly to Mo's algorithm.
    • Dynamic computation: computing 𝑤(𝑗,𝑖)w(j,i) depends on {𝑓(𝑗′) :𝑗′ <𝑗}{f(j′):j′<j}, so 𝑓f and 𝑤w must be computed in order.

    These two properties are not mutually exclusive.

    Divide and Conquer {#divide-and-conquer}

    To compute all states, it suffices to compute all optimal decisions. First compute opt⁡(𝑛/2)opt⁡(n/2). Then recursively compute decisions on the left and right halves: by monotonicity, the left half only needs decisions in [1,opt⁡(𝑛/2)][1,opt⁡(n/2)], and the right half only needs decisions in [opt⁡(𝑛/2),𝑛][opt⁡(n/2),n]. Recording these search bounds gives 𝑂(𝑛log⁡𝑛)O(nlog⁡n) total work: the recursion has 𝑂(log⁡𝑛)O(log⁡n) levels, and on each level each decision is tested only 𝑂(1)O(1) times.

    val_t w(int j, int i);  // 成本函数
val_t f[N];             // 最优值
int opt[N];             // 最小最优决策

// 递归求解 [l,r] 中的问题
// 已知它们的最小最优决策点一定出现在区间 [opt_l, opt_r] 中
void calc(int l, int r, int opt_l, int opt_r) {
  int mid = (l + r) / 2;
  // 求问题 mid 的最优决策点
  for (int j = opt_l; j <= std::min(opt_r, mid); ++j) {
    if (w(j, mid) < f[mid]) {
      f[mid] = w(j, mid);
      opt[mid] = j;
    }
  }
  // 根据决策单调性得出左右两部分的决策区间，递归处理
  if (l < mid) calc(l, mid - 1, opt_l, opt[mid]);
  if (r > mid) calc(mid + 1, r, opt[mid], opt_r);
}

// 求解整个区间 [1,n] 的问题
void solve(int n) {
  // 每次调用递归函数前，都需要清空数组 f
  std::fill(f + 1, f + n + 1, inf);
  // 最开始时，只知道问题 [1,n] 的所有决策点都一定在 [1,n] 中
  calc(1, n, 1, n);
}

    Besides the random-access case, this divide-and-conquer algorithm also works with moving access. Maintain a cursor (𝑗,𝑖)(j,i) and the current value 𝑤(𝑗,𝑖)w(j,i), and move the cursor by brute force whenever a new value is requested. The complexity is still 𝑂(𝑛log⁡𝑛)O(nlog⁡n). This is discussed further in Simplified LARSCH Algorithm. However, divide and conquer cannot handle dynamic computation, because it needs the midpoint decision before the left half has been solved.

    Binary-Search Queue

    For each decision 𝑗j, the problems for which it is the smallest optimal decision form an interval. We can maintain, in a monotone queue, the interval of problems currently solved by each decision.

    When processing a new decision 𝑘k, the queue stores triples consisting of a candidate decision 𝑗j and the endpoints 𝑙𝑗,𝑟𝑗lj,rj of the interval it currently solves. For any problem in [𝑙𝑗,𝑟𝑗][lj,rj], 𝑗j is the smallest optimal decision among the decisions processed so far. The decisions in the queue need not be consecutive, but the still-unsolved problem range should be the disjoint union of the stored intervals.

    Corollary 1

    Let opt𝑘⁡(𝑖)optk⁡(i) be the smallest optimal decision for problem 𝑖i when only decisions in [1,𝑘][1,k] are allowed. If 𝑤w satisfies the quadrangle inequality, then for any 𝑖1 <𝑖2i1<i2, opt𝑘⁡(𝑖1) ≤opt𝑘⁡(𝑖2)optk⁡(i1)≤optk⁡(i2).

    Proof

    Let 𝑀M be sufficiently large and define 𝑤′(𝑗,𝑖) =𝑤(𝑗,𝑖) +𝑀[𝑗 >𝑘]w′(j,i)=w(j,i)+M[j>k], where [ ⋅][⋅] is the Iverson bracket. The new cost still satisfies the quadrangle inequality, and no decision 𝑗 >𝑘j>k can be the smallest optimum. Applying Theorem 1 to this auxiliary DP proves the claim.

    The algorithm is as follows: 1

    • Initially the queue is empty. As in a monotone queue, each new decision performs pop and push operations.
    • Pop: remove the previous problem 𝑗 −1j−1. If the front decision's right endpoint is exactly 𝑗 −1j−1, pop it; otherwise update its left endpoint to 𝑗j.
    • Push: compare the new decision 𝑗j with the decision 𝑗′j′ at the back.
    • If 𝑤(𝑗,𝑙𝑗′) <𝑤(𝑗′,𝑙𝑗′)w(j,lj′)<w(j′,lj′), pop 𝑗′j′ and continue.
    • If the queue becomes empty, push (𝑗,𝑗,𝑛)(j,j,n).
    • If 𝑗′j′ is no worse than 𝑗j on 𝑟𝑗′rj′, then push (𝑗,𝑟𝑗′ +1,𝑛)(j,rj′+1,n) when 𝑟𝑗′ <𝑛rj′<n; otherwise 𝑗j is never useful.
    • Otherwise, binary-search the smallest 𝑖 ∈[𝑙𝑗′,𝑟𝑗′]i∈[lj′,rj′] such that 𝑤(𝑗,𝑖) <𝑤(𝑗′,𝑖)w(j,i)<w(j′,i), change 𝑗′j′'s right endpoint to 𝑖 −1i−1, and push (𝑗,𝑖,𝑛)(j,i,n).
    • After processing decision 𝑗j, the front decision is the smallest optimal decision for problem 𝑗j.

int lt[N], rt[N];       // 决策 j 可以解决的问题区间 [l_j,r_j]

// 求解整个区间 [1,n] 的问题
void solve(int n) {
  std::deque<int> dq;  // 存储所有可行决策的单调队列

  // 顺次考虑所有问题和决策，下标从 1 开始
  for (int j = 1; j <= n; ++j) {
    // 出队
    if (!dq.empty() && rt[dq.front()] < j) dq.pop_front();
    if (!dq.empty()) lt[dq.front()] = j;
    // 入队
    while (!dq.empty() && w(j, lt[dq.back()]) < w(dq.back(), lt[dq.back()])) {
      dq.pop_back();
    }
    if (dq.empty()) {
      lt[j] = j;
      rt[j] = n;
      dq.emplace_back(j);
    } else if (w(j, rt[dq.back()]) >= w(dq.back(), rt[dq.back()])) {
      if (rt[dq.back()] < n) {
        lt[j] = rt[dq.back()] + 1;
        rt[j] = n;
        dq.emplace_back(j);
      }
    } else {
      int ll = lt[dq.back()], rr = rt[dq.back()], i = rr;
      // 二分
      while (ll <= rr) {
        int mm = (ll + rr) / 2;
        if (w(j, mm) < w(dq.back(), mm)) {
          i = mm;
          rr = mm - 1;
        } else {
          ll = mm + 1;
        }
      }
      rt[dq.back()] = i - 1;
      lt[j] = i;
      rt[j] = n;
      dq.emplace_back(j);
    }
    // 计算
    f[j] = w(dq.front(), j);
    opt[j] = dq.front();
  }
}

    Each decision is pushed and popped at most once. Popping is 𝑂(1)O(1), and pushing may require a binary search, so the total complexity is 𝑂(𝑛log⁡𝑛)O(nlog⁡n).

    Because this algorithm processes problems and decisions in order, it supports dynamic computation. Its binary search requires random access to 𝑤(𝑗,𝑖)w(j,i), so it does not support moving-access-only costs.
