    Knapsack DP

    Introduction

    Before describing what "knapsack DP" is, consider the following example:

    USACO07 DEC Charm Bracelet

    Problem summary: There are 𝑛n items and a knapsack with capacity 𝑊W. Each item has two attributes, weight 𝑤𝑖wi and value 𝑣𝑖vi. Choose some items to put into the knapsack so that the total value is maximized while the total weight does not exceed the knapsack capacity.

    In this example, each item has only two possible states, chosen or not chosen, corresponding to 11 and 00 in binary. Problems of this type are called 0-1 knapsack problems.

    0-1 Knapsack

    Explanation

    The known data in the example are the weight 𝑤𝑖wi and value 𝑣𝑖vi of item 𝑖i, and the total knapsack capacity 𝑊W.

    Let the DP state 𝑓𝑖,𝑗fi,j denote the maximum total value achievable with a knapsack of capacity 𝑗j when only the first 𝑖i items may be used.

    Consider the transition. Suppose all states for the first 𝑖 −1i−1 items have already been computed. For item 𝑖i, if it is not put into the knapsack, the remaining capacity and the total value both stay unchanged, so the best value in this case is 𝑓𝑖−1,𝑗fi−1,j. If it is put into the knapsack, the remaining capacity decreases by 𝑤𝑖wi and the total value increases by 𝑣𝑖vi, so the best value in this case is 𝑓𝑖−1,𝑗−𝑤𝑖 +𝑣𝑖fi−1,j−wi+vi.

    Thus the state transition equation is:

    𝑓𝑖,𝑗=max(𝑓𝑖−1,𝑗,𝑓𝑖−1,𝑗−𝑤𝑖+𝑣𝑖)fi,j=max(fi−1,j,fi−1,j−wi+vi)

    If we directly use a two-dimensional array to store the states, we may get MLE. We can instead optimize with a rolling array.

    Since only 𝑓𝑖−1fi−1 affects 𝑓𝑖fi, the first dimension can be removed. Use 𝑓𝑖fi to denote the maximum value for capacity 𝑖i after processing the current item. This gives the following equation:

    𝑓𝑗=max(𝑓𝑗,𝑓𝑗−𝑤𝑖+𝑣𝑖)fj=max(fj,fj−wi+vi)

    Be sure to remember and understand this transition equation, because most knapsack transitions are derived from it.

    Implementation

    One more point deserves attention: it is very easy to write the following incorrect core code:

# f[i - 1][l] + w[i]), f[i][l + w[i]])

    What is wrong with this code? The enumeration order is wrong.

    Looking carefully at the code, for the current item 𝑖i and current state 𝑓𝑖,𝑗fi,j, when 𝑗 ⩾𝑤𝑖j⩾wi, 𝑓𝑖,𝑗fi,j is affected by 𝑓𝑖,𝑗−𝑤𝑖fi,j−wi. This is equivalent to allowing item 𝑖i to be put into the knapsack multiple times, which contradicts the statement. In fact, this is exactly the solution for complete knapsack.

    To avoid this, enumerate in the opposite direction, from 𝑊W down to 𝑤𝑖wi. Then the error above cannot occur, because 𝑓𝑖,𝑗fi,j is always updated before 𝑓𝑖,𝑗−𝑤𝑖fi,j−wi.

    Therefore the actual core code is:

    for (int i = 1; i <= n; i++)
  for (int l = W; l >= w[i]; l--) f[l] = max(f[l], f[l - w[i]] + v[i]);

    1

3
    for i in range(1, n + 1):
    for l in range(W, w[i] - 1, -1):
        f[l] = max(f[l], f[l - w[i]] + v[i])

    Complete Knapsack

    Explanation

    The complete knapsack model is similar to 0-1 knapsack. The only difference is that each item can be chosen infinitely many times instead of at most once.

    We can borrow the idea from 0-1 knapsack to define the state: let 𝑓𝑖,𝑗fi,j be the maximum value achievable with a knapsack of capacity 𝑗j when only the first 𝑖i item types may be used.

    Note that although this definition is similar to 0-1 knapsack, its transition equation is different.

    Process

    Consider a naive approach: for item 𝑖i, enumerate how many copies are chosen and transition accordingly. This has time complexity 𝑂(𝑛3)O(n3).

    The state transition equation is:

    𝑓𝑖,𝑗=+∞max𝑘=0(𝑓𝑖−1,𝑗−𝑘×𝑤𝑖+𝑣𝑖×𝑘)fi,j=maxk=0+∞(fi−1,j−k×wi+vi×k)

    Now consider a simple optimization. For 𝑓𝑖,𝑗fi,j, it is enough to transition from 𝑓𝑖,𝑗−𝑤𝑖fi,j−wi. Therefore the transition becomes:

    𝑓𝑖,𝑗=max(𝑓𝑖−1,𝑗,𝑓𝑖,𝑗−𝑤𝑖+𝑣𝑖)fi,j=max(fi−1,j,fi,j−wi+vi)

    The reason is that when we transition this way, 𝑓𝑖,𝑗−𝑤𝑖fi,j−wi has already been updated from 𝑓𝑖,𝑗−2×𝑤𝑖fi,j−2×wi, so 𝑓𝑖,𝑗−𝑤𝑖fi,j−wi already fully accounts for the optimal result after considering how many copies of item 𝑖i are chosen. In other words, we reuse the previous enumeration process through the locally optimal substructure, reducing the enumeration cost.

    As with 0-1 knapsack, we can remove the first dimension to optimize space complexity. If you understand the optimization for 0-1 knapsack, it is not hard to see that the compressed loop here goes forward, which is the "wrong optimization" mentioned above.

    Luogu P1616: Crazy Herb Gathering

    Multiple Knapsack

    Multiple knapsack is another variant of 0-1 knapsack. The difference is that each item type has 𝑘𝑖ki copies instead of one.

    A very naive idea is to transform "choose each item type up to 𝑘𝑖ki times" into "there are 𝑘𝑖ki identical items, and each can be chosen once". This reduces the problem to 0-1 knapsack, so the method above applies. The state transition equation is:

    𝑓𝑖,𝑗=𝑘𝑖max𝑘=0(𝑓𝑖−1,𝑗−𝑘×𝑤𝑖+𝑣𝑖×𝑘)fi,j=maxk=0ki(fi−1,j−k×wi+vi×k)

    The time complexity is 𝑂(𝑊∑𝑛𝑖=1𝑘𝑖)O(W∑i=1nki).

    Binary Grouping Optimization

    Consider optimization. We still transform multiple knapsack into a 0-1 knapsack model.

    Explanation

    Clearly, the 𝑂(𝑛𝑊)O(nW) part of the complexity cannot be further optimized, so we can only work on the 𝑂(∑𝑘𝑖)O(∑ki) part. For convenience, use 𝐴𝑖,𝑗Ai,j to denote the 𝑗j-th item split from item type 𝑖i.

    In the naive approach, for all 𝑗 ≤𝑘𝑖j≤ki, 𝐴𝑖,𝑗Ai,j denotes the same item. The main reason for the low efficiency is the large amount of repeated work. For example, we consider both "choose 𝐴𝑖,1Ai,1 and 𝐴𝑖,2Ai,2" and "choose 𝐴𝑖,2Ai,2 and 𝐴𝑖,3Ai,3", two completely equivalent cases. We perform this kind of redundant work many times, so optimizing the splitting method is the key.

    Process

    We can make the splitting more elegant using binary grouping.

    Specifically, let 𝐴𝑖,𝑗(𝑗∈[0,⌊log2⁡(𝑘𝑖+1)⌋−1])Ai,j(j∈[0,⌊log2⁡(ki+1)⌋−1]) denote bundled items made from 2𝑗2j individual items. If 𝑘𝑖 +1ki+1 is not a power of 22, add one final bundled item made from 𝑘𝑖 −2⌊log2⁡(𝑘𝑖+1)⌋−1ki−2⌊log2⁡(ki+1)⌋−1 individual items to make up the remainder.

    Examples:

    • 6 =1 +2 +36=1+2+3
    • 8 =1 +2 +4 +18=1+2+4+1
    • 18 =1 +2 +4 +8 +318=1+2+4+8+3
    • 31 =1 +2 +4 +8 +1631=1+2+4+8+16

    Luogu P1064: Jinming's Budget Plan

    Jinming has 𝑛n yuan and wants to buy 𝑚m items. Item 𝑖i costs 𝑣𝑖vi and has importance 𝑝𝑖pi. Some items are accessories attached to a main item; to buy such an item, its main item must also be bought.

    The goal is to maximize the sum of 𝑣𝑖 ×𝑝𝑖vi×pi over all purchased items.

    Consider the cases. For a main item and its accessories, the possible choices are: buy only the main item, or buy the main item plus some accessories. Since exactly one of these possibilities can be chosen, this can be treated as group knapsack.

    If the dependency structure is a forest of multiway trees, compute each child subtree first, then compute the parent subtree.

    Knapsack with Generalized Items

    In this kind of knapsack, an item has no fixed cost or value. Its value depends on the cost allocated to it. In a knapsack problem with capacity 𝑉V, when cost 𝑣𝑖vi is allocated to the item, the value obtained is ℎ(𝑣𝑖)h(vi). In this case, replace the fixed value with a reference to a function.

    The 𝑘k-th Best Knapsack Solution

    Ordinary 0-1 knapsack asks for the optimal solution. By slightly modifying ordinary knapsack DP and adding one dimension to record the top 𝑘k solutions for the current state, we obtain an algorithm for finding the 𝑘k-th best solution of 0-1 knapsack.

    Specifically, dpi,j,kdpi,j,k records the 𝑘k-th largest value sum obtainable among the first 𝑖i items when the total volume of chosen items is 𝑗j. This state can be understood as extending the ordinary 0-1 knapsack state dpi,jdpi,j, which stores only one value, into a sorted sequence of optimal values. During the transition, ordinary knapsack computes dpi,j =max(dpi−1,j,dpi−1,j−vi +𝑤𝑖)dpi,j=max(dpi−1,j,dpi−1,j−vi+wi). Here, instead, we merge the two decreasing sequences of size 𝑘k, dpi−1,jdpi−1,j and dpi−1,j−vi +𝑤𝑖dpi−1,j−vi+wi, and keep the largest 𝑘k values in dpi,jdpi,j. This step uses two pointers and costs 𝑂(𝑘)O(k), so the total time complexity is 𝑂(𝑛𝑚𝑘)O(nmk). As in ordinary knapsack, the first dimension can be compressed, giving space complexity 𝑂(𝑚𝑘)O(mk).
